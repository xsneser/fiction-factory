## 0. 一句话现状

项目已收敛为**单写作核心 = 桥段写作（timeline_writer.py）**：所有写作（含新书启动）走同一条桥段管线；集中式 `prompt_harness.py` 统一 prompt；笑点完全涌现（`gag_injector.py` 探测器）、内涵跟随桥段、跨章语义摘要。**书名/简介生成是书库详情页的独立功能**（"🎬 生成书名/简介"按钮），不再自动触发。节拍写作（beat_writer）与新书老流程（new_book）已整体删除。

详细架构演变见 `docs/harness重构交接文档.md`（Part 1 = harness 原则，Part 2 = 写作核心统一）。

## 1. 运行与测试

### 启动 / 重启服务（端口 58080）

```powershell
# 正常启动
python ui/web_ui.py

# 重启：停掉旧进程后起新进程
taskkill /F /PID <58080的pid>
python ui/web_ui.py
```

查当前 pid：`netstat -ano | findstr :58080`。**改了 libraries/ 或 ui/web_ui.py 必须重启才生效**（模块在启动时导入）。

### 测试

```powershell
python test_all.py          # 50/50 无 LLM 测试（含 Phase3 写作核心统一健全性）
python tools/test_full_flow.py --genre 都市 --sub 系统流   # 真实 LLM E2E（约30分钟，自建自删测试书）
```

> Windows 控制台默认 GBK，脚本打印中文要加 `sys.stdout.reconfigure(encoding="utf-8")`。E2E 的 stdout 重定向到文件是块缓冲，看进度用 `books/{book_id}/chapters` 轮询。

## 6. 坑与注意事项

- **四大库是进程内单例**：改了 `libraries/data/*.json` 必须**重启服务**才生效。
- **api.json 是明文 Key**：gitignored，别 `git add -f`。
- **flash 模型 max_tokens 必须留推理余量**：任何新的 LLM 调用，max_tokens 都要明显大于"纯正文+推理"之和，否则静默空响应。写作 1600、摘要/书名 1024、探测器 400。
- **时间线流程进度**：`book.json.current_chapter` 由 `_finalize_written_chapter` 写回（已修）。手动改测试数据要同步 book.json 和 timeline.json 的 written_chapter。
- **测试会动数据**：`test_full_flow.py` 自建自删测试书；`books/`、`profiles/` 是用户真实数据，别删。
- **删除类操作**：`delete_book`/`timeline_delete` 无回收站，帮用户删除前先确认。
- Windows 控制台 GBK：脚本打印中文加 `sys.stdout.reconfigure(encoding="utf-8")`。
