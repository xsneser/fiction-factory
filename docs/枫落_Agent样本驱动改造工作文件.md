# 枫落｜Agent 样本驱动改造工作文件

## 任务目标

将现有写作风格系统，从“规则驱动”改造成：

> **人工样本负责主要风格学习，少量负约束只负责防止明显生成腔。**

不要继续增加文风规则。

不要继续增加固定句长、段落比例、对话比例、比喻数量、标点频率、禁词替换等规则。

---

## 1. 已确认的实验结论

目前已有明确对照：

- 第一段小说：人工创作。
- 第二段小说：AI 生成。
- 第三段小说：AI 生成。
- 第三段 AI 输出在**没有提供人工样本、仅使用风格 MD 文件**的情况下生成。

第三段虽然流畅、悬疑感强、句子漂亮，但出现：

1. 文学化程度过于均匀。
2. 金句密度偏高。
3. 线索出现后容易立即解释。
4. “观察 → 判断 → 总结”结构重复。
5. 人物容易成为作者观点的代言人。
6. 细节容易被主动赋予主题意义。
7. 动作、心理、意义闭环过快。
8. 模型会主动执行“悬疑写法”，而不是自然叙事。

因此，本次改造的核心不是继续告诉模型“如何像人”，而是：

> **减少模型需要执行的风格规则，让模型从真实人工样本中学习语言和叙事惯性。**

---

# 2. 当前系统的问题

旧风格配置包含大量“可执行公式”，例如：

- 固定单句成段比例
- 固定对话比例
- 固定省略号数量
- 固定比喻频率
- 固定句长范围
- 固定短句 / 中句 / 长句混排
- 大量禁词与替换词
- 固定章节结尾形式
- 逗号和主语省略的强制规则
- 大量示范句

这些规则虽然意图是防止 AI 味，但模型会把它们理解成：

> “这一段应该使用哪些写作技巧。”

结果容易形成另一种高度稳定的 AI 文风。

---

# 3. 新架构

最终建议分成三层。

## Layer 1：STYLE REFERENCE

最高优先级。

内容为用户提供的真实人工小说样本。

模型主要从样本学习：

- 语言惯性
- 叙述距离
- 信息投放方式
- 人物观察和反应
- 对白习惯
- 句式变化
- 普通句与突出句的分布
- 何时解释、何时不解释
- 不同场景下节奏如何自然变化

不要要求模型总结样本。

不要要求模型抽取技巧。

不要让模型把样本变成固定模板。

核心提示：

> 以下文本是同一作者的既有作品。直接参考其实际语言和叙事方式继续创作，不要总结、分析或抽象成写作公式。

---

## Layer 2：NEGATIVE CONSTRAINTS

只保留少量负约束。

建议初始使用以下 10 条：

1. 不要让全文每句话都很漂亮。
2. 不要让每个段落都主动制造悬念、反转或金句。
3. 不要每发现一个信息就立即解释它的意义。
4. 不要每个动作后面都跟一段心理总结。
5. 不要让每个细节都精准服务主线。
6. 不要让人物句句都聪明、完整、逻辑严密。
7. 不要连续使用同一种“观察 → 判断 → 总结”结构。
8. 不要为了显得像真人而主动制造口吃、废话、漏洞或停顿。
9. 不要为了追求文笔而主动添加比喻、排比、哲理句。
10. 不要为了规避所谓 AI 高频词而机械替换正常中文。

这些只用于“防止过度生成”。

不要将它们变成正向模板。

---

## Layer 3：TASK / STORY

原有的剧情、人物、世界观、章节任务继续存在。

建议优先级：

1. 当前剧情和人物一致性
2. STYLE REFERENCE
3. 中文自然度
4. NEGATIVE CONSTRAINTS
5. 其他格式约束

---

# 4. 旧机制的迁移要求

不要一次性删除整个旧 Style System。

采用兼容迁移。

旧配置仍然能够读取，但新模式默认不执行旧规则。

建议增加：

```json
{
  "style_mode": "sample_driven",
  "style_reference_enabled": true,
  "negative_constraints_enabled": true,
  "legacy_rules_enabled": false,
  "style_reference_max_chars": 24000,
  "negative_reference_enabled": false
}
```

字段名可按项目现有架构调整。

---

## 4.1 固定比例全部降级

取消生成阶段的：

- 单句成段比例
- 对话占比
- 长句 / 短句比例
- 每章省略号数量
- 每段比喻次数

这些交给样本自然决定。

---

## 4.2 固定字数全部降级

取消：

- 5-12 字短句
- 20-30 字句
- 35-55 字长句
- 固定段落长度

不要让模型为了满足字数主动修改自然句子。

---

## 4.3 词级硬替换关闭

不要再执行：

```text
A词出现 → 强制替换成B词
```

例如：

```text
然而 → 可 / 但
因此 → 所以 / 于是
顿时 → 猛地
微微一笑 → 笑了笑
```

这些如果保留，只能作为低优先级警告，不得逐词强制改写。

---

## 4.4 固定章末规则关闭

关闭：

- 章末必须停在动作
- 章末必须留悬念
- 章末不能用警句
- 每章必须使用省略号
- 每章必须设问
- 每章必须反转

章末由剧情和样本自然决定。

---

## 4.5 固定修辞规则关闭

取消：

- 每段最多一个比喻
- 比喻必须具体
- 固定排比频率
- 固定设问频率

样本自己提供修辞分布。

---

## 4.6 过度句法修复关闭

不要把：

- 逗号规则
- 主语省略规则
- 句长规则

做成逐句强制重写。

如果项目有 style repair 阶段，建议降级为最终质量检查，而不是生成前约束。

---

# 5. 样本注入方式

不要把人工样本拆成：

- 比喻样本
- 对话样本
- 动作样本
- 悬疑样本
- 金句样本

这种做法会把风格拆成技巧。

优先使用：

> **完整、连续的人工场景。**

推荐单个样本约 1500～3000 字（低于约 800 字多半只是金句/片段，不适合单独喂），
尽可能保留上下文。样文池合计 6000～10000 字即可覆盖较完整的语言分布——
不是每份越长越好，过长会稀释真正有价值的分布。

最好有不同场景：

- 对话密集
- 推理
- 恐怖 / 死亡
- 平静过渡
- 人物独处
- 群像

目标不是让模型背句式，而是让它看到：

> **同一作者在不同情况下如何自然改变写法。**

---

# 6. STYLE REFERENCE 推荐格式

```text
# STYLE REFERENCE

以下文本是本作品实际的人工作品样本。

不要总结样本。
不要解释样本为什么这样写。
不要抽取固定技巧。
不要建立固定句式模板。
不要复制具体句子、人物和事件。

直接参考其自然呈现出的：
语言习惯、叙事距离、信息组织、人物表达和节奏变化。

在剧情独立的前提下，继续采用相近的写作惯性。

<sample>
[人工样本]
</sample>
```

---

# 7. NEGATIVE REFERENCE 可选

可以把“语言流畅、质量不差、但明显有生成感”的 AI 输出作为负向样本。

例如当前实验中的 AI 输出。

格式：

```text
# NEGATIVE REFERENCE

以下文本并非因为语言质量差而作为负向样本。

它的问题是：
过度工整、过度解释、过度文学化、金句密度过高、
因果闭环过快，容易产生明显的模型生成感。

不要复制这些生成倾向。

<negative_sample>
[AI 样本]
</negative_sample>
```

默认建议：

```json
"negative_reference_enabled": false
```

先验证正向样本驱动是否有效，再决定是否启用负向样本。

---

# 8. Prompt 结构建议

生成 Prompt 尽量简单。

```text
[SYSTEM]

你正在根据既有作品样本继续创作。

STYLE REFERENCE:
[人工样本]

NEGATIVE CONSTRAINTS:
[少量负约束]

STORY CONTEXT:
[世界观 / 人物 / 前文]

CURRENT TASK:
[本章 / 本段需要完成的剧情]

请直接写正文。
不要解释写作方法。
不要分析样本。
不要输出风格说明。
```

不要在这里重新注入旧版几百行风格规则。

---

# 9. 一个重要原则：允许样本中的普通表达保留

不要把人工样本里的：

- 重复
- 普通句
- 解释性旁白
- 不够漂亮的表达
- 常见副词
- 一些冗余

自动视为缺陷。

这些东西可能就是作者稳定的语言惯性。

**不要主动把样本“优化”成更高级的版本。**

---

# 10. 代码实现建议

建议新增一个独立的 sample-driven style provider，例如：

```text
StyleProvider
├── LegacyRuleProvider
└── SampleDrivenStyleProvider
```

SampleDrivenStyleProvider 负责：

1. 获取当前 style profile。
2. 获取用户配置的 STYLE REFERENCE。
3. 根据上下文选择合适样本。
4. 注入少量 NEGATIVE CONSTRAINTS。
5. 生成最终 style prompt。
6. 不调用旧 hard-rule rewrite。

如果当前架构已经有 StyleProfile、PromptBuilder、RuleEngine 等组件，优先复用，不要为了这次改造重新设计整个系统。

---

# 11. 样本选择建议

如果样本数量较多，不要每次把全部样本全部塞入模型。

优先考虑：

```text
当前章节场景
    ↓
选择最接近的 1～3 个人工样本
    ↓
组成 STYLE REFERENCE
```

例如：

- 正在写推理 → 优先推理样本
- 正在写群像对白 → 优先对白密集样本
- 正在写恐怖场景 → 优先死亡 / 恐怖样本
- 正在写平静过渡 → 优先日常 / 过渡样本

但不要使用简单关键词硬匹配作为唯一依据。

如果已有 embedding / retrieval 能力，可以复用。

---

# 12. 验收方式

修改后，用**同一个剧情任务**进行 A/B/C 测试。

### A
旧 Style System

### B
Sample-driven，但不提供人工样本

### C
Sample-driven + 人工样本

主要目标：

> C 明显比 A、B 更接近人工原文。

重点观察：

### 1. 文学密度

是否仍然每几段就主动产生一个金句？

### 2. 因果闭环

是否每个线索刚出现就立即解释？

### 3. 人物对白

角色是否句句逻辑完整、聪明、精准？

### 4. 修辞

是否为了“好看”而主动加入比喻和升华？

### 5. 普通句

文本中是否允许自然出现普通、功能性的句子？

### 6. 叙事结构

是否不断重复：

```text
观察 → 判断 → 总结
```

### 7. 风格模仿

是否真正接近人工样本，而不是自行生成一个“它理解中的悬疑小说风格”？

---

# 13. 特别注意

不要把以下指标作为目标：

- AI 检测器分数低
- 每句话都像真人
- 每段都很有画面
- 每段都有金句
- 文风高度统一
- 每章都有钩子

这些指标容易再次把系统推回公式化生成。

真正目标是：

> **让模型少执行写作技巧，多参考真实作者已经写出来的文本。**

---

# 14. 最终设计理念

旧系统：

> 告诉模型这个作者应该怎么写。

新系统：

> 给模型看这个作者真实写过的东西，只提醒它不要过度发挥。

最终权重关系应接近：

```text
STYLE REFERENCE  >>>  NEGATIVE CONSTRAINTS
```

样本负责：

> **怎么写**

负约束负责：

> **哪些地方不要过度**

代码负责：

> **管理样本、选择样本、组织 Prompt**

而不是继续替模型规定：

> 这一句应该多少字、这一段应该几个短句、这一章应该几个省略号。
