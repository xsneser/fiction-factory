## 一、架构信息（速览 §1.1–1.5 + agent·dsh 运行机制深挖 §1.6–1.10）

### 1.1 一句话

NovelEngine = 可视化、**外部 agent 可驱动**的多阶段小说创作平台。创作大脑在平台之外（Claude Code / 侧栏 dsh headless），经 **MCP stdio** 调一套**薄工具面**（`agent_tools.py TOOL_REGISTRY`，44 个，以 `tools/mcp_smoke.py` EXPECT_MCP_TOOLS 为准）驱动平台；平台只存数据、跑免费规则（去 AI 味 / 审查 / 门禁 / 台账 / 角色状态机），**LLM 生成类工作全在 agent 侧**——工具内不再内嵌 LLM。

### 1.2 分层与进程

```
┌─ 驱动方(大脑，平台外)───────────────────────────────┐
│  Claude Code  ·  侧栏 dsh headless(vendor/dsh-ne)     │
└──────────────┬──────────────────────────────────────┘
               │ MCP stdio：mcp__novel-engine__*（44 个）
        ┌──────▼────────┐          ┌───────────────────────┐
        │ mcp_server.py │          │ Web 服务 Flask 58080    │
        │ FastMCP stdio │          │ ui/web_blueprints/ 蓝图 │
        └──────┬────────┘          └───────────┬───────────┘
               │   agent_tools.py TOOL_REGISTRY（唯一工具源）│
               │   护栏：PHASE_GATES / BookLock / LoopGuard  │
               ▼                                     ▼
   ┌─────────────────────────────────────────────────────────┐
   │ libraries/ 引擎 + 四库模板 + 规则层     books/ 真实书数据  │
   │ libraries/data/{structures,plots,gags,characters}.jsonl │
   └─────────────────────────────────────────────────────────┘
```

- **双进程并存**：Web 与 MCP 子进程各自独立 import，靠 `books/` JSON + `storage/` 运行时缓存协调；写工具带书级锁（`BookLock`），冲突抛 `BookBusyError`。
- **书数据落盘**：`books/<id>/storyline.json`（故事线全量，见 §2.1）、`chapters/<n>.json`（正文）、`draft_chapter.json`（草稿）、`character_states.json`（角色动态状态，见 §3.4）。

### 1.3 双通道驱动

| 通道 | 机制 | 用途 |
|---|---|---|
| dsh 事件流（SSE） | `vendor/dsh-ne/events-runner.mjs` 把每次 tool_call/result 推 SSE | 侧栏实时工具卡、导航零延迟（默认主通道） |
| MCP 意图队列（轮询兜底） | `navigate`/`drive_ui` 写 `storage/nav_intent.json`（TTL），浏览器 ~2.5s 轮询 | Claude Code 等无 SSE 的外部客户端 |

### 1.4 阶段与 skill（分发表）

| 阶段 | skill | phase 前置 | 出口 | 主要薄工具 |
|---|---|---|---|---|
| 建书 | `novel-build-candidates` → `novel-build` | 无书 / config | 向导提交即 `ready` | drive_ui(set_candidates/set_outline/set_world/set_characters) / validate_storyline(内联) / query_arc_library / query_plots / validate_world |

### 1.5 护栏（不可绕）

- **直建/直删不在工具面**：建书必须 `navigate("/books/start")` + `drive_ui` 驱动向导由系统建；删书走书库页手动。
- **ready 只由用户动作翻转**：正常=向导步3 提交即 `ready`（深化式生成已并入步3）；config 补弧兜底 = 用户在书详情「✅ 确认弧+情节段」。agent 无翻 ready 工具。
- `PHASE_GATES` phase 门控 / `LoopGuard` 循环熔断（同参只读 >3 次即停）/ `BookBusyError` 写锁 / `budget_paused` 额度停顿（停下问用户）。

### 1.6 dsh 驱动方：提示词拼装与规则来源（三层，平台不拼 prompt 文本）

dsh（DeepSeek Harness，Node agent 框架，vendored 于 `vendor/dsh-ne/`）是 one-shot headless：给一个任务文本，内部反复调 MCP 工具直到完成。**给模型的「提示词」分三层**，规则与身份几乎不进任务文本、由系统注入，任务文本只放「历史回放 + 本次任务」：

| 层 | 注入方式 | 来源/位置 | 内容 |
|---|---|---|---|
| persona（系统提示） | system-prompt 插件**整体替换**（dsh patch 非深合并，必须给全） | `libraries/dsh_bridge.py:_PERSONA`(193-202)；写进运行期 overlay 的 `system-prompt` 段；基线模板 `agent-sidecar/cordis.patch.yml` 同步 | 一句话 coding agent：`You drive the NovelEngine … through its MCP tools (mcp__novelengine__*); Follow … NOVEL_AGENT.md … single source of truth.`；`includeRuntimeContext: false`（禁沙箱/审批/运行时快照——对纯 MCP 小说 agent 无意义） |
| workspace 指令（规则唯一源） | agent-instructions 插件注入 system-reminder | `NOVEL_AGENT.md`（`instructionFileCandidates:['NOVEL_AGENT.md']`，maxBytes 20000；`localInstructionFileCandidates: []` → **不注入**工程 `CLAUDE.md`） | 只留**定义(1.1)+工具参数契约(1.2)**；流程拆成 5 个 skill（头部即指示：任务匹配先调 `skill` 工具按名加载再执行）。**不加 skill 分发表**——stock dsh 自动把 skill 目录的 name/description 注入 |
| 任务文本 | dsh_bridge 拼「历史回放 + 当前任务」 | `_build_task_text`(`dsh_bridge.py:344`) | `[用户]/[助手] … [用户] {task}`；规则不再内联前缀；超长截中间旧历史保头尾（≤20k 字符，Windows 命令行 ~32K 留余量） |

**动态内容不经平台静态拼装**：风格靠 `get_pen_style`/`pick_plot_sample`/`style_card`、人物卡/弧目标靠 `get_writing_context`、素材靠 `query_*`——全部在工具返回里结构化给出，引用职责在 agent。模型/计费：deepseek-v4-flash（推理型；流式 max_tokens 需 ≥8192 留推理余量）；`DEEPSEEK_BASE_URL=http://127.0.0.1:58082` 本地 token 代理（`ensure_proxy()` 拉起，bootstrap-only 只能从进程 env 进）；`NOVEL_AGENT_DEBUG=1` 时 events-runner 把每次 LLM 调用的提示词/MCP 工具 schema/响应 emit `llm/call`，完整载荷写 `storage/debug-prompts/<seq>.json`（SSE 只发裁剪预览）。

### 1.7 运行期 overlay（`storage/dsh_runtime.yml`）——dsh 子进程的“长相”

dsh 的 cordis patch 层对 id-targeted entry 是**整体替换 config**（非深合并），所以 overlay 每个 entry 必须给全。`dsh_bridge._write_runtime_overlay`(`dsh_bridge.py:274`) 每次任务前重写：

| entry | 作用 |
|---|---|
| `mcp-novelengine` | MCP stdio 客户端；`command` 钉到 `_python_with_mcp()`（**能 `import mcp` 的解释器**——双运行时坑：PATH/服务进程解释器没装 mcp → mcp_server 起不来 → 满屏 unknown tool）；`args:['mcp_server.py','--source','dsh']`（日志记 source=dsh）；`toolCallTimeoutMs:600000`（薄工具/长生成阻塞数分钟不被 MCP 掐断） |
| `agent-instructions` | 只注入 `NOVEL_AGENT.md`（见 1.6） |
| `system-prompt` | persona 内联 + `includeRuntimeContext:false`（见 1.6） |
| `headless-runner` disabled + insert `events-runner` | `file:///vendor/dsh-ne/events-runner.mjs`，`inject:['headlessStartup']`，`task` 取自 ctx；把 headless-runner 的「summarize + 只打印最终文本」换成逐事件 NDJSON |
| `tool-result-pruner` disabled（逃生口 `NE_KEEP_TOOL_PRUNE=1` 保留 dsh-base 默认 8192 裁剪） | 保证大载荷（get_pen_style 全量 md+样文等）不被裁中段 |

基线模板：`agent-sidecar/cordis.patch.yml`（手动安装 headless profile 用），并**禁用 dsh 系统工具**（`tool-fs`/`tool-fs-search`/`tool-bash` 等 `disabled: true`）——护栏：dsh 只能经 MCP 驱动平台，不能直操文件/shell/子代理，保留联网 + `mcp__novelengine__*`。

### 1.8 一次 dsh 任务的端到端时序 & Web API

```
浏览器侧栏消息 → POST /api/agent/chat（ui/web_blueprints/agent.py:26，SSE）
  → dsh_bridge.run_dsh_task(task, history, debug)（dsh_bridge.py:627）
      ├ interrupt_current_task()            # 全服务单任务：先打断正在跑的旧 dsh
      ├ _write_runtime_overlay()
      ├ cmd = node vendor/dsh-ne/lib/bin.js --profile headless --patch <overlay> <任务文本>
      ├ env: DEEPSEEK_BASE_URL=58082 (+ debug: NOVEL_AGENT_DEBUG / DEBUG_PROMPT_DIR)
      └ 读 stdout 逐行 NDJSON → _map_dsh_event(529) 转 SSE：
          tool_call / tool_result / navigate / ui_command / reply / done / error（+debug llm_call）
            ├ tool_call/tool_result/llm_call 持久化 storage/task_events.jsonl（刷新重建卡片流，跨任务累积）
            └ yield 给前端（工具卡实时渲染）
  done/error 收尾；异常退出(exit≠0 且无 done) → error+done；被打断 → 「任务已被打断」；
  客户端断连(GeneratorExit)不杀子进程——任务后台跑完，由 get_current_task_status 感知/取消
```

- 任务无整时长上限（可远超 15 分钟）；单工具超时由 overlay `toolCallTimeoutMs` 独立兜底；可 `/api/agent/chat/cancel`。
- Web API 面（`ui/web_blueprints/agent.py`）：`/api/agent/chat`(SSE) / `chat/cancel` / `chat/status` / `task-events` / `task-events/clear` / `token-usage` / `build-status` / `tool-log` / `nav-intents` / `debug-prompt/<seq>`。
- 页面↔侧栏同步：`agent_panel.js` 事件 `ne:agent-state`、`window.agentIsBusy / agentStopTask / agentSendTask`；建书向导步 2「已挑选完毕」→ `agentSendTask` 自动派 `novel-build`（`ui/templates/start_book.html:337-347`）；步 1 主按钮「🚀 让 Agent 构建」→ 派 `novel-build-candidates` 停步 2 等候选。
- **双通道**：dsh = 事件流（默认主通道，§1.3）；外部客户端（Claude Code/其它）无 SSE → `navigate`/`drive_ui` 写 `storage/nav_intent.json`（TTL），浏览器 ~2.5s 轮询 `window.onnecommand` 消费。

### 1.9 MCP / tool 面：注册、包装链与护栏

- **工具唯一源 = `agent_tools.TOOL_REGISTRY`**（44 个）。`_build_registry`(`agent_tools.py:2765`)：有序 fns 列表 → 包装链 **phase 门控(`_wrap_phase_gate`，最外层) → 书锁(`_wrap_book_lock`，仅 `_LOCKED_TOOLS`) → 原函数**；`functools.wraps` 保 `__name__/__doc__`；`input_schema` 由签名 `_func_to_schema` 自动生成。**顺序有意**：navigate/drive_ui 排最前（flash 对列表前部更敏感）→ 只读摸底 → 创作链 → 上架/门禁/校验 → 抓取/提取。
- **MCP 适配层 `mcp_server.py`**（FastMCP stdio）：`for _e in TOOL_REGISTRY: mcp.tool()(_wrap_logged(_e["func"]))`。`_wrap_logged`(`mcp_server.py:87`)：`LoopGuard.before/after_call`（同参同结果轮询 / 连续失败即熔断，所有 MCP 客户端受益）+ `log_tool_call`（`run_id=mcp.<ts>`；`source` 由 `--source` 定：**dsh 内部不写 `storage/tool_log.jsonl`**，「工具日志」页签只展示外部 source=mcp 调用）。`_mcp_summary`(53) 对增量候选/字数推进/建书轮询等动态字段造摘要，防 LoopGuard 把正常推进误判死循环。异常 `raise` → MCP isError → dsh 工具卡红叉。
- **护栏三件套 + 建书护栏**：`PHASE_GATES`(tool_policy，phase 不对先拦、不占锁) / `BookLock` 写锁(`BookBusyError`) / `LoopGuard` 循环熔断 + `budget_paused`（额度/预算触发停下问用户）。直建/直删工具不在注册表——建书走向导 UI（`drive_ui` 驱动，浏览器 `POST /books/start` submit），删书走书库页手动；`ready` 翻转无 agent 工具。
- **词条结构校验（系统层堵 agent 漏写）**：`libraries/storyline.py: outline_payload_problems` 挂在两个写入口 `drive_ui(cmd=set_outline)` 与 `save_outlines`——弧缺完整跨度（半组如只有 `end_word` 无 `start_word`）/缺 id/name、情节段 `outline_id` 悬空或挂非叶弧 → 直接 `raise RuntimeError`（不自动换算兜底，agent 收到红叉自改）。前端 `story_line.js:arcWords` 与服务端 `reconcile_outline` 的兜底保留为存量/遗留弧的读路径。

### 1.10 skill 发现与分发（dsh vs Claude）+ 与薄工具的关系

## 二、故事线 / 线程 / 弧 / 情节段 关系

### 2.1 一张总图（模板层 vs 实例层）

核心前提：**「库(模板)」与「书(实例)」是两层；弧与情节段是纵轴（一根轴上粗细两档）；线程是横轴；设局→收局是线索生命周期轴。三根轴正交，不是层级递进。**

```
【模板层 · 可复用素材】                 【实例层 · 一本书落地 books/<id>/storyline.json】
libraries/data/*.jsonl
┌──────────────────────────┐          ┌─────────────────────────────────────┐
│ 情节弧库  ArcNode(平级)    │──选──▶   │ outlines[]  OutlineSlot 弧(树状嵌套)   │
│   无父-子、每行一条独立弧    │template_id│  parent_arc_id 连成弧树               │
│   自带 description/key_…  │ 回指     │  start_word/end_word = 字数权威轴      │
├──────────────────────────┤          │  └─ stages[] 从模板展开的阶段          │
│ 情节段库  PlotTemplate     │──选──▶   │ plots[]   PlotSlot 情节段(挂叶弧)       │
│   骨架 template_structure │template_id│  outline_id→叶弧 · thread_id→线程      │
│   变量槽  (plot.PlotSlot) │ 回指     │  resolves_plot_id=设局/收局呼应        │
├──────────────────────────┤          │  roles / gag_ids / theme_hints …       │
│ 笑点库/角色原型库 等        │          ├─────────────────────────────────────┤
└──────────────────────────┘          │ threads[]  {id,name,desc}              │
                                      │ promises[] 读者承诺台账(伏笔生命周期)    │
                                      │ themes[] / global_gags[] 全书贯穿元素     │
                                      │ basic_info 人物/世界观/基调/视角          │
                                      └─────────────────────────────────────┘
```

### 2.2 三轴正交对照（绳穿竹竿图）

- **纵轴-粗 情节弧 Arc**：树状目标节点，掌控一段走向（约 5–15 章）；实例 `OutlineSlot`，`parent_arc_id` 套子弧；覆盖字轴无空白。
- **纵轴-细 情节段 Plot**：弧内可执行戏剧节拍（约 0.3–2 章）；**正文写作最小单元**；只挂**叶弧**。
- **横轴 线程 Thread**：把散布在不同弧里的情节段串成一条叙事线索（主线/副线/伏笔线）；`threads[]` 定义 + 每情节段 `thread_id` + `thread_seq`。
- **生命周期 设局→收局**：设局情节段（`resolves_plot_id` 空）被后续收局情节段（`resolves_plot_id` 指回其 id）呼应；登记进 `promises[]`（pending→advanced→fulfilled，逾期由 `promise_ledger.py` 出决策点）。

> 「绳穿竹竿」：竹竿段 = 弧，竹节 = 情节段，贯穿的绳 = 线程。一个情节段同时属一个弧（纵向）+ 一个线程（横向）+ 一个设局/收局槽（生命周期）。

| 误区 | 正解 |
|---|---|
| 「大纲=卷」 | 大纲（弧）是有方向的叙事段；卷是更大的后处理分组概念，不在素材/故事线层 |
| 「弧=模板」 | 弧模板 `ArcNode`（平级可复用）≠ 书内弧实例 `OutlineSlot`（树嵌套、有字坐标、`template_id` 回指） |
| 「线程是情节段的一类」 | 线程是横轴维度；情节段是纵轴最细档，二者正交 |
| 「storyline=timeline.json」 | 落盘是 `storyline.json`（timeline 只是旧称/兼容） |
| 「`plot.py` 的 PlotSlot」 | 那是**模板变量槽位**，与书内情节段实例 `storyline.PlotSlot` 同名不同物 |

### 2.3 数据模型速查（`libraries/storyline.py`）

**OutlineSlot —— 一条弧（`storyline.py:236`）**：`id/name`、`template_id`（回指弧模板；空=已展开）、`start_word/end_word`（**0 基字坐标，start 含/end 不含，落盘权威**）、`start_chapter/end_chapter`（章号视图，由字坐标推导）、`parent_arc_id`（弧树嵌套）、`stages[]`（从模板展开的阶段）、`notes`（弧目标 + 偏离库模板点的说明）、`overlaps_with/predecessor/successor/transition_type`（平级关系）、`narrative/narrative_target`（主要影响 UI）。

**PlotSlot —— 一个情节段（`storyline.py:262`）**：`id/template_id/name`、`category/sub_category`、`outline_id`（所属弧 id，写作归属，须为叶弧）、`stage_index/order`（弧内阶段/排序）、`parent_plot_id/children_plot_ids`（情节段嵌套）、`words`（目标字数，按内容浓淡；0 回退 `cover_beats×200`）、`template_structure/slots`、`gag_ids/theme_hints/theme_moments/hook_points`、`written_chapter`（已写第几章，0=未写，断点依据）、`thread_id/thread_seq`、`resolves_plot_id/resolves_name`（收局槽位）、`roles`（出场人物，主角恒在首位）、`confirmed`。

**BookStoryline —— 整本书（`storyline.py:301`）**：`book_title/words_per_chapter/pen_name/platform` + `basic_info`（characters 统一数组 + world_building + tone/target_audience/pov/era_language）+ `outlines[]/plots[]/threads[]/promises[]/themes[]/global_gags[]` + `phase(config|outlines|plots|ready)`。`to_dict()`（`storyline.py:340`）往返带 `reconcile_outline` 同步章/字双坐标。

**库模板层**：弧库 `ArcNode`（`libraries/structure.py:22`，别名 `StructureTemplate`，2026-09 v3 **平级独立**：无父-子；自带 description/min_words/max_words/key_events/foreshadow_opportunities/tags）；情节段库 `PlotTemplate` + 变量槽 `PlotSlot`（`libraries/plot.py:11/20`）。库→实例靠 `template_id` 回指；展开弧模板成 `stages` 走 `structure_to_stages`（`storyline.py:462`）。

### 2.4 硬规则与写作闭环

- **validate_storyline 两条硬校验**（只报告不修复，问题作 decision_points）：① 顶层弧完整覆盖纵轴（无叙事空白）；② 情节段仅挂叶弧（不是任何弧的父弧）。步3 建书内联回打 ≥1 轮直到 passed；另带 warning 级弧内填充/字数均一提示。
- **字数是权威轴，章是视图**：写作按情节段累计字数，章满（2000–6000 可发布字）由 agent 切分后 `save_chapter_text` 落盘；章号只是兼容视图。
- **agent 写作闭环（薄工具路径）**：
  ```
  get_writing_context → next_plot = tl.plots 第一个 written_chapter==0 且不在草稿内
        │（plot_run 给该情节段收敛上下文：弧目标/线程状态/承诺/字数余量/roles）
        ▼
  agent 自主生成情节段正文 → save_plot_draft（草稿缓冲，同 plot_id 重写）
        ▼（字数达「章」目标）
  save_chapter_text 整章：去 AI 味 → 规则审查 → 硬字数门禁 → 落盘 → 书进度 →
       标记 written_chapter → 角色状态机(§3.4) → 承诺台账 → 清草稿
        └（可选）chapter_quality_gate 五项门禁：审查/连续性/追读/伏笔/爽点
  ```
- 线程穿插：内置引擎有 2:1 加权排序（`libraries/storyline_writer.py:180`，现行 agent 薄工具路径不走）；agent 路径排序 = `next_plot` 沿 `tl.plots` 顺序，线程交错由 agent 生成时自行安排。

## 三、写作时角色「性格 / 口头禅」的注入方式

> 背景：LLM 生成全在 agent 侧 → 平台**不拼 prompt 文本**，注入 = **把结构化人物卡放进工具返回的上下文 payload + skill 指令约束 agent 引用它**。分三条链路：**静态人物卡**（性格/口头禅怎么进正文）、**动态状态机**（每章后角色状态怎么延续）、**风格注入**（笔名语言风格——与人物两条不混）。

> **2026-09-07 升级（行为注入）**：本节下文的「人物卡只带 personality/catchphrase、plot_run.roles 只给名字、动态状态不回流写作上下文」已过时。现行链路为：
> **人物卡** 增 `behavior`（情境→一贯反应）+ `speech_profile`（语言倾向，替代固定口头禅）+ 可选 `development_plan`（成长方向，挂人物不绑 Storyline）；
> **plot_run.cast_pack**（`protagonists/active/referenced`）按出场分级预解析好紧凑卡并注入 csm 动态态（`dyn.goal/relationship/arc_stage/…`）；agent 按情节段经 `save_plot_draft(character_events=…)` 上报**剧情造成的人物变化**，`save_chapter_text` 落账进 `character_states.json`（事件台账），mood/secret 等推断字段禁 agent 直写。
> 三层分工不变且更清晰：**cast_pack 决定「谁在写」、plot_run(plot/arc/thread) 决定「写什么」、pick_plot_sample/get_pen_style 决定「怎么写」**。文件锚点见下文 3.1/3.3 补充说明与代码。

### 3.0 先分清两个「catchphrase」

| | 位置 | 字段形态 | 作用 |
|---|---|---|---|
| **角色原型库**（模板层） | `libraries/data/characters.jsonl` | `CharacterArchetype.catchphrases`（**复数列表**）+ `personality/description/archetypes/examples/tags/fit_tags`（`libraries/character.py:12`） | 建书/提取时给 agent 挑**原型**的素材，不直接进正文 |
| **书内角色**（实例层） | `basic_info.characters[]` | `catchphrase`（**单数**）+ `personality/identity/golden_finger/brief/gender/title/age/relations/faction/role/importance` | 写正文时该引用的**人物卡** |

书内角色由 `set_characters` 整体写入（契约见 `NOVEL_AGENT.md`）：`role` 只取 主角/配角/反派/其他，`importance` 主角=1，`relations` 为 `[{name,relation}]` 数组，`faction` 与势力名逐字一致。主角卡读取走 `get_mc`（`storyline.py:174`，role==主角 优先，importance==1 兜底）；角色列表读 `get_characters`（`storyline.py:166`）。

### 3.1 静态人物卡 → 正文（性格/口头禅怎么用）

**携带载体**：`get_writing_context(book_id)`（`agent_tools.py:282`）一次返回写本情节段所需的全部上下文：

```
get_writing_context(book_id)
  └─ get_book_state(book_id)（agent_tools.py:125）
       ├─ book(配置/tags) / outline(synopsis) / chapters[](最近章摘要) / draft(草稿)
       └─ storyline = BookStoryline.to_dict()
            └─ basic_info.characters[]   ← 完整人物卡（storyline.py:360 原样带出，
                                            含 personality / catchphrase / identity …）
  ├─ protagonist  扁平主角卡（get_mc 结果）
  ├─ next_plot    {plot_id, name, roles:[出场角色名…], outline_id}
  ├─ plot_run     本情节段收敛块：plot 全量 / roles / 弧目标(arc_path+notes+stage) /
  │               线程状态(same_thread_written/unwritten) / 承诺 / words / style_query
  └─ style_card   本笔名精简风格提醒（防漂移，见 §3.5）
```

**使用动作（skill 层约束，写作 agent 执行）**：dsh `novel-story` / Claude `novel-write` 都指示——拿到上下文后组装「**写 next_plot + 出场角色 + 风格 + 前文语气**」，然后自主生成正文。具体到人物：

1. 按 `next_plot.roles`（情节段 `roles` 字段，主角恒在首位）从 `basic_info.characters[]` **取该情节段的出场人物卡**；
2. `personality` 决定该角色行为反应/说话方式的**性格基调**（是冷静毒舌还是热血莽撞）；
3. `catchphrase` 决定其**口头禅/惯用语**——在角色对白中该不该出现、什么时候冒一句；
4. `identity/brief/title` 决定**称呼与身份自洽**，`relations` 决定**与主角/他人的远近称呼**（如关系「宿敌/至交」），`faction` 决定立场站队；
5. 一致性铁律：人名/称呼/数值/设定不得与已写冲突，伏笔前后呼应（写章 skill 里内嵌为纪律）。

> 平台侧没有「把某人物的 personality/catchphrase 单独排版塞进固定 prompt 槽」——因为每章上下文是 agent 连续持有的，重复灌大块角色卡反而稀释。平台给全量人物卡 + 出场名单（roles），引用职责在 agent。

### 3.2 出场角色从哪来

- 情节段 `roles[]`（主角恒在首位）→ `get_writing_context` 的 `next_plot.roles` / `plot_run.plot.roles` 直接暴露出场名单；
- 世界观侧出场约束：`validate_world` 保证人物 `faction` 归势力、势力有人物（一致性底线）；
- 主角全书写卡：`protagonist`（get_mc）每次随上下文扁平给出，保证主角视角铁律有据可依（默认第三人称，视角锁定主角不漂移）。

### 3.3 动态角色状态机（跨章延续的「人物」信息）

性格/口头禅是**静态**卡；每章之后角色的**动态状态**由规则自动机维护：

- 文件：`books/<id>/character_states.json`。
- 写入：`save_chapter_text` 落盘副作用里调 `CharacterStateMachine.update_from_chapter`（`agent_tools.py:938-948`）。
- 字段（`libraries/character_state.py:10`）：`location / mood / goal / power_level / relationship_to_mc / arc_stage / offline_chapters / last_appeared_chapter` 等**动态量**，外加复制的 `gender / personality / catchphrase / brief` 兜底。
- 消费：主要喂 **`chapter_quality_gate` 的连续性检查**（角色状态/出场/语气断裂会出 decision_point）；`register` 只填空字段、不覆盖已演化状态（`character_state.py:40-49`）。
- 写作侧跨章语气延续 = `chapters[]` 最近章摘要（agent 持上下文）；动态状态机**不整块灌进写作 prompt**，是「写完后自动记账 + 门禁核查」的闭环。

### 3.4 边界：与「风格注入」不混（两条独立链路）

| 链路 | 管的对象 | 载体/工具 | 时机 |
|---|---|---|---|
| 人物注入（本节） | 角色**性格/口头禅/关系/称呼**（说什么、怎么称呼） | `storyline.basic_info.characters[]` + `protagonist` + `next_plot.roles`，随 `get_writing_context` 一次全给 | 每情节段运行开始时 |
| 风格注入 | 笔名**语言风格**（句式惯性、禁 AI 味词、叙述距离） | `get_pen_style(no_ref=True)` 全量规则 + `pick_plot_sample` 单篇样文（k=1，服务端按 `plot_run.style_query` 加权随机+避重）+ `style_card` 精简提醒 | 动笔前 `get_pen_style`；每情节段调一次 `pick_plot_sample`；`style_card` 每轮必读 |

> 人物管「内容与对白」，样文管「语言外壳」，互不替代。硬约束：**未拿到风格（get_pen_style）不得写正文**（skill 层），单篇样文是最高风格来源、不抽公式不套模板。

### 3.5 小结：角色信息一次写作的注入顺序

```
动笔前   get_pen_style(book_id, no_ref=True)        全量风格（负约束）
本轮     get_writing_context(book_id)               书/故事线/人物卡(性格·口头禅)/next_plot/plot_run/style_card
         pick_plot_sample(book_id)                   本情节段唯一 STYLE REFERENCE 单篇样文
生成     agent 自持上下文连续产出 → 性格定行为语气、catchphrase 进对白、称呼按 relations
落盘     save_plot_draft(单情节段) → save_chapter_text(整章，含人物状态机更新)
复核     chapter_quality_gate                       连续性/追读/伏笔等，人物状态断裂列 decision_point
```
