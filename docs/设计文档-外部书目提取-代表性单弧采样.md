# 外部书目提取 · 代表性单弧采样方法论（agent 协作）

> 本文定义 **agent 协作模式下外部书目提取功能**的完整方法论：agent（Claude Code / dsh 侧车）在 `/scout`·`/extract` 页读已抓取的参考书 → 自主提炼五类资产 → `drive_ui(set_review)` 呈现 → 用户勾选确认 → 页面入库。
> 回答六个核心问题：**什么是弧 / 如何区分弧 / 如何判断层级 / 如何划分桥段 / 怎么 get「内涵」/ 如何设计写作风格**。
> 概念权威 = `NOVEL_AGENT.md` §1.1（全书唯一来源），故事线概念研究 = `docs/研究文档-故事线大纲桥段线程.md`；落地契约 = `novel-scout` skill 与 `NOVEL_AGENT.md` §1.2。

---

## 0. 提取的产出形态（先对齐，避免三套东西混淆）

外部提取写的是**可复用模板**，进桥段库 / 情节弧库 / 笑点库 / 角色库 / 风格规则库：

| 词 | 书中运行时（平台书内） | 可复用模板（提取产出） |
|---|---|---|
| **弧** | `OutlineSlot`：靠 `parent_arc_id` 树嵌套、`start_word/end_word` 字数轴定位，属某本平台书 | `StructureTemplate`：`stages`=子弧 `StageNode`、`children` 多层嵌套；**单弧一条模板** |
| **桥段** | `PlotSlot`：挂在某叶弧 `outline_id` 下 | `PlotTemplate`：单场景可复用事件模板 |
| **母题** | `plot.theme_hints/theme_moments`、`OutlineSlot.stages[].themes` | `StageNode.themes:[{name, position, how}]` |

**三条硬口径**（与书内规则不同，勿照搬）：
1. **代表性单弧采样**：整本书只挑结构典型、可复用的弧段拆成**单弧模板**（约 1.5万–4万字）。**不做全书故事线还原、不做「顶层弧覆盖全纵轴」**——覆盖规则只约束平台书的 `storyline`（`validate_storyline`），对模板不适用。
2. **`total_words` / `min_words` / `max_words` = 该（采样）弧 / 该 stage 在书里实际占用的字数跨度**，**绝不等于全书总字数**。旧 scout prompt 把 `total_words` 写成 `章数×3000`（全书）是 bug，勿抄。
3. **只表述字数、不含章数**；参考书**不改**。

## 1. 什么是弧（提取语境定义）

**弧 = 有方向/目标的情节单元**（`NOVEL_AGENT.md` §1.1：弧是**树状目标节点**，一个弧承载一个方向/目标，可由多个子弧组成，层数/分支由剧情设计决定、不设固定值）。

在提取语境下要把「弧」读成**可复用目标单元**，而不是卷、不是副本名、不是章数段：

- **弧 ≠ 卷**：卷是几十上百章的出版分组；弧是「末日来临前 10 章囤物资」这一级（约 5–15 章 / ≤3 万字 / 1.5万–4万字模板跨度）。
- **弧 ≠ 章节块**：章节 = 纯字数切分（`words_per_chapter`），不是叙事单元，不能当弧边界。
- **弧 ≠ 桥段**：桥段 = 弧内一个可执行场景/事件（完成子目标的一步，0.3–2 章），弧可含多个桥段与多个场景。
- **弧 ≠ 线程**：线程 = 贯穿全书的横线索（主线/副线/情感线…），由散布在不同弧里的桥段组成，属作者跨弧构思，**提取不建线程**。

一句话判据：**一段篇幅能否被一个「读者可感知的目标 + 一次起承转合的张力 + 一个阶段性收束」概括**。能 → 弧；只能概括为「做了一件事/一场戏」→ 桥段；跨好几个互不相干目标还串不起来 → 拆开。

## 2. 如何区分弧（在一本长书里把一个弧「划」出来）

**识别弧的边界信号**（满足 ≥2 即可判边界；供定位章节边界用，先 `read_crawled_novel(chapter=0)` 看目录再抽样核对正文）：

1. **目标单元的开启与闭合**：出现可被读者感知的「这段要办成什么事」（接任务 / 立计划 / 出现要克服的威胁 / 要夺取的对象 / 要破解的事件）；当该目标**阶段性闭合**（达成 / 失败 / 转化为新威胁，常配打脸、夺宝到手、境界突破、危机解除、身份揭示）即为终点；随后节奏回落进入下一个目标 = 天然边界。
2. **一次完整的张力呼吸**：动机确立 → 阻碍升级 → 尝试/受挫 → 手段升级/翻底牌 → 阶段结果。读到一个「收束小高潮」+ 回落，即可判一个弧走完。
3. **章节块 / 标题信号（最省力）**：卷名、副本名、换地图、事件组标题是强边界；正文用**随机抽样**读（每段头 + 中 + 尾若干章）核对，不必逐章读完。
4. **字数量级**：模板跨度 ≈ **1.5万–4万字**。小于 ~1 万字的多为子弧或大事件（不足单弧样本）；大于 ~5 万字多半内藏多层，先拆子弧再决定是否采。

**采样原则（关键）**：书很长时**不逐弧切全书**，只挑①题材里典型、可在别书复用的弧；②与现有库缺口 / 用户选材方向相关的弧；③结构完整、好讲清、好扩写的弧。弧与弧在书里可以连续甚至交错，但**采样弧彼此独立成模板**，不要求覆盖全书。提炼前先 `query_arc_library` / `query_plots` / `query_gags` 查库内已有模板，避免重复度高。

## 3. 如何判断层级（一个弧该不该拆、拆几层）

**核心判据**：一个节点往下拆成子弧 ⇔ 它承载的目标能分解为 **≥2 个「递进、且各自能独立开合一次小张力呼吸」的子目标**，且每个子目标在书里实际占**一段连续篇幅（经验线 ≥ ~5000 字，不设死值）**。

- **够格拆 children**：子目标之间有**推进关系**（前一个为后一个铺路），且每个单独读起来像一段「小起承转合」。
- **不够格、收作 `key_events`**：并列小额操作（卖房 vs 抵押贷款）、一个动作拆几步、撑不起独立张力的——写进本节点 `key_events`（= 关键事件清单，**不是**子弧名）。
- **一个都不够格 = 叶节点**：书里若给它挂桥段，模板里它就是叶 stage。

参考反例（`NOVEL_AGENT.md` 思考例）：「囤物资」→ 变卖资产→采购→住所加固 是三个递进、可独立闭合的子目标 → 拆成 3 个子弧；「变卖资产」下的 卖房/抵押 是并列小额操作 → 收作 key_events，不再拆。

**实操顺序**：
1. 写出该弧承载的目标。
2. 列出推进该目标所需的**子目标序列**。
3. 逐个按「独立张力 / 连续篇幅 ≥ ~5 千字 / 能否独立闭合」打标。
4. 够格的递归进 `children`；不够的留作本节点 `key_events`。
5. 为整弧与每个有意义的节点补 `foreshadow_opportunities`（能埋的坑，将来在哪收）与 `themes`（见 §6）。

**硬约束**：深度/分支**按书里真实结构定、不要求均匀**——同一份提取里 3 层弧、1 层弧、纯叶弧并存是合法的。别为了好看强拆到等深。

## 4. 如何划分桥段（弧内怎么切、怎么进桥段库）

弧往下切桥段，是「把完成子目标的一步步动作/冲突切成**单场景事件**」，每桥段承载推进一步。

**切分尺度与内容判据**：约 **0.3–2 章 / 800–2500 字**（模板 `word_range` 默认 [800, 2500]；运行时 `planned_words = cover_beats×200 封顶 1200` 是**书内**口径，模板不需要）。一个合格桥段应含：场景、人物行动、冲突或小转折、能直接扩写成文。

**模板化三件事**（决定它能否被别书复用）：
1. `template_structure` = 箭头流程骨架：`[当众羞辱]→[主角隐忍]→[关键时刻亮实力]→[全场震惊]→[对方后悔]`。骨架只留**戏剧动作**，不留人名数值。
2. `slots` = 变量槽 `[{name, options}]`：把桥段里会随书/角色变化的点提成槽（如 `空间类型: [封闭密室, 空旷大厅, …]`）。**能提槽的才值得入库**。
3. **剥离绑定**：主角名 / 专有金手指 / 具体数值 → 不写进桥段。绑定角色的私货归角色模板（`catchphrases`），绑定金手指的设定归弧模板，桥段只留「换个人也能演的戏剧动作」。

**从书里筛**（不是叶弧内每拍都收）：只收①情绪 / 爽感 / 反转结构清晰、可迁移；②库里同类少的；③能一句话讲清动作骨架的。纯流程向、非网文爽点节奏的事件不收。

## 5. 笑点(gag)：抓到「为什么好笑」的机制

目标 = 把段子抽象成**与人物解耦的可复用机制**：

- 落 `pattern_description`（机制描述，含「结构：…」句式骨架，如 `生死关头对方猜身份 → 主角一本正经报离谱职业 → 全场错愕`）+ `fit_scenes`（适配场景）+ `examples`（书里原例 1–2 条）。代码会把 `pattern_description` 自动回填 `template`。
- 提炼法：读到段子 → 问「笑点来自哪种结构」（预期违背 / 冷面吐槽 / 误会错位 / 反差 / 内心吐槽 / 节奏破坏…）→ 写成与人物解耦的机制。
- **绑定具体角色的口头禅式笑点 → 归角色 `catchphrases`，不进 gag 库**。
- 一个 gag 至少能被答出「在什么场景、对什么预期、做哪种打破」才成立，否则不单收。

> 注：平台语义里 **「内涵」≠ 笑点机制**。gag 只承载机制（`pattern_description`）；「内涵」指**母题/theme**，见下节。

## 6. 怎么 get「内涵」（母题 / theme 挂载）

平台术语里 **内涵 = 母题/theme**：全文反复出现、可被读者反复「尝到」的主题意义，与笑点无关。既有词汇表：**公平（Justice）/ 成长的代价（Cost of Growth）/ 身份与伪装（Identity & Disguise）/ 牺牲（Sacrifice）/ 归属感（Belonging）/ 传承与突破（Legacy & Breakthrough）**，可扩。

**提取产出落点**：弧模板的**整弧与每个 stage** 写 `themes:[{name, position, how}]`——
- `name`：母题名（上面词汇或自拟）。
- `position`：母题在**这段**最浓的位置（开头 / 中段 / 结尾）。
- `how`：靠**哪类事件**让读者尝到它（如「主角为救人押上全部家当」落地 牺牲）。

**提炼问法**：读一段 → 问「这段最想让读者心里留下哪种味道/主题意义、在哪个位置最浓、靠哪类事件落地」。写不出 `how` 就不硬写。

**传导链与已知边界（如实保留，决策点暂不改代码）**：平台书内 plot 级自动化挂母题靠 `THEME_PLOT_COMPAT`（`libraries/storyline.py` 内）且**只覆盖内置 `plot_dating_*` 桥段模板**；`scout_*` 提取桥段的 template_id 不在此表，故 scout 桥段无法经该规则自动带母题。因此 **scout 弧模板的 `stage.themes` 是「新书用它时选母题 / theme_moments 传导」的主要载体**——这正是要求 stage 写 `themes` 的原因。若想让 scout 桥段也自动挂母题（把提取桥段的 category 或模板接入一张映射表），属**未来可做项**，本文档不做代码改动。

## 7. 角色原型提取（简述）

人物 → 原型，落 `personality / description / archetypes / examples（含出处角色）/ catchphrases / tags / fit_tags`。**剥掉与书名绑定的专属剧情**；可复用的是「人设类型 + 口头禅 + 适配题材」。参照样例：`冷静破局智囊 ← 《十日终焉》齐夏（职业骗子型主角 / 规则破局者 / 高智商冷静型）`。

## 8. 如何设计写作风格（外部作者文风 → 目标笔名规则）

**落点只能是 `prefer` / `ban` 两条机制**（平台风格规则库，归属用户所选笔名 `profile_id`；未指定归默认笔名「枫落」），且**规则语义站在平台读者 / 去 AI 味视角——不是克隆作者**。

> 红线（平台设计硬约束，`docs/设计文档-总览-claude.md`）：**刻意不做**「拆书仿写 / loom 式写作指纹」级分析，风格只能落规则层。

**提炼法**：抽读 5–15 章（开头几章 + 中段 + 对话密集章）→
- **句式层 → `prefer`（正向指令）**：句长整体倾向（短句为主 / 长短交错 / 长句铺陈）、段落疏密、对话占比、视角与心理描写习惯、「有效且想借用」的句式结构。写成指令文本，如 `句长偏短，动作推进用三连短句`。
- **用词 / 套话层 → `ban`（禁止内容）**：作者的套话、口头禅、冗余腔调——若属「AI 味 / 水词要防」，落 `ban` 且 `replacements` 给替代表达（作者的常用替代表达正好可填进 `replacements` 触发自动去 AI 味替换）；`replacements` 空 = 硬禁句式检测。**作者低效 / 雷同 / AI 味的表达照禁**，不是照抄。
- **数量分寸**：一档建议 3–8 条 `prefer` + 5–15 条 `ban`，只收「高频、可判、有迁移价值」的，不把整本书词典灌进规则库。

## 9. 呈现与入库纪律（agent 协作护栏）

1. 提炼完五类（桥段 / 弧 / 笑点 / 角色 + 写作风格规则），调 `drive_ui(set_review)` 呈现成**可勾选审查卡**——`title` 必填、五类至少一类非空；`style_rules` 每项 `{kind(prefer|ban), pattern, desc?, severity?, replacements?}`。
2. **然后停下，等用户勾选确认**，不直接 ingest；汇报「已呈现，请在页面勾选确认入库」。用户确认后由**页面** POST `/api/scout/ingest` 落库（不经 agent）。
3. **兜底**：仅当用户明确要求直接入库，才调 `ingest_library_assets`（四库，不含风格；风格另用 `add_style_rule` 逐条）。
4. 参考书仅供借鉴 / 入库复用，**不改书**。
