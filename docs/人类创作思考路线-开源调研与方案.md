# 模拟人类创作思考路线：开源模式调研与本项目落地方案

> 日期：2026-08-05。任务：模拟人类创作小说时的思考路线 → 调研 GitHub 相关开源模式 → 给本项目（NovelEngine）落地方案。
> **硬约束**（本项目记忆约定）：保持 `deepseek-v4-flash` 模型；只优化 prompt / 生成参数 / 免费规则层；不换模型、**不加"写完质量重写"型 LLM 后处理**。本方案的每一条都对照此约束分级。

---

## Part 1：人类创作小说的思考路线（认知模型）

把一位成熟网文作者从"一个念头"到"一章落地"的思考拆成 11 步。本项目"已有/缺失"对照见表格。

| # | 思考环节 | 作者在做什么 | 本项目现状 |
|---|---|---|---|
| 1 | **选题/市场直觉** | 写给谁看、哪个平台赛道、核心卖点、反卖点、书名简介钩子 | ⚠️ 部分：Phase 1 故事分析产出设定，**缺市场定位（卖点/反卖点）与逐章留存计划** |
| 2 | **真相源（设定库）** | 主角欲望/恐惧/弱点、金手指机制数值闭环、世界规则、配角声线、禁忌桥段 | ✅ 有：`basic_info` + 书级设定卡（Book Bible） |
| 3 | **全书骨架** | 主线目标、几大阶段、终局在哪（不写死，滚动） | ✅ 有：大纲序列（OutlineSlot）+ 过渡类型 |
| 4 | **分卷/卷纲** | 每卷显性目标、隐藏危机、阶段反派、伏笔回收表 | ⚠️ 部分：大纲=卷弧，有阶段事件，**缺卷级目标/隐藏危机/伏笔回收表** |
| 5 | **分章细纲** | 每章入口功能、读者此刻欲望、可见爽点、章尾追更理由 | ✅ 有：阶段→桥段（PlotSlot）+ slots |
| 6 | **开写前瞬间（编辑诊断）** | 上一章结尾承接什么、这章最强爽点、敌人要付出什么可见损失、谁出场、章尾留什么钩子 | ⚠️ 部分：render_bridge_prompt 有上下文组装，**缺"读者欲望/最强爽点/敌人损失/追更理由"诊断块** |
| 7 | **写句子（技法）** | 情绪→视角/节奏/话语模式映射；对话驱动；画面优先 | ✅ 有：render_bridge_prompt 7 条铁律 + 视角铁律 + 出场人物 |
| 8 | **灵机一动（涌现）** | 笑点现场冒出，不硬凑 | ✅ 有：GagInjector 探测器环（本项目独有且已落地） |
| 9 | **写后自查** | 人设崩没崩、逻辑通不通、AI 味重不重、钩子够不够 | ⚠️ 部分：`reviewer.py` 规则检查存在，**未接入写作流程做门禁** |
| 10 | **账本更新** | 埋了哪些伏笔（承诺）、兑现了哪些、人物状态变没变 | ⚠️ 部分：`resolves_plot_id` 设局→收局 + `character_states` + 语义摘要，**缺"读者承诺台账"（outstanding/overdue 生命周期）** |
| 11 | **长线回扣** | 后面想起前面埋的钩子，回扣闭环 | ⚠️ 部分：设局→收局 + CONSISTENCY_RULES，缺跨章的承诺到期提醒 |

**核心洞察**：人类作者能写百万字不崩，靠的不是"记得住"（那是上下文窗口），而是三件东西——**分层规划**（大→小逐层展开）、**承诺台账**（埋了什么一定记下、到期兑现）、**写前/写后两个瞬间**（开写前想清楚这一节要达到什么，写完后对照检查）。开源项目全部围绕这三件东西做文章。

## Part 2：GitHub 开源模式调研（重点项目 + 可借鉴点）

调研了 10+ 个中文/英文长篇小说生成开源项目，四个与本项目最相关、模式最可迁移的如下（其余见文末列表）。

### 2.1 zhougz520/novel-architect —— 审查门禁 + 读者承诺台账（生产验证 140 章）

网址：[novel-architect](https://github.com/zhougz520/novel-architect)

- **开书流程**：`init 骨架 → market-pack（写给谁/卖点/反卖点/前10章每章 hook）→ 补强真相源（blueprint/characters/voice_bible/world/taboos/volumes）→ first10 留存计划 → 前三章试生产 → first3-review 门禁 → 第 4 章起稳定续写`。
- **章节生产**：`status → prepare（产出 writing_task：writer_brief/reader_desire/visible_payoff/enemy_visible_loss/status_change/turn_page_reason/active_reader_promises）→ beat-competition（生成 ≥3 个候选方案：更爽/更猎奇/更狗血，按读者欲望/可见 payoff/敌损/追更理由选优）→ write → review → model signals → repair 直到 gate.passed → commit`。
- **12 项质量信号**：reader_pull / visible_payoff / blockbuster / title_hook / character_voice / domain_translation / story_logic / state_guard 等，AI 判断 + 确定性 state guards 分离。
- **读者承诺台账**：每章"记忆回写"登记新增/兑现/overdue 承诺（带 id/类型/期待/兑现窗口/强度/线程），`commit` 时更新 ledger。
- **正文禁区**：写后扫描正文不得出现"上一章/本章/伏笔/作者安排/剧情需要"等创作流程词，必须有故事内语言承接。

> 借鉴：**writing_task 的编辑诊断字段集**、**beat 竞争**、**读者承诺台账**、**正文禁区扫描**、**first3 门禁**。

### 2.2 jiaw-Zh/long-novel-writer —— 分层摘要冻结 + 正典账本（百万字）

网址：[long-novel-writer](https://github.com/jiaw-Zh/long-novel-writer)

- **六层摘要（L0-L5）**：L0 正文永不改 → L1 单章 brief 写完即冻结 → L2 chunk(3-5章) → L3 arc(10-30章) → L4 卷 → L5 全书。只读下层不改下层；卷收尾才重生成 L5。
- **实体中心档案**：角色/地点/道具/组织/力量体系各一文件，四段式（正典摘要/硬约束/关键节点追加/当前状态）；写某章只按需加载出场实体。
- **正典账本（canon ledger）**：`facts.jsonl`（原子事实，追加不修改，含 `known_by` POV 知识边界）/ `rules.md` / `timeline.md` / `promises.jsonl`（承诺状态机）/ `progression.jsonl`（境界不可倒退）。
- **写前组装协议**：9 步固定顺序拼上下文（story-bible → 当前卷/arc 摘要 → 章 blueprint → 最近 3-5 章 brief → 上一章结尾原文 → 出场实体 + 已知秘密 + 台词样本 → 活跃伏笔 → 禁用桥段 + overdue 承诺 → 关键词反查相关章节）。
- **写后校验**：前置字数门（机械）+ 8 项语义（正典冲突/POV 边界/硬约束/进阶合法性/命名一致/桥段重复/场景节奏/台词样本更新）。
- **节奏监测**：同一 scene_type 连续 ≥4 章提示切换、张力连续 5 章超界提示调节奏。

> 借鉴：**分层摘要冻结**（本项目语义摘要 = 只做到 L1）、**承诺/进阶账本**、**POV 知识边界**、**节奏监测**。

### 2.3 sanshanjianke/ai-webnovel-workflow —— 四层创作架构 + 叙事技法映射

网址：[ai-webnovel-workflow](https://github.com/sanshanjianke/ai-webnovel-workflow)

- **L1 种子层**：创意结构化（把一句话创意拆成可操作的要素）。
- **L2 架构层**：三专家会议（资深作者/读者代表/剧情架构师/网络编辑/人物设计师）产出剧情方案。
- **L3 叙事层**："效果 → 技法"确定性映射（翻译器）：压抑→反派内聚焦+慢速扩述+对话心理；爆发→外聚焦+中速等述+动作环境；余韵→众人视角+快速概述+震惊反应。装逼打脸标准配置=铺垫(压抑)/反转(爆发)/收尾(余韵)。
- **L4 渲染层**：按细纲的视角/节奏/话语模式生成正文。

> 借鉴：**情绪→视角/节奏映射**（免费规则可做，直接写进 prompt）。

## Part 3：落地方案（分级：免费规则 / 轻量 LLM / 不建议）

> 排序原则：先做**零成本免费规则**（Tier 1），再做 **flash 便宜的单次轻量调用**（Tier 2），明确**不做的**（Tier 3）。全部尊重"不加写完重写后处理"的硬约束。

### Tier 1 — 免费规则层（不调 LLM，改动最小、立即可做）

#### 1.1 读者承诺台账（Reader Promise Ledger）★ 最高价值
- **现状**：`PlotSlot.resolves_plot_id/resolves_name` 只有"设局→收局"一次映射，没有跨章生命周期（哪些承诺 outstanding / overdue / 到期该兑现）。
- **落地**：
  - `libraries/timeline.py`：`BookTimeline` 加 `promises[]`（`{id, type, status: pending|advanced|fulfilled, expected_window, deadline_chapter, setup_plot_id, desc}`）。
  - 桥段写完后（`engine._finalize_written_chapter`）免费规则登记：设局桥段 → 新增 pending 承诺；收局桥段写完 → 标记 fulfilled；阶段推进 → advanced。
  - `prompt_harness.render_bridge_prompt` 注入【读者承诺台账】块：本桥段要兑现的、已 overdue 的（免费规则按当前章节号对比 deadline）。
- **改动文件**：`timeline.py` / `prompt_harness.py` / `engine.py`。

#### 1.2 写前编辑诊断（Pre-write Diagnosis）★ 直接映射人类第 6 步
- **现状**：render_bridge_prompt 有上下文，但缺"这一节要达到什么"的诊断块。
- **落地**：免费规则从 timeline 现算 5 行【写前诊断】注入 prompt：
  - 读者此刻欲望 ← 桥段 category 映射（爽文→打脸快感；悬疑→解谜欲；情感→关系推近；成长→变强确认）
  - 本桥段最强可见爽点 ← `hook_points[0]` / `template_structure` 高潮位
  - 敌人/系统可见损失 ← 无（免费规则给"通用损失模板"：身份/面子/资源/权力 选其一）
  - 章尾追更理由 ← 本桥段组尾必须留的悬念（已有），升级为显式指令
  - 要承接的上一章钩子 ← 已有【上一章结尾】
- **改动文件**：`prompt_harness.py`（新增 `_pre_write_diagnosis()` 纯函数 + 注入 render_bridge_prompt）。

#### 1.3 叙事技法映射（情绪→节奏）—— 借鉴 L3-narrative
- **落地**：按桥段类型给 render_bridge_prompt 注入一段【本桥段节奏提示】（免费规则，一句话）：
  - 爽文打脸 → 铺垫用压抑细节（对话+心理）→ 反转用快动作 → 收尾用众人反应；
  - 悬疑 → 内聚焦信息差 + 短句留白；
  - 情感 → 慢速扩述 + 对话延伸。
- **改动文件**：`prompt_harness.py`。

#### 1.4 正文禁区扫描（Meta-leak 扫描）—— 借鉴 novel-architect
- **落地**：`timeline_writer.py` 写每组后免费规则扫描正文，命中"上一章/本章/伏笔/作者安排/剧情需要/这里先埋"等创作流程词 → 不重写（守约束），而是**注入下一组【重写提示】**："上一段出现创作流程词「X」，请用故事内语言承接"（复用现有 `WRITER_EMPTY_RETRIES` 重试通道）。
- **改动文件**：`timeline_writer.py`。

#### 1.5 场景类型/节奏监测 —— 借鉴 long-novel-writer
- **落地**：免费规则统计最近 N 个已写桥段的 category 分布，连续同类型 ≥4 桥段时注入"本章应切换场景类型"提示；收局密度过低（设局多、收局久未出现）时提示"该回收钩子了"。
- **改动文件**：`prompt_harness.py` / `timeline_writer.py`。

### Tier 2 — 轻量 LLM（≤500 token 输入、≤256 输出，flash 便宜；仍是"生成过程"不是"重写后处理"）

#### 2.1 前十章留存计划（Retention Plan）—— 新书创建 Phase 1 后一次调用
- **落地**：`outline_generator` Phase 1 故事分析后，可选追加一次轻量调用，产出 `retention_plan`（前 3 章每章 hook/可见 payoff/弃读风险 + 前 10 章节奏），存 `timeline.json`，写作时注入前几章的【留存计划】块。
- **改动文件**：`outline_generator.py` / `prompt_harness.py`。

#### 2.2 前三章门禁（first3 gate）—— 第 3 章写完一次检查
- **落地**：`engine._finalize_written_chapter` 在第 3 章时触发一次轻量检查（输入前 3 章语义摘要 ≤500 token），输出 pass/fail + 一句建议；fail 时建议注入第 4 章写作 prompt（不是重写前 3 章）。
- **改动文件**：`engine.py` / `prompt_harness.py`。

#### 2.3 Beat 竞争（轻量版，可选开关）—— 关键桥段开写前
- **落地**：对设局/收局/转折/卷末桥段开写前，给 2-3 个写法角度（更爽/更冲突/更悬念）让模型选一个（≤500 token）；默认关闭，`book.json` 加开关。普通桥段不开，避免每桥段都加一次调用拖慢。
- **改动文件**：`timeline_writer.py` / `prompt_harness.py`。

### Tier 3 — 不建议做（违反本项目硬约束）

| 模式 | 为什么不做 |
|---|---|
| 整章重写/扩写/缩写（enrich/condense/rewrite loop） | 直接违反"不加写完质量重写后处理" |
| 多智能体独立交叉评审（subagent cross-review） | 每次多份完整调用，flash 下成本/收益存疑，且与"单一生成管线"冲突 |
| 向量库 / 知识图谱 RAG（ChromaDB/Neo4j/BM25） | 本项目是 prompt 优先、无重型基础设施；timeline JSON + 语义摘要 + 承诺台账已覆盖同等目标 |
| 拆书+仿写整书 | 需外部书源解析管线，超出"新书创建"范围，且仿写风格与笔名档案机制重叠 |

## Part 4：改动顺序建议

按 1.1 → 1.2 → 1.3 → 1.4 → 2.1 → 2.2 推进（1.5 随 1.1 一并做）。每一条都能独立提交、独立验证：

1. **1.1 承诺台账**：先在 `timeline.py` 加模型字段 → 落盘/加载 → 写后登记 → 写前注入。无 LLM 调用，`test_all.py` 健全性可覆盖。
2. **1.2 写前诊断**：纯函数，直接进 render_bridge_prompt，改 prompt 即可用现有 E2E 看效果。
3. **2.1 留存计划 / 2.2 first3 gate**：新增两次轻量调用，需验证 flash 的 max_tokens 余量（沿用"输入 ≤500 token、输出 ≤256"约定，给足推理余量）。

### 5.3 对照本项目后修正的优先级

相比 Part 3 的通用顺序，**针对本项目**最优改动顺序是（每条都是接线或纯规则，无新增 LLM）：

1. **接线 hook_points → render_bridge_prompt**（5.1 第 1 条）：最便宜的"爽点白生成"修复，直接提升写作质量。
2. **接线 reviewer → `_finalize_written_chapter` 门禁**（5.1 第 2 条）：零调用点变 gate，fail 注入下一桥段【重写提示】（不重写、守约束）。
3. **接线 platform_constraints → render_bridge_prompt**（5.1 第 3 条）：番茄铁律进 prompt。
4. **读者承诺台账 promises[]**（5.2 #10/#11）：最大缺口，见 Part 3 Tier 1.1。
5. **写前编辑诊断**（5.2 #6）：纯函数，见 Part 3 Tier 1.2。
6. **叙事技法映射 + 卷级目标 + 留存计划 + first3 gate**：依次为 Tier 1.3 / Tier 2 类。

> 1-3 是"接线"，半小时内可完成且可独立验证；4-5 是新字段+纯函数；6 往后才是新 LLM 调用。
