# 交接文档：故事线构建改造——plots 草案评审门 + 研究式多段深化（L1/L2/L3）

> 日期：2026-09-04　提交：c12260f / d430768 /（skill/指令层）/（老路径删除与文档）　范围：dsh/平台侧（Claude 侧不跑故事线构建）
> 一句话：**新书弧+桥段不再「随 submit 直接 phase=ready」**——改为 submit 落 **phase=plots 草案** → 页面自动派 dsh「深化弧+桥段」任务（研究式多段深挖 + 免费规则校验回改）→ 用户在书详情页点「✅ 确认弧+桥段」才进 ready。**ready 翻转无任何 agent 工具**。

---

## 一、背景与动机

弧+桥段原本是 agent **一次生成** → 向导 submit → `phase=ready` → 写作立即解锁。产物**浅、模板味**：

- 研究文档实锤 agent 产扁平顶层弧 / 卷级大纲（book_001/002）。
- dsh `novel-build` skill 只有「可反复思考 / 反复反思直到满意」的**软词**——LLM 被要求「多想想」不会多想，必然走阻力最小路径（查模板 → 一次 `set_outline` 交差）。
- `validate_storyline`（免费规则）「只报告不修复」，从不在定稿前形成打回环。

目标：构建故事线像研究一样**多段深层思考**，而非一次 LLM 调用出浅模板蓝图。深度靠「中间产物可被校验/人打回」逼出，不靠要求模型自觉。

## 二、目标形态（新书故事线流）

```
向导步3 agent 照常草拟弧+桥段(初稿, 允许浅)
   → submit 建书：phase=plots（草案）                          ← dashboard 不再置 ready
   → 跳书详情(?newdraft=1)，页面自动发一次 dsh「深化弧+桥段」任务（仿 step2→build 接棒；sessionStorage 防重发）
        L1 反模板：差异化命题 + 每弧 notes「目标+偏离库模板点」（存盘）
        L2 回改环：validate_storyline(book_id, 含 arc_fill) → save_outlines 回改 → 再校验，
                   until passed 或残留 decision_points 明确列出（≥1 轮）
        → 蓝图汇报（弧树/字数/线程/设局收局 + passed + decision_points）
   → 用户过目（书详情横幅/故事线）→ 点「✅ 确认弧+桥段，开始写作」
        → /api/book/<id>/confirm-storyline：挂内涵 + phase=ready（唯一翻转）
   → novel-story 写作解锁（plots 期间写作工具已被 phase 门拒）
```

phase=plots 期间 `save_bridge_draft` / `save_chapter_text` / `save_book_meta` / `chapter_quality_gate` 均被 `tool_policy.py` phase 门拒（只允许 ready）→ 草案书写不了正文，天然护栏。

## 三、三层机制

- **L1 反模板指令脚手架（skill/指令层，存盘）**：排弧前先想清「本书与同类/所查模板的差异点」→ 最核心一条压 `world_building.core_conflict`；完整论述/发散比较在书已建（plots）后经 `save_basic_info` 存 `world_building.differentiation`（深合并保留任意键，门控已放开到 plots）；**每条弧 `notes` 必含「弧目标 + 偏离库模板 X 的点」**（落库可复核，供蓝图/用户过目）。
- **L2 校验回改闭环**：定稿/深化时**必调** `validate_storyline`（建书前走内联 outlines/plots，建书后走 `book_id` 含 arc_fill），首次没过必须 ≥1 轮回改，二次仍不过的 `decision_points` 才列给用户裁。
- **L3 草案评审门（平台硬墙）**：建书落 `plots` 草案；**plots→ready 唯一翻转 = 用户 UI 确认端点**；深化任务在 plots 内 `save_outlines`+`validate` 迭代。

## 七、坑 / 注意

- **续写/扩写追加弧**：靠「已 ready 保持 ready」不降级（否则删 fill_gags 后会卡死在 plots 且无 agent 能翻回）。这是删除 `fill_gags` 的**必要条件改动**，勿回退。
- **差异化命题存盘两条路**：向导 submit 前（书未建）只能压 `core_conflict`（`worldToBi` 白名单会丢自定义键）；完整论述/`world_building.differentiation` 只能在书已建（plots）后经 `save_basic_info` 写。`save_basic_info` 门控因此放开到 `{config, plots}`。
- **弧 notes 落盘**：`set_outline`（向导）与 `save_outlines`（薄工具）两条路都要能带 notes；薄工具原先丢 notes 已修，别在重构 OutlineSlot 构造时再漏 `notes=o.get("notes","")`。
- **旧内部 editor 路由** `api_fill_gags`/`api_confirm_outlines`（storyline 蓝图）仍会翻 phase，但 **agent 不可达**（非 MCP、dsh 无浏览器点击）——保留仅旧编辑器兼容并标废弃；用户自己走那里等于人工确认，可接受。
- **遗留 config 书**（book_001/002）：novel-outline 老路径已删，不再有老流程翻 ready；如要救 → `save_outlines` 落弧 → plots → 用户在书详情确认（`save_outlines` 工具仍在、门控含 config/plots）。
- **文档一致性**：docs/架构总览 工具数已更 39；`docs/分析文档-写作流程skill`、`docs/架构文档-内置agent-dsh`、`docs/设计文档-总览-claude` 仍为旧工具架构的历史记录，未重写（列出旧 fill_gags/novel-outline 属历史快照，勿当现行契约）。
