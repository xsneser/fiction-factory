## 一、项目定位（v0.5）

**全自动网文量产系统**：AI 拟人写作 × 节拍级生成 × 外部采集 + 分析入库。

### 核心理念

每个笔名 = 一个独立的 AI 作家，拥有独立的记忆、风格、桥段库和创作习惯。不是"一个生成器生成多本书"，而是"一群 AI 作家同时开工"。

### 不是

- 不是 MOSS 项目的子模块（完全独立）
- 不是"按模板生成一段，人工编排"的半自动工具（已全自动）
- 不是简单 prompt 拼接（有完整架构层）

### 核心算法：扫描线槽位分配

大纲和桥段栏均使用扫描线算法避免重叠：

```python
def assign_lanes(items):
    """
    为时间上重叠的条目分配不重叠的水平槽位。
    排序后贪心分配：每个条目放入第一个空闲的 lane。
    """
    sorted_items = sorted(items, key=lambda x: (x.start, -x.end))
    lanes = []  # lanes[i] = 该槽位最后一条的 end
    assignments = [0] * len(items)

    for idx, item in enumerate(sorted_items):
        lane = 0
        while lane < len(lanes) and lanes[lane] > item.start:
            lane += 1
        lanes[lane] = item.end
        assignments[item._original_idx] = lane

    return assignments, len(lanes)
```

### 各栏位设计细节

| 栏位 | 数据类型 | 渲染方式 | 排版规则 |
|------|---------|---------|---------|
| **大纲** | 范围（start-end） | 彩色竖条，渐变色 | 扫描线槽位，重叠则左右错开 |
| **桥段** | 范围 + 嵌套层级 | 竖条 + 缩进 + 连线 | 先按层级分块，块内扫描线分配 |
| **笑点** · **内涵** | 点（word） | 圆点 / 菱形◇ | 同栏左右分列，笑点左、内涵右 |

### 交互

- 悬停任意元素 → tooltip 显示名称、字数范围、跨度、层级/手法
- 章节分隔线（虚线）横贯全部栏位
- 桥段父子关系用贝塞尔曲线连线
- 底部图例：大纲 / 主桥段 / 子桥段 / 笑点 / 内涵 / 章节

### 与四大库的映射

| 库 | 数据类 | 可视化 |
|----|--------|--------|
| `libraries/structure.py` | 大纲线（ChapterOutline） | 大纲栏 → 范围彩条 |

## 三、引擎流程

### 3.1 新书启动

```
规划（大纲+角色+伏笔+书名方案）
  → CH1（钩子 + 金手指 + 首次危机）
  → CH2（世界观展开）
  → CH3（首次核心冲突）
  → 生成书名+简介
  → 自动转入续写模式
```

### 3.2 续写循环

```
写 → 审 → 去AI → 修正 → 继续写
```

每章拆 6-8 个**节拍**，用 14 种微模板逐节拍生成：

| 节拍类型 | 说明 |
|---------|------|
| 开篇 | 章首场景锚定 |
| 对话 | 对话推进剧情 |
| 动作 | 动作描写 |
| 内心独白 | 角色内心活动 |
| 环境描写 | 场景氛围 |
| 战斗 | 打斗场景 |
| 冲突 | 冲突升级 |
| 反转 | 剧情反转 |
| 情感爆发 | 情绪高点 |
| 日常过渡 | 舒缓段落 |
| 信息揭露 | 关键信息揭示 |
| 悬念收尾 | 章末悬念 |
| 高潮 | 剧情高潮 |
| 余韵 | 事后的情绪沉淀 |

### 3.3 BookAssembler（昨日新增）

连接四大库与生成管线的关键模块。核心工作流：

```
选定大纲 → 逐阶段匹配桥段 → 逐桥段匹配笑点
→ 选定全书母题 → 生成 Plan → 注入写作 prompt
```

LLM 在写作 prompt 中看到：
- 当前阶段要用的桥段模板 + 变量填充建议
- 该桥段匹配到的 1-3 个笑点模式
- 全书的母题 + 阶段级内涵提示

匹配策略：纯规则（关键词 + 分类 + 评分），无额外 LLM 调用。

## 五、番茄侦察兵（`plugins/fanqie_scout.py`）

| 功能 | 方式 | 说明 |
|------|------|------|
| **搜索** | Bing 搜索 → SSR 页面解析 | 番茄搜索 API 全部失效（`code:-2`） |
| **下载** | Reader 页面 SSR → PUA 字体解码 | 使用 fonttools + 内置 362 映射表 |
| **分析** | 4 次 LLM 调用 | 桥段/大纲/笑点/内涵自动入库 |

### PUA 解码关键发现
- 章节数据在 `page.chapterListWithVolume`（二维列表）
- 正文在 `reader.chapterData.content`（PUA 编码）
- Reader URL：`/reader/{chapter_id}`（不带 book_id）
- 字体从 `@font-face` CSS 提取
- 每本书字体不同，映射表不通用

#### 2.1 大纲引擎设计

**输入**：用户想法（流派/子流派/自定义描述）+ 笔名档案 + 四大库（作为候选池）
**输出**：`BookTimeline` JSON — 多大纲时间线 + 桥段嵌套 + 笑点/内涵/吸睛注入

**5 阶段 LLM 管线**（SSE 流式）：

```
用户输入
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ Phase 1: 故事分析（1 次 LLM）                             │
│   输入: genre, sub_genre, custom_context, pen_profile    │
│   输出: {protagonist, world_building, tone, audience}    │
│   → 写入 BookTimeline.basic_info                         │
├──────────────────────────────────────────────────────────┤
│ Phase 2: 大纲时间线规划（1-2 次 LLM）                     │
│   输入: basic_info + StructureLibrary 候选模板            │
│   AI 从大纲库选 2-5 个模板，排布时间线                    │
│   （顺序接续 / 重叠过渡 / 融合）                          │
│   输出: OutlineSlot[]，每大纲含 stages[]                  │
│   质量保障：自动验证大纲覆盖度 → 不足则重试               │
│   → 写入 BookTimeline.outlines                           │
├──────────────────────────────────────────────────────────┤
│ Phase 3: 桥段编排（每大纲 1 次 LLM）                      │
│   输入: OutlineSlot + PlotLibrary 候选桥段               │
│   每阶段匹配 1-3 个桥段，AI 决定嵌套/链式关系             │
│   填充变量槽位（slots），分配 cover_beats                │
│   输出: PlotSlot[]                                       │
│   质量保障：桥段分类覆盖检查                              │
│   → 写入 BookTimeline.plots                              │
├──────────────────────────────────────────────────────────┤
│ Phase 4: 加料注入（规则匹配 + 1 次 LLM 复查）             │
│   笑点：按桥段 category 从 GagLibrary 匹配，AI 复查       │
│   内涵：从 ThemeLibrary 选全书母题 → 分配每桥段 hint      │
│   吸睛：每桥段标记 1-2 个 hook_points                    │
│   → 写入 PlotSlot.gag_ids / theme_hints / hook_points    │
├──────────────────────────────────────────────────────────┤
│ Phase 5: 一致性验证（1 次 LLM）                           │
│   检查：时间线合理性、桥段-大纲匹配、笑点密度分布          │
│   输出: 验证报告 + 自动修正建议                           │
│   → 用户可确认/手动调整                                   │
└──────────────────────────────────────────────────────────┘
  │
  ▼
BookTimeline JSON → 存入 books/{book_id}/timeline.json
                   → 可喂入 BlueprintWritingPipeline 或 BeatWriter
```

**每次 LLM 调用的上下文注入**（参考 show-me-the-story 的做法）：

- 笔名档案的风格指纹
- 前面阶段已生成的内容作为约束

#### 2.3 与 show-me-the-story 大纲的关键差异

| 维度 | show-me-the-story 大纲 | NovelEngine 大纲（BookTimeline） |
|------|----------------------|--------------------------------|
| **粒度** | 逐章文本描述 | 多大纲时间线 + 阶段 + 桥段 |
| **结构** | 线性 chapter[].outline | 非线性 Outlines → Stages → Plots（树状） |
| **关系** | 无 | 重叠/融合/前驱后继 |
| **注入** | 无 | 笑点 + 内涵 + 吸睛 三者显式标注 |
| **可复用性** | 每书新生成 | 模板库驱动，AI 编排+选择 |
| **输出格式** | 纯文本 | 结构化 JSON（可程序化消费） |

> **目标**：把 show-me-the-story 的工程精华移植到 NovelEngine，解决 token 效率、质量验证、容错三个短板。

- [ ] **P0-1 修复 engine↔timeline_writer 断链** ✅ 已完成（7/31）
- [ ] **P0-2 Volume 压缩（Arc-aware outline compression）**
  - 来源: show-me-the-story `inject.go:buildOutlineConstraintsForLang`
  - 做法: `build_outline_constraints` 中，已总结卷的 past 章节压缩为 `【《卷名》卷摘要】` 一行
  - 效果: 100 章书 past 部分从 ~90 行 → ~5 行，token 节约 85%+
- [ ] **P0-3 大纲长度自动验证+重试**
  - 来源: show-me-the-story `outline.go:validateOutlineChapterLengths` + `outlineGenMaxAttempts`
  - 做法: 大纲引擎 Phase 2 生成后验证 stage 覆盖度，不足则追加 `formatShortOutlineRetryFeedback` 重试
  - 效果: 消除 AI 偷懒写 50 字大纲的问题
- [ ] **P0-4 段落级原文引用注入**
  - 来源: show-me-the-story `inject.go:extractSnippet`
  - 做法: 叙事记忆存储时记录 paragraph position，注入 prompt 时连带原文 snippet
  - 效果: AI 看到的不只是"王峰有一枚玉佩"，而是原文「王峰从怀中掏出一枚刻着龙纹的玉佩」
- [ ] **P0-5 自适应 context budget 估算**
  - 来源: show-me-the-story `postprocess.go:buildPostProcessBundle`
  - 做法: LLM 调用前计算 `fixedCost + contentCost < usableBudget * 0.65`，超限自动切换摘要模式
  - 效果: 长书不会 context overflow
- [ ] **P0-6 段落边界尾提取**
  - 来源: show-me-the-story `inject.go:tailAtParagraph`
  - 做法: 取上章结尾按 `\n\n` 分割取最后一个完整段落，替换现在的字符截断
- [ ] **P0-7 Config Snapshot**
  - 来源: show-me-the-story `outline.go:StoryConfigSnapshot`
  - 做法: 大纲生成时保存配置快照到 `books/{id}/config_snapshot.json`

## 九、技术决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 语言 | Python | 熟练、生态成熟、LLM 集成方便 |
| LLM | DeepSeek API | 低成本 + 中文能力强 |
| 后端 | FastAPI (58080) | 灵活、异步支持、与 Flask 共享端口 |
| 管理面板 | Flask + Jinja2 | 灵活度最高，15 模板稳定运行 |
| 存储 | JSON 文件系统 | 初期不需要数据库，后期可迁移 |
| 外部采集 | SSR + PUA 解码 | 番茄搜索 API 全部失效，只能走前端渲染 |
| 运行环境 | Windows | 番茄爬虫依赖 Windows（WSL2 无法连番茄） |
| 任务管理 | threading + Event | 轻量、协作式取消 |
| 匹配策略 | 纯规则（BookAssembler） | 无额外 LLM 调用，低延迟 |
