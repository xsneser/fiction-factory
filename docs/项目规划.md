# NovelEngine — AI 小说创作系统

> 创建日期：2026-07-26
> 技术栈：Python · Windows · Markdown · DeepSeek API · Web UI

---

## 一、项目定位

自用 AI 小说创作工具。核心能力：

1. **多库驱动** — 桥段库、大纲库、笑点库、内涵库，用模板+变量填充的方式生成内容
2. **仿写引擎** — 不是"AI 自由发挥"，是在结构化框架中有控制地生成
3. **多书管理** — 同时管理多本小说的进度、大纲、章节生成
4. **矩阵发布** — 多个账号、多本书、每日定时更新（后期功能）

不是 MOSS 项目的子模块，是完全独立的项目。

## 二、四大核心库

### 2.1 桥段库（Plot Device Library）

经典网文桥段的结构化模板。

```json
{
  "id": "plot_001",
  "name": "退婚打脸",
  "category": "爽文/身份反转",
  "template": "[甩婚书]→[众人嘲讽]→[主角展现实力]→[反转打脸]→[后悔莫及]",
  "slots": {
    "主角身份": "废柴/扮猪吃老虎",
    "对手身份": "世家少爷/宗门天才",
    "场合": "家族大会/宗门大典/婚礼现场",
    "关键道具": "隐藏实力的法宝/血脉觉醒"
  },
  "variants": ["严肃版", "幽默反转版", "草蛇灰线版"],
  "source": "创作积累"
}
```

### 2.2 大纲库（Structure Library）

各类网文的骨架结构。

| 流派 | 典型结构 |
|------|---------|
| 玄幻升级流 | 入门 → 打怪升级 → 遇敌 → 突破 → 换地图 |
| 都市爽文 | 落魄 → 金手指 → 逆袭 → 打脸 → 更大舞台 |
| 悬疑推理 | 事件 → 线索收集 → 误导 → 反转 → 真相 |
| 日常甜文 | 相遇 → 相处 → 误会 → 和解 → 升温 |
| 重生/穿越 | 前世 → 重生 → 先知优势 → 改变命运 |

### 2.3 笑点/金句库（Gag Library）

```json
{
  "id": "gag_001",
  "pattern": "预期违背",
  "template": "他本以为是[常见结果]，没想到[反转结果]",
  "examples": [
    "他本以为是来当炮灰的，没想到是来当祖宗的",
    "他本以为是来收徒弟的，没想到是来当孙子的"
  ],
  "fit_scenes": ["战斗后放松", "日常对话", "内心独白"]
}
```

### 2.4 内涵/意义库（Theme Library）

故事背后的核心讨论。

```
母题: 公平 / 代价 / 自由意志 / 牺牲 / 成长
表达手法:
  - 角色行动展示（不说教）
  - 对话间接暗示
  - 环境/象征物呼应
适用桥段: 对应桥段ID列表
```

## 三、仿写引擎工作流

```
用户输入: {桥段模板ID + 变量值设定}
  ↓
步骤1: 草稿生成（DeepSeek API, temp=0.3）
  → 根据模板和变量填充，生成基础段落
  ↓
步骤2: 仿写改写（DeepSeek API, temp=0.5）
  → 保留结构骨架，替换/丰富描述性语言
  ↓
步骤3: 风格统一（DeepSeek API, temp=0.2）
  → 把语言风格拧成一致（用预设风格参考）
  ↓
步骤4: 内容审查（本地规则 + LLM 二次确认）
  ↓
步骤5: 人工确认/修改
  ↓
输出: 可用章节段落
```

每次生成不以"写出一章"为目标，而是**按模板生成一段，人工组合编排**。

## 四、多书管理

```python
books/
└── {book_id}/
    ├── config.json      # 书名、作者、风格、流派、角色设定
    ├── outline.md        # 全书大纲（Markdown）
    ├── timeline.md       # 时间线 / 剧情路线图
    ├── characters.md     # 角色设定表
    ├── chapters/         # 已完成的章节
    │   ├── 001_第一章.md
    │   └── ...
    ├── state.json        # 当前进度（写到了哪、下一段用哪个模板）
    └── queue/            # 待发布的章节队列
```

### 前端选项

| 方案 | 优点 | 缺点 |
|------|------|------|
| **PyWebIO** | 纯 Python, 轻量, 零前端依赖 | 交互有限 |
| **Streamlit** | 社区成熟, 组件多 | 重, 启动慢 |
| **Gradio** | 适合 AI 演示 | 定制性差 |
| **Flask + Jinja** | 灵活度最高 | 需要写 HTML/CSS |
| **Flet** | Python 写 GUI, 可生成 Web/桌面 | 还在发展 |

**推荐**: 先 PyWebIO 或 Streamlit 起步，后期重写为 Flet 或 Flask。

## 六、矩阵发布层（后期）

```
scheduler/
├── accounts.json     # 各平台账号配置
├── publisher.py      # 发布接口（各平台适配器）
└── cron_job.py       # 定时任务脚本

定时逻辑:
  每天指定时间 → 遍历所有书的 queue/
  → 取出待发布的章节
  → 通过对应账号发布到对应平台
  → 记录发布状态
```

账号管理数据结构：
```json
{
  "accounts": [
    {
      "id": "acc_001",
      "platform": "qidian",
      "cookies": "...",
      "books": ["book_001", "book_002"],
      "schedule": "08:00, 18:00"
    }
  ]
}
```

## 八、技术决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 语言 | Python | 熟练、生态成熟、LLM 集成方便 |
| LLM | DeepSeek API | 低成本 + 中文能力强 |
| UI框架 | 待定（先 PyWebIO 起步） | 快速出原型 |
| 存储 | 文件系统(Markdown/JSON) | 初期不需要数据库，后期可迁移 |
| 发布 | 手动粘贴 → 后期自动化 | 先验证内容质量 |
| 运行环境 | Windows | 开发者日常使用环境 |
