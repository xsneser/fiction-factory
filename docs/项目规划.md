# NovelEngine — AI 小说工厂

> 创建日期：2026-07-26 | 最后更新：2026-07-31（v0.5）
> 技术栈：Python · DeepSeek API · FastAPI · Flask · Jinja2 · JSON 文件系统

---

## 一、项目定位（v0.5）

**全自动网文量产系统**：AI 拟人写作 × 节拍级生成 × 外部采集 + 分析入库。

### 核心理念

每个笔名 = 一个独立的 AI 作家，拥有独立的记忆、风格、桥段库和创作习惯。不是"一个生成器生成多本书"，而是"一群 AI 作家同时开工"。

### 不是

- 不是 MOSS 项目的子模块（完全独立）
- 不是"按模板生成一段，人工编排"的半自动工具（已全自动）
- 不是简单 prompt 拼接（有完整架构层）

## 三、引擎流程

### 3.1 新书启动

```
规划（大纲+角色+伏笔+书名方案）
  → CH1（钩子 + 金手指 + 首次危机）
  → CH2（世界观展开）
  → CH3（首次核心冲突）
  → 生成书名+简介
  → 自动转入续写模式
```

### 3.2 续写循环

```
写 → 审 → 去AI → 修正 → 继续写
```

每章拆 6-8 个**节拍**，用 14 种微模板逐节拍生成：

| 节拍类型 | 说明 |
|---------|------|
| 开篇 | 章首场景锚定 |
| 对话 | 对话推进剧情 |
| 动作 | 动作描写 |
| 内心独白 | 角色内心活动 |
| 环境描写 | 场景氛围 |
| 战斗 | 打斗场景 |
| 冲突 | 冲突升级 |
| 反转 | 剧情反转 |
| 情感爆发 | 情绪高点 |
| 日常过渡 | 舒缓段落 |
| 信息揭露 | 关键信息揭示 |
| 悬念收尾 | 章末悬念 |
| 高潮 | 剧情高潮 |
| 余韵 | 事后的情绪沉淀 |

### 3.3 BookAssembler（昨日新增）

连接四大库与生成管线的关键模块。核心工作流：

```
选定大纲 → 逐阶段匹配桥段 → 逐桥段匹配笑点
→ 选定全书母题 → 生成 Plan → 注入写作 prompt
```

LLM 在写作 prompt 中看到：
- 当前阶段要用的桥段模板 + 变量填充建议
- 该桥段匹配到的 1-3 个笑点模式
- 全书的母题 + 阶段级内涵提示

匹配策略：纯规则（关键词 + 分类 + 评分），无额外 LLM 调用。

### 前端技术选择（最终决策）

| 选择 | 说明 |

## 五、番茄侦察兵（`plugins/fanqie_scout.py`）

| 功能 | 方式 | 说明 |
|------|------|------|
| **搜索** | Bing 搜索 → SSR 页面解析 | 番茄搜索 API 全部失效（`code:-2`） |
| **下载** | Reader 页面 SSR → PUA 字体解码 | 使用 fonttools + 内置 362 映射表 |
| **分析** | 4 次 LLM 调用 | 桥段/大纲/笑点/内涵自动入库 |

### PUA 解码关键发现
- 章节数据在 `page.chapterListWithVolume`（二维列表）
- 正文在 `reader.chapterData.content`（PUA 编码）
- Reader URL：`/reader/{chapter_id}`（不带 book_id）
- 字体从 `@font-face` CSS 提取
- 每本书字体不同，映射表不通用

## 六、任务管理系统（`plugins/task_manager.py`，7/30 新增 ✅）

所有耗时后端操作统一注册管理。

### 状态机

```
start → running → cancel → cancelled
                → done / failed
```

### 核心原则
1. 任务卡片和日志各自独立更新
2. 关闭 = 取消（运行中 kill 线程，已完成移除卡片）
3. 所有耗时操作必须注册任务

文档详见 `docs/task-system-spec.md` v1.1

## 七、笔名档案（`libraries/profile.py`）

每个笔名拥有独立的风格指纹。

```python
{
    "pen_name": "枫落",
    "word_print": {
        "common_words": ["卧槽", "淦", "牛逼"],   # 常用词
        "avoid_words": ["仿佛", "似乎", "不禁"],  # 禁用词
        "dialogue_tags": ["说", "道", "笑了"],
        "action_beats": ["眯眼", "挑眉", "咂嘴"],
    },
    "style_fingerprint": {
        "sentence_length": "short",
        "humor_style": "吐槽型",
        "action_style": "简洁利落",
    },
}
```

预设笔名：**枫落**（都市爽文）、**夜雨**（玄幻正剧）、**青衫**（言情甜文）

## 九、技术决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 语言 | Python | 熟练、生态成熟、LLM 集成方便 |
| LLM | DeepSeek API | 低成本 + 中文能力强 |
| 后端 | FastAPI (58080) | 灵活、异步支持、与 Flask 共享端口 |
| 管理面板 | Flask + Jinja2 | 灵活度最高，15 模板稳定运行 |
| 存储 | JSON 文件系统 | 初期不需要数据库，后期可迁移 |
| 外部采集 | SSR + PUA 解码 | 番茄搜索 API 全部失效，只能走前端渲染 |
| 运行环境 | Windows | 番茄爬虫依赖 Windows（WSL2 无法连番茄） |
| 任务管理 | threading + Event | 轻量、协作式取消 |
| 匹配策略 | 纯规则（BookAssembler） | 无额外 LLM 调用，低延迟 |
