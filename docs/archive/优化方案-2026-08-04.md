## 1. 旧引擎残留代码（建议收敛/下线）

### 1.1 engine.py 旧状态机路由（残留最重）
- 位置：`libraries/engine.py`
- 现状：`Op`/`Phase`/`Instruction`/`route()`/`_route_continue()`/`execute()` 处理器表 + `_exec_review_current`/`_exec_de_ai_current`/`_exec_confirm_current`/`_exec_plan_outline` + `step()`/`run()`/`run_full_cycle()`。
- 事实：
  - UI 真实只走两个入口 —— `execute(Instruction(Op.WRITE_TIMELINE_CHAPTER))`（`ui/web_ui.py:950`）和 SSE 流式端点（`_write_timeline_chapter_stream` / `_write_next_bridge_stream`）。
  - **`route()` 不是死代码**：`test_all.py:359-385` Phase 9 直接调用 5 次并断言 `PLAN_OUTLINE / REVIEW_CHAPTER / DE_AI_PASS / WRITE_CHAPTER / COMPLETE`。删除会破坏 75/75 基线。
  - `step()`/`run()`/`run_full_cycle()` 全仓库零调用（含测试），是纯包装器。
  - `_exec_plan_outline`/`_exec_review_current`/`_exec_de_ai_current`/`_exec_confirm_current` 仅在 handler 表被引用，对应 Op 只由测试可达的 `route()` 产出；生产 `execute()` 只以 `WRITE_TIMELINE_CHAPTER` 调用，这 4 个处理器生产环境不可达。
  - `_get_stage_index` 零调用。
- 动作（与 75/75 基线兼容）：
  - 保留 `route()`/`_route_continue()`/`execute()`/`Op`/`Phase`（Phase 9 依赖）。
  - 删除 `step()`/`run()`/`run_full_cycle()`。
  - 删除上述 4 个 `_exec_*` 死处理器及 handler 表中对应 4 个条目（`PLAN_OUTLINE/REVIEW_CHAPTER/DE_AI_PASS/CONFIRM_CHAPTER`）；删后 `route()` 仍返回这些 Op，但生产无人调用 `execute()` 执行它们，测试也只断言 `route()` 返回值，不执行 —— 75/75 保持绿。
  - 保留 `_exec_write_chapter`/`_exec_complete`/`_exec_pause` 及 handler 表条目（保持 `execute()` 对 `WRITE_CHAPTER/COMPLETE/PAUSE` 的完整性；其中 `_exec_write_chapter` 是 `_exec_write_timeline_chapter` 的委托壳）。
  - 删除 `_get_stage_index`。
  - 若未来想连 `route()` 一起下线，须同步改写 Phase 9（列为 P2 决策项，推荐暂不删）。

### 1.2 timeline.py TimelineBuilder（与新管线功能重叠）
- 位置：`libraries/timeline.py:216-447`（`TimelineBuilder` 及 `_rule_build_sequence`/`_ai_build_sequence`/`fill_plots_for_outline`/`fill_themes_and_hooks`）
- 现状：被 `ui/web_ui.py` 的编辑/扩展端点使用（`extend-outline`、`generate-outlines`、`fill-plots`、`fill-gags`，web_ui.py:187/307/416/456/487），与新的 `OutlineGenerator`（`libraries/outline_generator.py`，6 阶段 LLM 管线，web_ui.py:727 使用）功能重叠，属"第二套生成实现"，质量低于新管线。

### 1.3 assembler.py（只服务旧路径）

## 4. 代码质量问题（低成本修复）

1. **人为瑕疵注入会引入真实错别字/性别错误**：`de_ai.py:add_human_imperfections` 随机替换 `他→她`、`在→再`、`的→地` 等；函数签名默认 `typo_rate=0.001`（行 75），调用点传 `0.0005`（行 161）。与新增的"角色性别纪律"直接冲突，长书必然产生"她"字错乱。→ 默认 `typo_rate=0`，或只保留无语义风险的字符级抖动开关。
2. **engine 路径未锚定项目根**：`engine.py` 大量 `Path("books")/...`（行 334/342/358/1048/1063）依赖 CWD，而 `BookManager` 已锚定 `__file__` 根（`book_manager.py:57-62`）。从其他 CWD 启动（如 launch 脚本）会写错目录。→ 统一走 `self.book_mgr.dir` / 项目根常量。
3. **成本统计偏低**：`engine.py:868` `cost_tracker.record(f"ch{n}_timeline", "", full_text)` 输入传空串 → 输入 token 不计费，长书预算失真。→ 传入实际 prompt 文本（或至少估算值）。
4. **日志不统一**：`engine.py:267` 用 `print()` 而非 logger；`web_ui.py:25-33` 只给 `"fanqie-scout"`/`"__main__"` 两个 logger 配了 handler，其余 `novel-engine.*` 无输出。→ 统一 logging 配置。
5. **AI 词表两份维护**：`de_ai.py:11 AI_WORD_MAP` 与 `reviewer.py:51 ai_tells`/`_get_replacements` 内容重叠（仿佛/似乎/不禁/只见/但见/不由得…）会漂移。→ 单一来源（de_ai 导出，reviewer 引用）。
6. **中文字数统计两套**：`reviewer.py:39,60` 自写 `[\u4e00-\u9fff]` 正则，`core/text_utils.py:count_prose_units` 另一套。→ 统一到 `count_prose_units`。
7. **`timeline_writer._group_prompt` 内联回退模板**（行 189 起）与 `prompt_harness.render_bridge_prompt` 双份渲染：回退版仅无 harness 时用（docstring 自述"便于单测"），易漂移。→ 收敛为 harness 单实现 + 极简兜底。
