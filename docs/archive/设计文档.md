## 1. 项目定位与核心理念

**全自动网文量产系统**：AI 拟人写作 × 桥段驱动生成 × 番茄侦察兵采集入库。

- 每个笔名 = 一个独立的 AI 作家，拥有独立的记忆、风格、桥段库和创作习惯——不是"一个生成器生成多本书"，而是"一群 AI 作家同时开工"。
- 不是 MOSS 项目的子模块；不是"按模板生成一段、人工编排"的半自动工具；不是简单 prompt 拼接（有完整架构层）。

### 1.1 核心设计决策（harness 三决策，2026-08-03）

| 项 | 决策 | 落地 |
|---|---|---|
| **笑点** | 完全涌现，大纲不参与 | 删除大纲 Phase 4 固定笑点分配（`gag_ids` 保留字段但不再写入）；写作时每写完一组短句由探测器判断是否注入（§5.3） |
| **内涵** | 跟随桥段 | 用 `THEME_PLOT_COMPAT` 免费规则把母题挂到能承载它的桥段，不硬挂（§3.6） |
| **长程记忆** | LLM 语义摘要 | 每章写完生成 80-150 字客观摘要存 `summary` 字段，写作时注入最近 5 章（§5.4） |
| **架构** | 集中式 harness | `prompt_harness.py` 统一产出书级设定卡与全部 prompt（§7） |

### 1.2 硬约束（用户反复强调，任何改动不得违反）

1. **保持 `deepseek-v4-flash` 模型**，不换模型。
2. **只优化 prompt / 生成参数 / 免费规则层**；不加"写完质量重写"型 LLM 后处理（探测器/摘要属于生成过程的一部分，不算后处理）。
3. 探测器/摘要调用小而轻：**输入 ≤500 token、输出 ≤256**。

### 1.3 引擎核心流程

```
新书：设定(世界观) → 规划(故事线) → 大纲(6阶段) → 写作(桥段驱动) → 书名/简介
续写：写 → 审(软门禁) → 去AI → 摘要 → 台账 → 继续写
```

所有写作（含新书启动）走**同一条桥段管线**；开场只是它的一种模式（§5.2）。

## 3. 核心资产库

统一基类 `JsonLibrary`（`base_library.py`）：进程内单例 + JSON 读写；条目含 `enabled / usage_count / banned_in[book_id] / source / created_at`。**改 `libraries/data/*.json` 必须重启服务才生效。**

| 库 | 模块 | 数据文件 | 数量（08-05） | 用途 |
|---|---|---|---|---|
| 桥段库 | `plot.py` | `plots.json` | 47 模板（12 内置 + 采集） | 桥段模板：category / template_structure / slots / fit_contexts；写作时作【桥段骨架】注入 |
| 大纲库 | `structure.py` | `structures.json` | 11 模板（5 内置 + 采集） | 卷→弧→章三级骨架，按流派搜索 |
| 笑点库 | `gag.py` | `gags.json` | 24 模式（10 内置 + 采集） | 探测器候选池（不写进大纲） |
| 摘录库 | `example_lib.py` | `excerpts.json` | 16 条演示（7 类型） | 真实原文范本，写前按 category 预筛 2 条注入【写法范本】 |
| 内涵库 | ~~theme.py~~（已删） | `themes.json` | 20 母题 | 书级母题库 + `THEME_PLOT_COMPAT` 免费规则挂载 |

### 3.1 桥段库（plot）

47 模板 × 7 分类（爽文/开篇/战斗/成长/冲突/情感/修罗场）。字段示例：

```json
{
  "id": "plot_001", "name": "退婚打脸", "category": "爽文",
  "template_structure": ["甩婚书","众人嘲讽","展现实力","反转打脸","后悔莫及"],
  "slots": [{"name":"主角身份","default":"废柴/扮猪吃老虎","options":["废柴","隐世高手"]}],
  "fit_contexts": ["开篇展示","身份揭示","多人场景"], "source": "创作积累 / 番茄分析"
}
```

### 3.2 大纲库（structure）

11 模板 × 5 流派（玄幻升级流/都市爽文/悬疑推理/日常甜文/重生穿越），每模板 5 阶段（含 `min_ch/max_ch/events`），支撑卷→弧→章三级骨架。

### 3.3 笑点库（gag）

24 模式 × 8 分类（吐槽/误会/打脸/反差/卖萌/装逼/自黑/神逻辑/冷幽默/谐音梗）。写作时按桥段 category → 场景关键词预筛候选池（≤6 条），探测命中才注入（§5.3）。

### 3.4 摘录库（example_lib）

7 类型：开头钩子/主角亮相/高张力对白/打脸爽点/章末钩子/结尾余韵/日常对话。每条限 2-3 句 ≤100 字，合规口径与 README 一致（抽象技巧为主，不传播不转载）。写前按 `CATEGORY_EXCERPT_TYPES` 预筛 2 条注入【写法范本】块（只借鉴节奏/画面/语气，严禁照抄）。

### 3.5 笔名档案（profiles.py）

```python
{
  "pen_name": "枫落",
  "word_print": {"common_words": [...], "avoid_words": [...], "dialogue_tags": [...], "action_beats": [...]},
  "style_fingerprint": {"sentence_length": "short", "humor_style": "吐槽型", "action_style": "简洁利落",
                        "pov_preference": ""},
}
```

预设笔名：**枫落**（都市爽文）、**夜雨**（玄幻正剧）、**青衫**（言情甜文）；`profiles/` 现存 profile_001~005。风格以 bullet 注入书级设定卡；幽默风格喂给探测器（喜剧声线）。

### 3.6 内涵体系的演进（theme → 免费规则）

- `theme.py` 模块已删除；`themes.json` 仍作为书级母题库（20 条）。
- 大纲 Phase 4 不再做固定笑点分配；母题挂载改为：`THEME_PLOT_COMPAT`（`storyline.py:255`，桥段模板 id → 可承载母题名）命中才挂，未命中母题仍随书级设定卡注入作为可用线索。
- 笑点 `gag_ids` 字段保留兼容旧数据，但**不再写入**。

## 4. 新书创建流程（端到端调用链）

### 4.1 流程总览

```
┌─ 阶段 A：规划（产出 storyline.json）──────────────────────────────┐
│ 1. GET /books/start            dashboard.start_new_book          │
│    → 建正式书 books/<id>/ + BookStoryline(phase=config)           │
│ 2. 设定先行：GET /books/<id>/world + /api/world-builder/*         │
│    → WorldBuildingGenerator（可选：一句话/示例/借鉴）填充设定圣经    │
│ 3. GET /storyline/<id>/edit    storyline.storyline_edit           │
│    POST /api/storyline/<id>/save-basic-info （基础设定手填）       │
│ 4. POST /api/storyline/<id>/generate-full → OutlineGenerator      │
│    （6 阶段 SSE，每阶段结束落盘）                                   │
│ 5. 可选：/api/storyline/<id>/agent（OutlineAgent）/extend-outline  │
│    /generate-title /generate-outlines /fill-plots /fill-gags      │
└──────────────────────────────────────────────────────────────────┘
┌─ 阶段 B：写作（写作台，桥段驱动）───────────────────────────────────┐
│ 6. GET /books/<id>/continue    desk 写作台（三栏）                 │
│    → NovelEngine.continue_book / start_new_book_timeline          │
│ 7. POST /api/storyline-engine/<id>/write-bridge（SSE，核心按桥段写）│
│    → _write_next_bridge_stream → StorylineChapterWriter           │
│ 8. POST /api/storyline-engine/<id>/write-chapter（SSE，整章兼容）   │
│ 9. 每章写完 → _finalize_written_chapter：                          │
│    · 规则降重（de_ai）· reviewer 软门禁 · 语义摘要 · 承诺台账登记    │
│ 10. 第 1 章写完可生成书名/简介（详情页按钮，非自动）                 │
└──────────────────────────────────────────────────────────────────┘
```

### 4.3 世界观生成器（world_builder）

三种启动方式：① 一句话自由输入（Call A 流式叙事化短文 temp≈0.8 → Call B 结构化 JSON temp≈0.5、失败重试 ≤3）；② 示例候选点选回填；③ 从已有书借鉴（extract_seed）。落盘语义：`merge_basic_info` 保留用户已填非空字段，末尾打 `_world_generated` 标记。产出「设定圣经」维度：description/era/power_system/factions/rules/geography/culture/history/social_structure/core_conflict/world_summary（§10.1 DEFAULT_WORLD_BUILDING）。

## 5. 写作引擎（唯一写作核心）

### 5.1 桥段驱动逐短句组

`StorylineChapterWriter._write_plot_segment_groups`：每个桥段内逐「短句组」调用 LLM（每次 3-5 短句约 150-250 字，temp 0.7，max_tokens 1600），组与组之间空行分隔成独立段落；每次调用携带「本章已写全部前文 + 上一章结尾[-150] + 本桥段已写[-300] + 角色状态」。桥段按**叙事线程轮流排列**（`_threaded_ordered_plots`：主线加权 2:1，副线/伏笔线各 1；全主线时退化为严格顺序）。写完累计字数，满 `words_per_chapter` 切章；每桥段写完立即写 `written_chapter`（断点续写）。

**质量重试通道**（复用同一 `WRITER_EMPTY_RETRIES=2` 通道）：
- 空响应重试（flash 推理吃光 max_tokens 的静默空返回）
- 连续重复词重试（`has_repeated_token`，笑声/拟声叠词白名单放行）
- 疑似错词重写（`_typo_issue`，`_TYPO_PATTERNS` 现 1 条：「先轻轻」→「先缓一缓」）
- 0 字桥段保护：不置 written_chapter、yield `bridge_skip`、下章重试

### 5.2 炸裂开场

第 1 章前 800 字且前 3 桥段命中 `opening_mode_active` → 注入 `OPENING_MODE_RULES`（冷开场三句入冲突 / 前 200 字钩子 / 前 500 字危机 / 冲突线前置）。

### 5.3 笑点探测器环（灵机一动涌现）

```
prescreen_pool(plot, book_id) → harness.prescreen_gag_pool（免费规则 ≤6 条：
  category → fit_scene 关键词 → search 去重 → 过滤 enabled/banned_in → usage_count 升序）
detect(item, recent_text, humor_style, pool) → temp 0.3, max_tokens 400
  → 解析失败/缺字段/越权模式(gag_ids⊄池) 一律未命中（静默，绝不打断写作）
命中 → build_inspiration_hint → 【灵机一动】注入下一组 prompt，用完即清
```

集成点：`_write_plot_segment_groups` 每写完一组、预算未用尽（remaining>100）、按 `detector_frequency`（BookConfig 字段，默认 1）时运行；命中时 yield `gag_hit` SSE 事件。**设计纪律：宁缺毋滥**——`has_opportunity=false` 不注入任何东西；deploy_hint 空或 >60 字丢弃；不改"一句收进场景、不解释、不标注笑点"的落点纪律。

### 5.4 语义摘要（L1 长程记忆）

每章固化时 `_summarize_chapter`（temp 0.3, max_tokens 1024）：输入本章尾部 600 字 + 本桥段名 → 输出 80-150 字客观摘要（发生了什么/主角状态/埋的钩子）→ 存 `chapters/{NNNN}.json.summary`。写作前 `load_chapter_summaries` 注入最近 5 章（≤600 字）作为【已完成章节语义摘要】。

### 5.5 叙事多线程 + 设局→收局

- `PlotSlot.thread_id/thread_seq`：大纲 Phase 4 由 LLM 规划线程归属（主线/副线/伏笔线，第 1 章附近多线并进）；兜底 `_apply_thread_fallback` 按分类归线。
- 设局→收局拆分：选中适合的桥段（阴谋/悬疑/智斗/成长转折）生成收局槽位（`resolves_plot_id/resolves_name`，payoff_after_stage≥2），纯即时爽点不拆。
- 写作注入：收局桥段带【本桥段收束】解决『X』埋的钩子；设局桥段带【设局桥段】为『Y』埋钩子，结尾留明确未解决悬念。

### 5.6 读者承诺台账

`BookStoryline.promises[]`（`{id, setup_plot_id, type, desc, status: pending|advanced|fulfilled, setup_chapter, deadline_chapter, payoff_plot_id, payoff_chapter}`）。免费规则登记：设局桥段写完 → pending；收局桥段写完 → fulfilled；阶段推进 → advanced（`engine._update_promises_ledger`）。写作注入【读者承诺台账】块：本桥段要兑现的 / 已逾期的 / 活跃可推进的（`prompt_harness._promises_block`，按当前章节号对比 deadline）。

### 5.7 叙事纪律（写前 prompt 层）

| 纪律 | 机制 | 位置 |
|---|---|---|
| 视角人称 | `basic_info.pov` 显式字段（Phase 1 生成），bible + 每桥段【视角铁律】 | prompt_harness |
| 角色性别/称呼 | 配角 `gender/title` + 出场人物块【本桥段出场人物】 | prompt_harness `_roles_block` |
| 时代语言 | bible 自动生成"禁止晚于时代新词"（era 年份 ≤2015 兜底） | `_era_language_bullets` |
| 时间线校验 | Phase 1 后 `_validate_storyline_math`（重生死亡年份<故事年份、年龄/年份自洽），独立 `timeline_warnings` | outline_generator |
| 重复词 | `has_repeated_token` 检测，该组仅重试一次 | storyline_writer |
| 疑似错词 | `_typo_issue` 规则检测，命中重写一档 | storyline_writer |

### 5.8 写前注入块（免费规则 + 轻量 LLM）

`render_bridge_prompt` 按需注入：书级设定卡（简）→ 开场铁律 → 全书一致性铁律 → 视角铁律 → 所属大纲/当前阶段/事件 → 【桥段骨架】+ 槽位 → 出场人物 → 母题 → 收局/设局 → 灵机一动 → 【本桥段吸睛点】（hook_points）→【写法范本】（example_lib 2 条）→【写前编辑诊断】（读者欲望/最强爽点/敌人损失/追更理由，`_pre_write_diagnosis`）→【读者承诺台账】→ 已完成章节摘要 → 前文上下文 → 平台约束 → 上章审查提示 → 写作要求 7 条。

### 5.9 章节收尾（`_finalize_written_chapter`）

顺序：DeAI 规则降重（`process_rule_based`，AI_WORD_MAP 替换）→ 状态更新 → 语义摘要 → **reviewer 章节软门禁**（字数/AI词/段落节奏/对话比/章末钩子，fail 不阻断，只把修复提示注入下一桥段【上章审查提示】一次性用完）→ 承诺台账登记 → 落盘章节（含 review）→ 成本记录。

### 5.10 预算门控

`cost_tracker` 预算（BookConfig.budget 默认 50 元）：桥段端点预算耗尽 → `bridge_skip` + `budget_paused` 事件，**保留草稿不固化**；整章端点同样存草稿不固化。前端 `timeline_write_flow.html` 有 `budget_paused`（warn）与 `bridge_skip`（info）分支。

## 6. 大纲生成引擎（OutlineGenerator，6 阶段）

> 一锤子 6 阶段 LLM 管线（SSE 流式）；每阶段结束落盘 `storyline.json`；任意阶段失败/无 LLM → 规则兜底。

| 阶段 | 方法 | LLM | 产出 |
|---|---|---|---|
| Phase 1 故事分析 | `_analyze_story` | temp 0.7, max_tokens 2048（非流式） | protagonist/world_building(含 rules 数值写死)/supporting_cast/tone/target_audience/pov/era_language；解析失败 → `_default_basic_info`；后接 `_validate_storyline_math` |
| Phase 2 故事线规划 | `_ai_sequence` | 流式, 0.7, 8192 | 选 2-max_outlines 个模板排时间线（可 overlap 2-5 章）；兜底 `_rule_sequence` |
| Phase 3 桥段选择 | `_ai_select_plots` | 流式, 0.5, 8192 | 每阶段 1-3 个（候选 ≤12，避免重复/乱入）；兜底 `candidates[:2]`；cover_beats=word_range//400，slots 展开，链式嵌套 |
| Phase 4 线程与呼应 | `_plan_threads_and_splits` | 非流式, 0.3, **16384**（空返回重试 3） | threads[]/assignments[]/splits[]（设局→收局）；兜底按分类归线 |
| Phase 4.5 内涵复查 | `_review_theme_assignments` | 流式, 0.3, 8192 | 复查母题挂载（只接受书级母题库内名字，每桥段 ≤2） |
| Phase 5/6 一致性验证 | `_validate`（规则）+ `_validate_with_llm`（流式, 0.3, 8192） | 规则先行 + LLM 抽查 | issues/warnings 事件（⚠️ 无自动重试，见 §14 路线图） |

**质量校验项**（`_validate`）：章节连续性、重叠区 ≤5 章、桥段覆盖（阶段数 vs 桥段数）、内涵覆盖率 ≥30%（建议性）、总章节 10-500。

**兼容路径**：`StorylineBuilder`（storyline.py）的规则/AI 模式仍被 `/extend-outline`、`/generate-outlines`、`/fill-plots`、`/fill-gags` 等编辑端点使用；已与 OutlineGenerator 抽公共函数（`structure_to_stages` / `mount_themes_and_hooks`）消除漂移，全量迁移留作后续评估。

**OutlineAgent**（Prompt L）：解析用户口语指令（intent: modify_plot/add_gag/remove_gag/add_plot/remove_plot/modify_outline/general），temp 0.2, max_tokens 2048；解析失败 → general + 帮助文本。

## 7. Prompt 系统（PromptHarness）

### 7.1 书级设定卡（Book Bible）分段

`_protagonist_bullets` / `_world_bullets` / `_style_bullets`（笔名档案，支持对象与 dict 两种形态）/ `_pov_bullets` / `_era_language_bullets` / `_rebirth_time_bullets` / `_supporting_cast_bullets` / `_theme_bullets` / `_tone_bullets`。优先级截断：`build_book_bible(max_chars=1200)` 全量（大纲 Phase 2/5 用）；`build_book_bible_condensed(max_chars=600)` 精简版（写作/探测器/Phase 3 用，目标 ~440 字）。

### 7.2 渲染器（6 个出口）

| 方法 | 场景 |
|---|---|
| `build_book_bible` / `build_book_bible_condensed` | 设定卡全量/精简 |
| `render_bridge_prompt(...)` | 桥段写作（Prompt I，user prompt 字符串） |
| `render_detector_prompt(...)` | 笑点探测器（Prompt J，system+user） |
| `render_summary_prompt(...)` | 章节语义摘要（Prompt K） |
| `render_outline_context(phase_kind, tl)` | 大纲各 phase 前置设定卡（sequence/select_plots/validate/theme_review/thread_split） |
| `prescreen_gag_pool(plot, book_id)` / `prescreen_excerpts(plot, book_id, limit)` | 候选池免费规则预筛 |
| `render_world_build_draft_prompt` / `render_world_build_struct_prompt` / `render_world_candidates_prompt` | 世界观生成（world_builder） |

### 7.3 两条全书铁律（模块级常量）

- `OPENING_MODE_RULES` — 炸裂开场：冷开场三句入冲突、前 200 字钩子、前 500 字危机、冲突线前置。
- `CONSISTENCY_RULES` — 全书一致性：系统绑定全书只一次、数值必须闭环、对话时间线不穿帮、跨天要有时间过渡。
- `WORLD_BUILD_SYSTEM` / `WORLD_BUILD_STRUCT_SYSTEM` / `WORLD_CANDIDATES_SYSTEM` / `WORLD_BUILDING_SCHEMA_HINT` — 世界观生成 system。

### 7.4 LLM 提示词清单（A–L）

| 编号 | 名称 | 调用点 | 输入 | max_tokens | temp | 频率 |
|---|---|---|---|---|---|---|
| A | 故事分析 | outline_generator `_analyze_story` | 流派/子流派 + 笔名风格 + 用户想法 | 2048 | 0.7 | 每新书 1 次 |
| B | 故事线规划 | `_ai_sequence`（`render_outline_context("sequence")` 前置） | 设定卡 ≤900 + 候选模板 ≤10 | 8192 | 0.7 | 每新书 1 次 |
| C | 桥段选择 | `_ai_select_plots`（"select_plots" 前置精简卡） | 设定卡精简 + 候选 ≤12 | 8192 | 0.5 | 每阶段 1 次 |
| D | 线程与呼应 | `_plan_threads_and_splits`（"thread_split" 前置） | 设定卡 + 大纲 + 桥段 ≤60 | **16384** | 0.3 | 每新书 1 次 |
| E | 内涵复查 | `_review_theme_assignments` | 桥段快照 ≤20 | 8192 | 0.3 | 每新书 1 次 |
| F | 一致性验证 | `_validate_with_llm` | 大纲视图 ≤10 | 8192 | 0.3 | 每新书 1 次 |
| G | 书名生成 | `timeline.generate_title` / `engine._generate_book_meta` | 流派/平台 + 第 1 章前 1000 字 | 1024 | 0.8 | 详情页手动触发 |
| H | 简介生成 | `engine._generate_book_meta` | 同 G | 1024 | 0.8 | 同上 |
| I | 桥段写作 | `StorylineChapterWriter._group_prompt` → `render_bridge_prompt` | 设定卡精简 + 计划 + 摘要 + 前文窗口 + 命中提示 | **1600** | 0.7 | 每短句组 |
| J | 笑点探测器 | `GagInjector.detect` → `render_detector_prompt` | ≤500 token（recent 450 字 + 池 4×60） | **400** | 0.3 | 每短句组（按频率） |
| K | 语义摘要 | `engine._summarize_chapter` → `render_summary_prompt` | ≤500 token（content 尾 600 字） | 1024 | 0.3 | 每章 1 次 |
| L | 大纲助手 | `OutlineAgent._parse` | 故事线上下文 + 用户指令 | 2048 | 0.2 | 用户触发 |

> **⚠️ 核心坑**：`deepseek-v4-flash` 先输出 `reasoning_content` 再输出 `content`，两者共享 `max_tokens`。max_tokens 过小（如 700）推理吃光预算 → content 为空（静默返回 ""）。实测同 prompt 700→0 字、1600→76 字。因此所有 max_tokens 都留足推理余量，写作路径对空响应重试 2 次（`WRITER_EMPTY_RETRIES`）。

## 8. 任务管理系统（task_manager）

> 所有耗时后端操作（抓取/提取/写作/入库）统一注册管理。文档源自 task-system-spec v1.1。

### 8.1 状态机

```
start → running → cancel → cancelled
                 → done / failed
```

### 8.2 核心 API（`plugins/task_manager.py`）

`start(task_id, name, title, total)` / `ensure_single(name)`（同工具互斥，新任务替代旧任务）/ `register_cancel` / `cancel` / `is_cancelled` / `progress` / `log` / `done` / `fail` / `get_tasks` / `clear_old(keep_seconds=60)` / `remove`。任务卡片与日志各自独立更新；每个任务最多保留 100 条日志。

### 8.3 端点（settings 蓝图）

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/status/tasks` | GET | 任务列表（前端 pollStatus 每 2s 轮询） |
| `/api/status/tasks/close` | POST | 关闭卡片（仅 UI 操作，不杀进程） |

### 8.4 前端规范

- 卡片：卡头（任务名 + ✕）、进度条（仅 running）、卡底（阶段 + 时间）；按开始时间新→旧排列。
- 日志：增量追加、按时间混合排列、颜色区分工具；刷新后日志丢失（未持久化）。
- 关闭 = 取消：运行中 kill 线程（worker 在检查点 `is_cancelled()` 优雅停止）；不支持取消的任务只移除卡片。

### 8.5 接入步骤

入口 `start()` → 循环 `progress()` + 关键节点 `log()` → 完成 `done()` / 异常 `fail()`；支持取消则在循环检查 `is_cancelled()`。

## 10. 数据模型与落盘

### 10.1 核心数据类（`storyline.py`）

- **BookStoryline**：`book_title/genre/sub_genre/words_per_chapter/pen_name/platform` + `basic_info`（protagonist/world_building/supporting_cast/tone/target_audience/pov/era_language）+ `outlines[]/plots[]/threads[]/promises[]/themes[]/global_gags[]` + `phase`（config|outlines|plots|gags|ready）+ `generated_at/updated_at`。
- **OutlineSlot**：`template_id/name/start_chapter/end_chapter/stages[]`（`{name,min_ch,max_ch,events}`）+ `transition_type`（sequential|overlap|merge）+ `narrative`（chronological|flashback|interleaved）+ `overlaps_with/predecessor/successor`。
- **PlotSlot**：`template_id/name/category/outline_id/stage_index/order` + `cover_beats/template_structure/slots[]` + `gag_ids（兼容保留）/theme_hints/hook_points` + `thread_id/thread_seq/resolves_plot_id/resolves_name` + `roles[]`（出场人物）+ `written_chapter`（断点续写）+ `parent_plot_id/children_plot_ids`（嵌套）。

### 10.2 文件布局

| 文件 | 内容 | 写入时机 |
|---|---|---|
| `books/<id>/book.json` | BookConfig：标题/笔名/流派/平台/预算(50)/detector_frequency/进度/状态 | create/update |
| `books/<id>/storyline.json` | 故事线配置（大纲+桥段+threads+themes+promises） | 每阶段结束 / 每桥段写完 |
| `books/<id>/outline/outline.json` | 结构大纲（含 synopsis） | 书名/简介生成后 |
| `books/<id>/chapters/{NNNN}.json` | 章节正文 + summary + review | 每章固化 |
| `books/<id>/draft_chapter.json` | 进行中章节草稿（预算暂停/中断恢复） | 每桥段写完未切章 |
| `books/<id>/character_states.json` | 角色状态机（last_appeared/offline/情绪/目标…） | 每章收尾 |
| `books/<id>/cost.json` | LLM 费用（输入+输出 token 计费） | 每次调用 |

### 10.3 世界设定圣经（DEFAULT_WORLD_BUILDING）

description（一句话种子，老字段）/ era / power_system / factions / rules（数值语义写死，全书唯一口径）/ geography / culture / history / social_structure / core_conflict / world_summary。

## 11. 质量体系与测试

### 11.1 规则审查（reviewer.py，软门禁）

检查项：字数（≥2000 下限）、AI 词（`AI_WORD_MAP` 单一来源，与 de_ai 共用词表）、段落节奏（每段 ≤200 字）、对话比例（≥15%）、章末钩子。fail 不阻断，修复提示注入下一桥段【上章审查提示】（§5.9）。

## 12. 工程约定

- **Git**：工作分支 `dev`，`master` 为历史；远程 origin → github.com/xsneser/fiction-factory.git（URL 内嵌 ghp_ token 会过期）；仓库级代理 `http://127.0.0.1:7897`；提交用中文 conventional 风格（feat/fix/refactor + 简述），末尾 `Co-Authored-By: Claude`；`books/`、`profiles/`、`api.json`、`storage/` 不入库。
- **启动/重启**：`python ui/web_ui.py`（127.0.0.1:58080，`NOVEL_DEBUG=1` 开启 debug）；**重启必须杀净 58080 LISTENING 全部 PID**（`netstat -ano | findstr :58080`），否则旧进程"改动不生效"假象。
- **四大库单例**：改 `libraries/data/*.json` 必须重启服务才生效。
- **Windows 控制台 GBK**：脚本打印中文加 `sys.stdout.reconfigure(encoding="utf-8")`。
- **flash max_tokens 余量**：任何新 LLM 调用，max_tokens 必须大于"纯正文+推理"之和（写作 1600 / 摘要·书名 1024 / 探测器 400）。
- **测试会动数据**：`test_full_flow.py` 自建自删测试书；`books/`、`profiles/` 是真实数据，别删。
- **删除类操作无回收站**：delete_book / storyline_delete 前先确认。
- **合规**：番茄侦察兵仅限个人学习研究（SSR 采集 + PUA 解码），禁商业用途/大量下载传播正文；README 有完整声明。
