# NovelEngine 用户体验报告与界面优化方案

> 日期：2026-08-05　分支：dev
> 方法：代码审计（7 蓝图 / 20 模板 / 3 CSS / 3 JS 全量通读）+ 视觉审查（Selenium+Edge 截取 11 张 1500×950 真机截图，本地视觉模型逐页 review_ui / analyze_image / compare_ui 交叉验证）
> 截图与脚本：`tools/shots_ux/`、`tools/shot_ui_pages.py`

## 一、视觉审查核心发现（按页面）

| 页面 | 视觉确认的问题 |
|---|---|
| **仪表盘** | 6 张统计卡片+书目表+笔名表；**右侧栏空置明显**；部分文字截断处理不够优雅 |
| **书库 / 写作台** | 卡片/表格内**每行 4 个操作按钮平铺**，决策负担重；标签元信息同质（"故事线 X大纲·Y桥段"） |
| **书详情** | 顶部 4 个彩色按钮 + 内容堆叠 → 视觉模型评"**信息过载**"；进度条数值与视觉状态可能有出入 |
| **时间线详情** | 与书详情**高度相似**（compare 确认"布局与信息结构高度相似"）→ 冗余；被评"信息不足" |
| **故事线编辑器** | 主区上部被"折叠设定面板+四步流程条"占用，**核心可视化被压缩到下部**；左侧彩色条形图正常渲染，但顶部无场景引导 |
| **设置** | **输入框内灰色文字对比度不足**；"未配置"警告条对比度低；右侧栏空旷 |
| **抓取** | 表单直觉尚可；顶部 tab 中 3 个是置灰的"即将推出"，占位却各有一整块空面板 |
| **桥段库 / 笑点库** | 列表间距偏紧；**元信息高度同质化**（12 张卡全部"1000-5000字"）→ 列表无法快速扫读 |
| **启动新书** | 4 个 fieldset 分区堆叠、**垂直间距偏紧偏拥挤** |

跨页一致共性问题：**① 右侧 260px 状态栏空闲时大面积空白；② 灰色小字（#8b949e/#484f58、8-11px）对比度偏低；③ 区块间距普遍偏紧凑。**

## 二、用户旅程分析

### 旅程 A：启动新书 → 生成大纲 → 写作（核心路径）
- **断点 1**：启动新书表单 4 个 fieldset 一屏塞满，无进度指引，不知哪些必填。
- **断点 2**：编辑器顶部"基础设定折叠面板 + 四步流程条 + info-bar"占去视口上部约 250px，**主工作区被压到下方一屏之外**；首次进入右侧阶段面板 + 左下聊天面板同时出现，认知负载高。
- **断点 3**：生成期间用 `alert()` 弹结果、整页 `location.reload()` 收尾，无恢复/断点续传提示。
- **断点 4**：蓝图写作页 SSE 流式体验好，但写作进度变化仅靠颜色高亮，无动画强调。

### 旅程 B：管理书库
仪表盘/书库/写作台三处列出同一批书三种形态；**"书详情"与"时间线详情"两个页面内容几乎一样**，用户困惑该点哪个入口。

### 旅程 C：资产库建设
审查卡片交互不错，但**入库按钮无反馈（静默）**，右侧状态栏若滚动走了用户完全感知不到成功。

### 旅程 D：配置
设置页保存/测试连接已有 toast，是全站**唯一**有 toast 的页面——暴露其余页面还在用 alert。

## 四、界面优化方案

### 方案 1：右栏可折叠 + 自适应（治 P0-1）
- `#status-bar` 加折叠按钮（▶/◀），点击加 `.collapsed` 类 → 宽度缩为 0/40px。
- 空态优化：无任务时显示一行「空闲」而非空卡片区（`base.js:43` 已有 `STATUS_EMPTY`，压扁高度）。
- 改动：`base.html:36`、`base.css:15-30`、`base.js` 加 toggle 函数。

### 方案 2：全局 toast + 统一反馈（治 P0-2、旅程 C）
- 把 `settings.html:78-84` 的 `showToast` 提升到 `base.js`（全局函数 + 全局容器）。
- 写操作（生成书名、保存设定、入库、扩展大纲）统一 toast；保留 `confirm()` 用于危险操作（删除）。
- 入库成功给 toast「✅ 已入库 N 条」。
- 改动：`base.js` + `base.html`（加 `#toast-root`）+ 替换各模板 `alert(`。

### 方案 3：设计令牌收敛（治 P0-3）
- `base.css` 顶部引入 CSS 变量设计令牌（--bg/--fg/--accent/--radius/--space-*）。
- 把 `.info-bar`、`.gen-feed`/`.gf-item`、`.editor-split` 系列、`.btn-primary` 抽到公共 CSS，删掉 timeline 两页重复 `<style>` 块。

### 方案 4：单一渲染器（治 P0-4）
- 改动后重绘统一走 `renderPlotList`/`renderOutlineList`（已存在），把 `timeline_outline_card.html` 字段补到 JS 渲染器，与 Jinja 用同一数据源。短期至少加 e2e 断言：服务端渲染与 JS 重绘关键字段一致。

### 方案 5：信息架构合并（治 P1-1）
- **合并书详情与时间线详情**为一个模板：把 `timeline_detail.html` 独有的"故事线大纲手风琴"并入 `book_detail.html`；时间线详情路由直接 302 到书详情。

### 方案 6：可读性提升（治 P1-2/P1-3）
- 全局字号下限提到 11px；`--fg-dim`(#484f58) 只在装饰性文字用，正文用 `--fg-muted`。
- 列表元信息：桥段/笑点库把"字数范围"从主标题行移到可折叠 body，提升扫读率。
- 对比度：`--fg-dim` 提到 `#6e7681`（GitHub 同款），input 占位符同样处理。

### 方案 7：核心工作台重排（治 P1-5、旅程 A）
- 故事线编辑器进入即聚焦生成：基础设定默认收起 + 未保存改动徽标；流程条压缩为一行细进度条；分栏上移到 `main` 顶部。
- 蓝图写作页：给 `StoryLine.highlight` 增加高亮呼吸动画，写作进度变化可见。

### 方案 8：抓取页精简（治 P2-5）
- 未上线平台只留 tab + 一行"即将推出"文字，删掉各占一块的空面板。

## 五、实施路线图（按收益/成本）

| 阶段 | 内容 | 预期效果 |
|---|---|---|
| **第一批（1 天内）** | 方案 2 toast 全局化 + 方案 1 右栏折叠 | 消灭最刺眼的反馈/留白问题 |
| **第二批（2-3 天）** | 方案 3 令牌收敛 + 方案 6 可读性 | 视觉一致性 + 可读性立竿见影 |
| **第三批（3-5 天）** | 方案 5 合并详情页 + 方案 4 单一渲染器 | 减冗余、防漂移 |
| **第四批（持续）** | 方案 7 工作台重排 + 方案 8 精简 | 核心路径体验质变 |

**结论**：UI 的功能骨架和故事线可视化是亮点（数据驱动垂直 Gantt、SSE 实时反馈、三栏信息架构清晰），主要短板在**反馈机制（alert）、样式重复、右栏空置、可读性**四个工程/体验债。前三个方案（toast、令牌收敛、右栏折叠）可覆盖 80% 观感提升。

**两处实施取舍（相对报告原文）**：

1. **方案5**：`timeline_detail.html` 模板**保留**，未物理删除。理由：该模板仍服务"未建书的 tl_ 草稿"的详情视图（`book_*` 时间线和已建书 tl_ 草稿均已 302 到书详情页，草稿无书可跳，需独立视图）。book_detail 已内含完整故事线大纲手风琴，双页冗余在书场景已消除，草稿场景为必要保留。

2. **方案7**：未做"分栏结构整体上移到 main 顶部"的大改，改用低风险替代——**基础设定折叠面板从顶部下移到 editor-split 之后**，折叠态仅占底部约 50px，工作台可视化分栏首屏上移约 50px；`tle-layout` 加 `overflow-y:auto` 保证设定展开不裁切。视觉验证（本地视觉模型）无挤压/裁切/错位。另含：流程条压缩、未保存徽标、写作高亮呼吸动画。

**后续可选 P2 项**（本报告未排期）：响应式布局、伪 SPA 脚本重执行加固、aria 可访问性、emoji 图标体系、progress 数值与视觉一致性。
