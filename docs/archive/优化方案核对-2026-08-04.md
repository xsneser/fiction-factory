## 3. ⚠️ 必须修正的错误

### 3.1 `route()` 并非"全仓库零调用"（最高优先级，与 P0 自相矛盾）

- 事实：`test_all.py` Phase 9（行 359-385）直接调 `engine.route()` 5 次，断言返回 `PLAN_OUTLINE / REVIEW_CHAPTER / DE_AI_PASS / WRITE_CHAPTER / COMPLETE`。
- 冲突：P0 清单同时要求"删除 engine 旧状态机死路径"和"跑 `python test_all.py` 确认 75/75 回归"。删 route() 后 Phase 9 必挂，二者不可兼得。
- 建议：**保留 route()，只删 step/run/run_full_cycle + 4 个 `_exec_*` 死处理器**；若坚持删 route()，必须同步删除/改写 Phase 9 测试，并在方案中写明。
- 补充：§2 的 engine 死列表还**漏了** `_exec_write_chapter` / `_exec_complete` / `_exec_pause`（同属仅被死路径 handler 表引用的函数）。

### 3.2 `plugins/__init__.py:149 requests` 误分类为"未使用导入"

- 事实：行 149 是 `WeiboPlugin.is_available()` 内 try 块的**局部 import**，用于可用性探测（可导入则返回 True）；行 166 同理（BilibiliPlugin）。是**被使用的**，不是未使用导入。
- 建议：从 §2 未使用导入清单中剔除；若想删，需连同 is_available 的探测逻辑一起处理。

### 3.3 `de_ai.py:151` 重复 `import random` 行号错

- 事实：顶层 `import random` 在行 6；函数内重复 import 实际在**行 64**（`apply_word_replacements` 内）。substance（重复导入）成立，行号需改。

### 3.4 `core/llm_client.py` "4 个顶层函数"表述不准

- 事实：`stream_chunks` / `call_stream` / `call_messages` 是 `LLMClient` **类方法**（行 184/197/210），仅 `render_prompt` 是模块级顶层函数（行 225）。
- 补充：`stream_chunks` 被 `call_stream` 内部调用（行 203），属互引死簇，删除须一起删。

### 3.5 行号偏移（substance 均成立）

| 方案原文 | 实际位置 |
|---|---|
| `engine.py:244` 用 print() | print 在 **行 267**（engine.py 仅此一处 print）|
| `web_ui.py:38-46` logger 配置 | 实际在**行 25-33**（`for name in ["fanqie-scout","__main__"]`，只有这俩 logger 配了 handler，结论不变）|

### 3.6 §3.2 "每次 0.3-1s" 无代码依据

- 事实：`DETECTOR_TEMPERATURE = 0.3`（gag_injector.py:18）是**采样温度**，不是时间间隔；代码中无任何 0.3-1s 的探测时间相关逻辑。
- 建议：删掉该数值表述，保留"频率固定每短句组、无旋钮"的实质结论。
