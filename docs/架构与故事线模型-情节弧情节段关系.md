## 一、项目架构速览（现行）

### 1.1 一句话

NovelEngine 是「可视化、**外部 agent 可驱动**的多阶段小说创作平台」。创作大脑在**平台之外**（Claude Code / 侧栏 dsh），经 **MCP stdio** 调一套**薄工具面**驱动平台，平台只负责存数据、跑免费规则（去 AI 味/审查/门禁/台账），生成类的 LLM 工作全在 agent 侧完成。

### 1.2 分层与进程

```
┌─ 驱动方(大脑，平台外)───────────────────────────────────┐
│  Claude Code  ·  侧栏 dsh headless(vendor/dsh-ne 子进程)  │
└──────────────┬──────────────────────────────────────────┘
               │ MCP stdio：mcp__novel-engine__*（约 39 个，以注册表为准）
        ┌──────▼────────┐           ┌────────────────────────┐
        │  mcp_server.py │           │  Web 服务 Flask  58080  │
        │  FastMCP stdio │           │  ui/web_blueprints/ 10 蓝图│
        └──────┬────────┘           └───────────┬────────────┘
               │        agent_tools.py TOOL_REGISTRY（唯一工具源）│
               │   护栏：PHASE_GATES / BookLock / LoopGuard / nav-intent │
               ▼                                    ▼
   ┌───────────────────────────────────────────────────────────┐
   │  libraries/ 引擎+四库(模板)+规则层      books/ 真实书数据    │
   │  libraries/data/{structures,plots,gags,characters}.jsonl  │
   └───────────────────────────────────────────────────────────┘
```

- **双进程并存**：Web 进程与 MCP 子进程各自独立 import，靠 `books/` 文件 JSON + `storage/` 运行时缓存协调；写工具带书级锁（`BookLock`），冲突抛 `BookBusyError`。
- **工具数**：`agent_tools._build_registry()` 实收（勿信文档写死的数字）。schema 从类型注解自动生成。
- **护栏（不可绕）**：直建/直删工具不在工具面——建书必须 `navigate("/books/start")` + `drive_ui` 驱动向导，由系统 `POST /books/start` 建；删书走书库页手动。**phase 翻 `ready` 无任何 agent 工具**（用户动作触发，见 §四）。

### 1.3 双通道驱动

| 通道 | 机制 | 用途 |
|---|---|---|
| dsh 事件流（SSE） | `vendor/dsh-ne/events-runner.mjs` 把每次 tool_call/result 推 SSE | 侧栏实时工具卡、导航零延迟（主通道） |

### 1.4 阶段与 skill 分发（平台面）

|---|---|---|---|---|

## 二、故事线模型：一张总图

核心前提：**「库(模板)」与「书(实例)」是两层**；**弧与情节段是一根轴上的粗细两档**；**线程是另一根横向贯穿的轴**。三者不是同义词、不是层级递进，是**不同维度的正交关系**。

```
【模板层 · 可复用素材】                 【实例层 · 一本书的落地】
libraries/data/*.jsonl                books/<id>/storyline.json
┌─────────────────────────┐           ┌────────────────────────────────────┐
│ 情节弧库  ArcNode(平级)   │──选──▶    │ outlines[]  OutlineSlot 弧(树状嵌套) │
│   无父-子、每行一独立弧    │ template_id│   parent_arc_id 连成弧树           │
│   自带 description/key_… │ 回指      │   start_word/end_word = 字数权威轴  │
├─────────────────────────┤           │    └── stages[] 从模板展开的阶段     │
│ 情节段库    PlotTemplate   │──选──▶    │ plots[]    PlotSlot 情节段(挂叶弧)     │
│   骨架 template_structure│ template_id│   outline_id→叶弧 · thread_id→线程  │
│   变量槽 PlotSlot(模板槽) │ 回指      │   resolves_plot_id=设局/收局呼应     │
├─────────────────────────┤           │    roles/gag_ids/theme_hints/… 加料 │
│ 笑点库/角色原型库 等      │           ├────────────────────────────────────┤
└─────────────────────────┘           │ threads[] 线程定义 {id,name,desc}    │
                                      │ promises[] 读者承诺台账(伏笔生命周期)  │
                                      │ themes[] / global_gags[] 全书贯穿元素 │
                                      │ basic_info 人物/世界观/基调/视角       │
                                      └────────────────────────────────────┘
```

### 2.1 一句话关系（绳穿竹竿图）

- **纵向切割（粒度）**：书 → **弧（约 5–15 章一段有方向的叙事）→ 情节段（弧内一个戏剧节拍/事件，约 0.3–2 章）**。弧是树（可套子弧），情节段挂叶弧。
- **横向贯穿（选择）**：**线程**把散布在不同弧里的情节段串成一条线（主线/副线/伏笔线）。一根绳穿过多段竹竿（弧），每段竹竿里又有若干竹节（情节段）。
- **素材/实例**：弧、情节段都不是凭空生成的——**agent 从情节弧库/情节段库挑平级模板，实例化出带 `template_id` 回指模板的落地节点**；模板可复用、实例是这一本独有。

### 2.2 三条正交轴对照

| 轴 | 概念 | 粒度/方向 | 例子 |
|---|---|---|---|
| 纵向-粗 | 情节弧 Arc | 树状目标节点，掌控故事走向，覆盖字轴无空白 | 「末日来临前 10 章囤物资」 |
| 纵向-细 | 情节段 Plot | 弧内的可执行戏剧节拍 | 囤物资弧里「发现征兆/抢购冲突/金手指变现」 |
| 横向 | 线程 Thread | 跨弧的一条叙事线索，由各弧中情节段组成 | 伏笔线：第 3 章(弧1)设局 → 第 30 章(弧3)收局 |
| 生命周期 | 设局→收局 + promises | 同一情节段线索的埋与兑现 | `resolves_plot_id` 指回设局情节段，台账登记 |

## 三、逐层数据模型速查

### 3.1 故事线实例层（`libraries/storyline.py`）

#### OutlineSlot —— 一条弧（情节弧）在故事线上的位置 `storyline.py:236`

| 字段 | 含义 |
|---|---|
| `id` / `name` | 唯一标识 / 显示名 |
| `template_id` | 回指情节弧库模板 id；`""`=已展开不依赖模板 |
| `start_word` / `end_word` | **0 基字数坐标（start 含 / end 不含），落盘权威**；`None` 由章号推导 |
| `start_chapter` / `end_chapter` | 章号视图（兼容/推导，靠 `reconcile_outline` 与字坐标双向同步） |
| `parent_arc_id` | **弧树嵌套**：父弧 id，空 = 顶层弧（2026-08-27 起支持弧套子弧） |
| `overlaps_with` / `predecessor` / `successor` / `transition_type` | 与其它弧的平级关系（重叠/前驱/后继/过渡类型） |
| `stages` | 从模板展开的阶段列表 `[{name,min_ch,max_ch,events,description,foreshadow_opportunities,themes}]` |
| `expanded` | 是否已展开填充情节段 |
| `notes` | 设计意图 / 偏离库模板点的说明（drive_ui `set_outline` 用 `notes` 承载） |
| `narrative` / `narrative_target` | 顺叙/倒叙/插叙（当前主要影响 UI 呈现，未驱动写作顺序） |

#### PlotSlot —— 一个情节段在故事线上的位置 `storyline.py:262`

| 字段 | 含义 |
|---|---|
| `id` / `template_id` / `name` | 唯一 id / 回指情节段库模板 / 显示名 |
| `category` / `sub_category` | 分类（爽文/悬念/战斗…）/ 子分类 |
| `outline_id` | **所属弧 id**（写作归属） |
| `stage_index` / `order` | 所属弧内阶段索引 / 阶段内排序 |
| `parent_plot_id` / `children_plot_ids` | 情节段嵌套（父/子情节段） |
| `words` / `cover_beats` | 目标字数（agent 按内容浓淡给；0/None 回退 `cover_beats×200`）/ 预计节拍数 |
| `template_structure` / `slots` | 模板箭头骨架字符串 / 变量槽位 |
| `gag_ids` / `theme_hints` / `theme_moments` / `hook_points` | 笑点 / 内涵提示 / 阶段级内涵 / 吸睛点 |
| `written_chapter` | 已写入第几章（0=未写，断点续写依据） |
| `thread_id` / `thread_seq` | 所属线程（默认"主线"）/ 线程内序号 |
| `resolves_plot_id` / `resolves_name` | **收局槽位**：解决/呼应哪个设局情节段 id + 冗余存名 |
| `roles` | 出场人物（主角恒在首位） |
| `confirmed` | 用户已确认 |

#### BookStoryline —— 整本书故事线 `storyline.py:301`

`book_title / words_per_chapter / pen_name / platform` + `basic_info`（characters 统一数组 + world_building + tone/target_audience/pov/era_language）+ **`outlines[]`（弧）· `plots[]`（情节段）· `threads[]`（`{id,name,desc}`）· `promises[]`（读者承诺台账）· `themes[]` · `global_gags[]`** + `phase`（`config|outlines|plots|ready`，`gags` 已废弃残留于注释）+ `generated_at/updated_at`。

> ⚠️ 落盘文件是 **`books/<id>/storyline.json`**（不是 timeline.json——那是旧路由/工具描述里的兼容称谓）。序列化 `to_dict` 在 `storyline.py:340`，往返都做 `reconcile_outline` 同步章/字双坐标。

### 3.2 库模板层

#### 情节弧库：`ArcNode`（平级独立弧模板）`structure.py:22`，兼容别名 `StructureTemplate = ArcNode`（`structure.py:84`）

- **2026-09 v3「平级独立」**：全库每个弧字段集相同、**无父-子、无 `parent_arc_id`**；原树中「整段壳」与各层子弧都各自成为一条独立弧。每条自带：`id / name / description`（本弧情节怎么发展）/ `min_words / max_words`（字数区间，`total_words` 属性）/ `key_events` / `foreshadow_opportunities`（埋坑机会）/ `tags`（题材标签，可搜）/ `opening_patterns / climax_patterns`（引用的开篇/高潮情节段模板 id）/ `source / created_at / enabled`。
- **2026-09 起弧模板已删除「内涵/themes」字段**（母题不再承载在弧模板上；书级内涵落在 `BookStoryline.themes` 与情节段 `theme_hints/theme_moments`）。
- 存储：`libraries/data/structures.jsonl`。检索：`StructureLibrary.roots()`=全库即候选、`get_by_id`、`search(tags, word_count)`（tag 任一命中+命中数排序）。MCP 入口 `query_arc_library`（压缩成 `{id,name,tags,total_words,description[:200]}`）。

#### 情节段库：`PlotTemplate` `plot.py:20` + 变量槽 `PlotSlot` `plot.py:11`

- `PlotTemplate` 字段：`id / name / category / sub_category / description / template_structure`（**箭头骨架字符串**，如 `[当众羞辱]→[隐忍]→[展现实力]→[全场震惊]`）/ `slots`（变量槽，决定具体呈现）/ `variants / fit_contexts / word_range / usage_notes / examples / quality_rating / source / enabled`。
- **命名坑**：`libraries/plot.py:11` 的 `PlotSlot` 是**情节段模板的变量槽位**（name/description/options/default），与 `storyline.PlotSlot`（书内情节段实例）同名不同物。
- 存储：`libraries/data/plots.jsonl`。MCP 入口 `query_plots`（压缩 `{id,name,category,sub_category,fit_contexts,template_structure[:80]}`）。

### 3.3 关键：库模板 → 书实例的映射

| 模板层 | 实例化锚点 | 实例层 |
|---|---|---|
| `ArcNode`（一条平级弧模板） | `OutlineSlot.template_id`；`structure_to_stages`（`storyline.py:462`）把模板展开成 `stages` | `OutlineSlot`（树里可按需再拆子弧） |
| `PlotTemplate`（一条情节段模板） | `PlotSlot.template_id` + 拷贝 `template_structure` / `slots` | `PlotSlot`（挂叶弧） |

实例化的两条路径：**agent 自主生成**（现行，步 3 / novel-story：agent 从 `query_arc_library`/`query_plots` 选模板后自行产弧与情节段，经 `drive_ui(set_outline)` 或 `save_outlines` 落盘）；**规则引擎兜底**（`StorylineBuilder.fill_plots_for_outline` `storyline.py:676` / `OutlineGenerator.generate()`，库内 `match_for_chapter` 自动匹配）。

## 四、关系上的硬规则与工作流

### 4.1 两条硬校验规则（`agent_tools.py` `validate_storyline`）

只报告不修复，问题以 `decision_points` 返回，由 agent/用户补弧或移情节段；**步 3 建书时内联回打 ≥1 轮直到 passed=true**：

1. **顶层弧完整覆盖故事线纵轴（无叙事空白）**：顶层弧（`parent_arc_id` 空）按 `start_word` 排序铺满全书——报首弧 `leading_gap` 与相邻弧之间 `gaps`（`agent_tools.py:1351`）。
2. **情节段仅挂最底层弧（叶弧）**：每个 plot 的 `outline_id` 必须指向真实存在、且**不是任何弧的父弧**的叶弧——否则报「悬空」/「非最底层弧」（`agent_tools.py:1371`）。

另有 warning 级弧内填充检查（顶层弧跨度 vs 叶弧情节段 `planned_words` 之和）与结构软提示（叶弧/情节段字数均一、三层拆分建议）。

### 4.2 线程与设局→收局（横向机制）

- **线程定义** `threads[]`（主线/副线/伏笔线…），每个情节段 `thread_id` + `thread_seq` 归属一条线。多线程交错推进 = 插叙/并行叙事的调度基础。
- **设局→收局**：一个「埋伏笔」情节段（`resolves_plot_id` 空）在后续被「收局」情节段呼应（`resolves_plot_id` 指回设局情节段 id）。生命周期进 **`promises[]` 台账**：设局 `pending →` 推进 `advanced →` 收局 `fulfilled`（完整登记在 `engine.py` 写章路径；agent 薄工具写章只做 `op` 分级；逾期/停滞扫描在 `libraries/promise_ledger.py`）。写作时若逾期会产生决策点。
- UI 上：情节段泳道设局/收局徽标 + 琥珀虚线连线，线程横带列出成员（`ui/static/js/story_line.js`）。

### 4.3 agent 写作闭环（现行薄工具路径）

```
get_writing_context  →  next_plot = tl.plots 里第一个 written_chapter==0（= 弧序→阶段→order 序）
        │  一次性读全上下文（书配置+故事线+人物+最近章摘要）
        ▼
agent 自主生成情节段正文（去 AI 味在落盘侧做）
        ▼
save_plot_draft  单情节段 → draft_chapter.json 草稿缓冲（同 plot_id 重写）
        ▼  (累计字数达本「章」目标)
save_chapter_text  整章 → 副作用：去 AI 味 → 规则审查 → 硬字数门禁 →
                   落 chapters/<n>.json(含 bridges) → 更新书进度/字数 →
                   标记情节段 written_chapter → 角色状态机 → promises 台账 → 清草稿
```

- **情节段是正文写作的最小单元**；**章是后处理分组**（agent 攒到目标字数即「章满」落盘，章号是兼容视图，字坐标才是权威轴）。
- 引擎内置的流式写章路径（`write_chapter`/`write_next_plot`）带线程 2:1 穿插排序（`libraries/storyline_writer.py:180`）；现行 agent 薄工具路径排序 = `next_plot` 沿 `tl.plots` 列表顺序，线程穿插交给 agent 生成时自行安排。
- **完整章节质量门禁 `chapter_quality_gate`** 聚合五项，默认执行、只报告不修复：① 规则审查 `review` ② 连续性 `continuity` ③ 追读 `retention` ④ 伏笔台账 `promises` ⑤ 爽点 `punch_points`（只读标注不落盘）。产出 `decision_points` 由 agent/用户定夺。

### 4.4 phase 流转与门禁

```
建书(向导步3深化式, agent 生成) → 用户点「提交建书」→ phase=ready（正常路径，无书详情二次确认）
                                                                  │
config/补弧兜底: agent 自主生成 outlines/plots 经 save_outlines 落盘
   → phase=plots → 用户在书详情点「✅ 确认弧+情节段」(api_confirm_storyline) → ready
```

- 门控表 `libraries/tool_policy.py` `PHASE_GATES`：写作/上架/门禁类工具 gate 到 `ready`；`save_outlines` 全阶段；`save_basic_info` config+plots。
- **ready 恒由用户动作触发**（正常=向导提交；兜底=书详情确认），agent 无翻 ready 工具；已 ready 书续写/扩写追加弧经 `save_outlines` **保持 ready**。

## 五、字数是权威轴（章是视图）

- 弧的 `start_word/end_word`（0 基，start 含 end 不含）是**故事线定位的权威**；`start_chapter/end_chapter` 由 `words_per_chapter` 推导/兼容。
- `reconcile_outline`（`storyline.py:217`）幂等补轴：新书只给字坐标→推导章坐标；旧书只给章坐标→按每章字数推字坐标。落盘前必调。
- 情节段 `words`（agent 按浓淡规划）→ 章满阈值 → `save_chapter_text`。别再直接 `len()` 判字数，口径看 `count_prose_units`（中文字+英文词）。

## 六、常见概念澄清

| 误区 | 正解 |
|---|---|
| 「大纲=卷」 | 大纲（弧）是有方向的叙事段（约 5–15 章）；卷是更大后处理分组概念，不在素材/故事线层 |
| 「弧=模板」 | 弧模板（`ArcNode`，平级可复用）≠ 书内弧实例（`OutlineSlot`，树嵌套、有字坐标、`template_id` 回指） |
| 「线程是情节段的一类」 | 线程是横向贯穿维度；一个情节段同时属一个弧（纵向）+ 一个线程（横向） |
| 「storyline=时间轴文件」 | 落盘是 `storyline.json`，含弧/情节段/线程/台账/设定全量 |
| 「`plot.py` 的 PlotSlot」 | 那是**模板变量槽**，与书内情节段实例 `storyline.PlotSlot` 同名不同物 |

## 八、术语表

| 术语 | 含义 |
|---|---|
| 故事线 Storyline | `storyline.json` 整书配置：弧树 + 情节段 + 线程 + 承诺台账 + 设定 |
| 情节弧 Arc（实例 `OutlineSlot` / 模板 `ArcNode`） | 树状目标节点，掌控一段走向，覆盖字轴；模板平级可复用，实例带字坐标可嵌套 |
| 情节段 Plot（实例 `PlotSlot` / 模板 `PlotTemplate`） | 弧内可执行戏剧节拍；只挂叶弧；是正文写作最小单元 |
| 叶弧 Leaf Arc | 无子弧的弧；情节段唯一可挂处（硬规则） |
| 线程 Thread | 跨弧的一条叙事线索（主线/副线/伏笔线），由各弧中的情节段组成 |
| 设局 / 收局 | 埋伏笔情节段 / 用 `resolves_plot_id` 指回并兑现该情节段 |
| 承诺台账 promises | 设局→推进→收局的伏笔生命周期登记，逾期产生决策点 |
| 模板 / 实例 | 四库模板（可复用）→ 经 agent 挑选实例化出的书内弧/情节段（`template_id` 回指） |
