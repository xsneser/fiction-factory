# NovelEngine vs GitHub 开源项目 —— 优缺点与写作质量对比

> 日期：2026-08-05
> 方法：① 实跑本项目真实 LLM 生成一段正文（`test_book_32` 桥段路径，deepseek-v4-flash）作为实证样本；② 经本机代理 `curl -x http://127.0.0.1:7897` 抓取 9 家 GitHub 仓库的 prompt/规则/样例原文；③ 对照前序调研（`docs/开源调研.md` 架构向、`docs/网文开头处理-开源调研.md` 开头向）聚焦本次新角度——**写作好坏**。

---

## 一、先说结论（TL;DR）

1. **本项目写作质量实测可读性高、AI 味低**，靠"prompt 前载约束 + 桥段增量生成 + 笑点涌现"这一套，在同量级成本下是**性价比最高的路线**；真实样本短句利落、对话驱动、几乎无 AI 高频词。
2. **本项目的短板是"结构跟随性"和"缺少多轮质量门"**：实测样本里桥段结构被模型即兴改写（退婚打脸 → 卡车追逐），且刻意不做"写→审→改→润"多轮（硬约束：不加 LLM 后处理）。
3. **全场写作质量天花板是 loom-novel**（写手→编辑→润色五 Agent + 写作指纹），但它需要人工参与；**长篇小说自动化质检闭环最完整的是 show-me-the-story**（事实核查门 + 伏笔追踪 + 全书优化）；**网文味范本最实的是 Chinese-WebNovel-Skill**（真实语料 + 正反例库）。
4. **本质矛盾**：本项目"只优化 prompt、不换模型、不加 LLM 后处理"的约束，正是它便宜、快、可量产的原因，也同时是它写作质量上限的来源。要提质量上限，最划算的不是加润色，而是补**范本/正反例库**与**桥段结构硬约束**（都在免费规则层内）。

### 2.2 真实生成样本（deepseek-v4-flash 实跑，桥段「退婚打脸」正文草稿节选）

> 测试设定：都市/系统流/赘婿，桥段结构 `[当众羞辱]→[主角沉默隐忍]→[关键时刻展现实力]→[全场震惊]→[对方后悔]`，阶段事件「当众退婚/主角隐忍/家人逼问」。

```
路况松动，右边车流让出口子。

萧晨切方向盘钻缝，后视镜里商务车被辆大货压住。

秃子回头咧嘴："总算甩……草！"

前头路口横出一辆黑色SUV，拦死半条道。

……

屏幕上是张照片——苏婷在银行柜台前，手指按着转账单，旁边站了个秃顶男人。

"你老婆下午三点前，要把五十万打给这个人。"那人笑道，"你猜，谁在等着你这车货？"

萧晨盯着那张照片，指节在方向盘上敲了两下。

……

"他追的是我，你慌什么。"

……

导航提示"前方右转进入码头"，可右转道口横着一辆黑色SUV，车门大开，三个人抱着膀子站在车边等着他。
```

**样本评分（个人实测判断）**：

| 维度 | 得分 | 依据 |
|---|---|---|
| 可读性/节奏 | ★★★★☆ | 短句利落、动作+对话驱动、紧张感在线，"他追的是我，你慌什么"很有味道 |
| AI 味控制 | ★★★★☆ | 无"仿佛/似乎/不禁"等高频词，口语化"草""孙子"，不像 AI 腔 |
| 场景画面 | ★★★★☆ | 具体动作（切方向盘、碾斑马线、指尖泛白），非抽象抒情 |
| 章末钩子 | ★★★★☆ | 码头三人堵路收尾，留有悬念 |
| **结构跟随性** | ★★☆☆☆ | **严重漂移**：桥段本是「退婚打脸」的"当众羞辱→隐忍→展现实力→全场震惊→对方后悔"，实际写成了**卡车追逐/码头交货**，五步结构完全没走 |
| 格式完整性 | ★★★☆☆ | 段落切分把对话引号拆到孤行（`"那人认识你？` 换行后 `"` 单独成段），属于短句组拆分瑕疵 |

**对样本的诚实解读**：
- 模型吸收了"冷开场 + 冲突前置"的写前铁律（第一段就是追逐冲突），但**把桥段骨架当参考而非蓝图**——结构跟随弱。好的一面是它把"退婚/背叛"重新发明成了"妻子转账的金钱背叛"，钩子依然成立；坏的一面是节奏不受控，若后续桥段也这样漂移，大纲→正文的映射会失真。
- 对话引号孤行是 `_split_sentences` 按句末标点拆段时的边界 bug，属可修的工程问题。
- **结论**：本项目单段文笔在同成本开源项目里属中上（优于一次性整章生成的 AI 腔），但**"桥段结构跟随"和"写后无改稿"是质量短板**。

## 四、本项目 vs 各家的优缺点对照

### 4.1 相对优势（本项目强在哪）

| 维度 | 本项目 | 竞品参照 |
|---|---|---|
| **量产规模** | 笔名=独立 AI 作家，多书矩阵、逐章续写闭环、成本记账 | 竞品几乎全是"一书一生成"，无批量多书矩阵（连 show-me-the-story 也不做） |
| **成本控制** | flash + 免费规则层，探测/摘要调用 ≤500 token | loom/Chinese-WebNovel-Skill 的编辑+润色多轮，成本数倍 |
| **笑点/幽默** | 探测器环涌现注入，全场独有 | 无一家有"笑点探测器"这类**涌现式幽默**机制 |
| **长线一致性** | 承诺台账 + 语义摘要 + 设局→收局 + 线程穿插 | 强于多数单轮项目，接近 show-me-the-story 的伏笔系统 |
| **单段文笔** | 桥段增量 + 炸裂开场 + 平台约束，实测 AI 味低 | 同量级（无润色工序）项目里属上乘 |

### 4.2 相对劣势（本项目弱在哪，以及竞品谁更强）

| 短板 | 本项目现状 | 谁更强 | 差距在哪 |
|---|---|---|---|
| **写后多轮改稿** | 刻意不做（硬约束） | loom-novel(编辑+润色)、show-me-the-story(定向修订)、harnessNovel(humanize) | 竞品有"生成后独立质量工序"，本项目只有软门禁+词表替换 |
| **结构跟随性** | 实测漂移：桥段骨架被即兴改写 | harnessNovel「章纲是唯一蓝图」、show-me-the-story「严格承接不矛盾」 | 本项目桥段结构在 prompt 里偏弱，模型当参考不当法律 |
| **事实/一致性核查门** | reviewer 纯规则、软门禁（fail 不阻断） | show-me-the-story FactCheck（FAIL 自动重写）、harnessNovel 批次合理性审计 | 竞品有客观矛盾硬门，本项目靠 prompt 铁律兜 |
| **范本/正反例** | 无 good_examples，网文味靠规则文字 | Chinese-WebNovel-Skill(166篇语料)、tance-mang(真实钩子例句) | 规则给不出"味儿"，真实范本才能 |
| **去 AI 味深度** | 词表随机替换（`random.choice`）+ 段落切分，属表面净化 | loom 写作指纹、novel-harness 语感原则("人写东西有废话") | "像人"不是擦词，是保留不规整；本项目偏机械 |
| **文笔质量评测** | 测试只验机制（桥段/开场开关/审查路由），无 LLM 判卷 | qiaomu 的 `evaluate_story.py`（抽象度/对白/场景/钩子指标） | 本项目无"这章写得好不好"的量化反馈闭环 |

## 五、写作质量纵向结论

按"写作好坏"把本项目放进谱系：

```
个人润色上限高 ─────── loom-novel / Chinese-WebNovel-Skill（人机协作，需人参与）
        │
        │ ← 本项目的现实生态位
        ↓
自动化量产质量好 ───── show-me-the-story / harnessNovel（有硬质量门，成本略高）
        │
        ↓
全自动便宜速产 ─────── NovelEngine（桥段增量+笑点涌现+软门禁）
```

- **绝对写作质量**：本项目打不过 loom-novel（五工序+指纹）和 show-me-the-story（事实门+全书优化）——它们就是为"写得好"设计的，代价是慢和贵。
- **单位成本写作质量**：本项目是最优档。flash 单次生成 + 免费规则，产出接近"无润色工序竞品"里最好的水平（实测样本可读性 4/5）。
- **差异化**：笑点涌现、笔名人格化、批量矩阵是三家最强竞品都没有的；这些恰好是**商业/量产**而非"单本文学性"的武器。

## 六、可借鉴改进（全部落在"只优化 prompt/免费规则层"约束内）

按性价比排序（对应 `docs/人类创作思考路线-开源调研与方案.md` 未做项）：

1. **桥段结构硬约束**（修 2.2 实测漂移，最高优先）：写作 prompt 把 `template_structure` 从"参考"升级为"本桥段唯一事件顺序"，每短句组完成后对照结构步进，漂移即注入【重写提示】——借 harnessNovel「章纲是唯一蓝图」。改 `prompt_harness.py` 一处。
2. **范本/正反例库**（治"没味儿"）：仿 `gag_lib` 建 `example_lib`（开篇钩/打脸/断章真实范本各若干条，男女频），桥段开写前按 category 预筛注入——借 tance-mang hook-library、Chinese-WebNovel-Skill 语料层。新库，免费规则。
3. **硬禁句式表升级**（治 AI 腔）：补"不是A而是B/破折号/值得一提"等全场共识硬禁——借 harnessNovel/qiaomu 的禁令清单，直接并入 `OPENING_MODE_RULES` 或新增 `STYLE_BAN_LIST`。免费规则。
4. **审阅改"软门禁→分级"**：reviewer 现为软门禁（fail 只注入下桥段）。可加"规则重灾区"（如连续 2 章 AI 词超标）时把该词升级进下章 prompt 的禁用表——免费规则。
5. **对话引号孤行 bug**：修 `storyline_writer._split_sentences` 对对话引号边界的切分，避免 `"` 单独成段。
6. **不做**（守约束）：loom 式写作指纹、LLM 编辑/润色工序、show-me-the-story 式整章修订——都属"加 LLM 后处理"，与硬约束冲突；若未来要提质量上限，应从 **loom 的指纹学习信号**（只学人工改稿 diff）切入，那是唯一不违背"prompt 层"哲学的做法。
