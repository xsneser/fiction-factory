## 一、当前 agent 架构（一句话）

**侧栏聊天 / 建书向导按钮 → `libraries/dsh_bridge.py` 起 dsh-ne headless 子进程（事件流版）→ `vendor/dsh-ne/events-runner.mjs` 把每个工具调用逐事件写 NDJSON → 实时转 SSE → 前端工具卡 / 导航 / 向导命令。全服务单任务（新任务打断旧任务）。建书拆成两个 skill：`novel-build-candidates`（步 1 候选生成**呈现**，按钮路径仅 2 次工具调用）→ 用户在步 2 挑选 → 点「已挑选完毕」页面**自动触发** `novel-build`（步 3 精简分阶段建书）。**

```
浏览器（侧栏 / 🚀 让 Agent 构建）
  → POST /api/agent/chat（或 agentSendTask → busy 打断+排队）
  → run_dsh_task：interrupt_current_task() 打断旧任务 → Popen node vendor/dsh-ne/lib/bin.js
  → events-runner.mjs 监听 session/event，tool/call·tool/result 逐行 NDJSON
  → _map_dsh_event 转 SSE（tool_call/tool_result/navigate/ui_command/reply/error/done）
  → 前端 handleEvent：callId 配对工具卡、实时导航、dispatchCommand 驱动向导
```

**护栏链**：系统工具已禁（headless profile `disabled: true` 约 30 个，只留 MCP+skills+联网）→ phase 门控 `tool_policy.py` → MCP 循环熔断 `loop_guard.py` → 建书保真度（前端自动 reset + 校验）→ 全服务单任务打断。

## 二、核心机制

### 2.1 事件流实时推送
- `vendor/dsh-ne/events-runner.mjs`：替换 `headless-runner`（原只打印最终文本），监听 `session/event` 把 `tool/call`/`tool/result` 逐事件写 NDJSON；收尾补 reply/done/error。挂载 = 运行期 overlay `--patch` 禁 headless-runner + insert events-runner（`file:///` 绝对 URL）。
- `dsh_bridge.py`：`Popen` + 双线程（stdout/stderr）逐行读 NDJSON → `_map_dsh_event` 转 SSE；`pending` 字典按 **callId** 配对 tool/result 补工具名。
- **drive_ui 参数拆内层（2026-08-21 修复）**：`_map_dsh_event` 的 drive_ui 分支把整个工具参数 `{cmd, args:{…}}` 当 `ui_command.args` 发出去过——`cmd` 从顶层取到但 `args.candidates` 等全部落空（页面渲染「候选为空」）。已改为 `args.get("args")` 取**内层 args**，与 nav-intent 通道一致；前端 `onnecommand` 另加防御性拆包（守卫 `'cmd' in args`）。
- `agent_panel.js`：callId 配对工具卡（`toolCards`/`TOOL_CARD_LIMIT`）+ **`⏱` 工具耗时**（`addToolCard` 记 `performance.now()`，`finishToolCard` 收尾追加 `⏱ N.Ns/ms`）+ `busy` 期间暂停 nav-intent 轮询 + done 时 drain nav-intent 残留。
- 效果：浏览器实时看到工具进度/耗时/导航/向导命令（不靠 2.5s/3s 轮询）；外部 Claude Code 仍走 nav-intent 轮询兜底。

### 2.2 全服务单任务打断
- `dsh_bridge.py`：模块级 `_current_proc` + `interrupt_current_task()`（Windows `taskkill /F /T` 杀整树——node 会 spawn python mcp_server 子进程，`Popen.kill()` 只杀父进程会留孤儿）。
- `run_dsh_task`：启动前打断旧任务；`finally` 反注册+收尸（孤儿进程/客户端断连 GeneratorExit 兜底）；被打断/崩溃且无 done 事件 → `error`+`done` 收尾（前端 busy 复位）。
- `POST /api/agent/chat/cancel` 幂等端点；前端 `agentSendTask` busy 时先 cancel 再排队（`pendingTask`，done 接力）。
- 验证：`python tools/test_single_task_interrupt.py`（B 打断 A → A error+done / B 正常）。

### 2.3 建书：两 skill 拆分 + 用户挑选作为硬交互点（2026-08-21 重构）
- 前端固定候选管线已移除（`loadCandidates` fetch 删，现为 stub）；步 1 主按钮「🚀 让 Agent 构建」。
- **`WZ.agentBuild()`**：点按钮 → **web 自动** reset + 填 idea/tags + **自动进步 2**（候选框「⏳ 等待 Agent 生成候选…」）→ `window.agentSendTask(task, {card:true})`（右侧「🚀 建书任务」卡片，history 带 `card:true` 刷新后仍显卡片）。任务文本指名 `novel-build-candidates`。

**步 1 = `novel-build-candidates`（候选生成呈现，停）——按钮路径极简，只 2 次调用**：
- **🚀 按钮路径（任务说「已自动进步 2」）**：表单已填好、向导已在步 2、书必不存在。**禁止** `list_books`/`get_build_status`/`navigate`/`reset`/`set_field`/`set_tags`/`next`/`query_profiles`（全冗余）。
  1. `world_candidates(book_id="", idea, tags)`（genre 可空由 tags 推导）→ 候选。
  2. `drive_ui(set_candidates, {candidates:[{title, one_liner, world_brief}]})` → 渲染**可点选候选卡**（存 `window.__CANDIDATES__`；用户点卡走 `WZ.pickCandidate(i)` 高亮、可换；卡片无底部提示文案）。
  3. **停止**。笔名仅当任务为「（未选，请帮我选）」才 `query_profiles` + `set_field pen` 补。
- **侧栏路径（「帮我建一本 / 开一本新书」）**：`navigate(/books/start)` 翻到**步 1 表单**（非步 1 / 残留草稿先 `drive_ui(reset)`；用户已给全则 `set_field idea` + `set_tags` + `set_field pen` 预填）→ **停止交用户**填写/确认（不代填后自动 next、不聊天索要设定、不代生成候选）→ 点「🚀 让 Agent 构建」由按钮路径接管（生成候选并呈现，停步 2）。
- **硬规则**：绝不 `pick_candidate` / `next` / `submit`（挑选是用户动作）。

**步 2 交棒（页面自动）**：用户点「已挑选完毕」→ `WZ.next()` 以 `_task2Fired` 守卫触发**第二个任务**（文本指名 `novel-build`）→ 右侧第二张「🚀 建书任务」卡片；同时置 `_agentDriving` 抑制 `show(3)` 的旧 `fillWorld()` 一键补全（步 3 显示「⏳ 已挑选完毕，等待 Agent 分阶段补全世界观…」）。

**步 2 = `novel-build`（步 3 精简分阶段建书，~13 次调用）**——不做候选（候选已由用户选定）：
- ① `generate_core_conflict` → `set_world(core_conflict)`（返回 genre）
- ② 选材**省略**（不 `query_structures`/`query_plots`/`set_picks`；`generate_full_outline` 自动选材，要自定义走 novel-outline / `set_picks`）
- ③ `generate_factions` → `set_world(factions)`
- ④ `generate_characters` → `set_characters`（不 `query_characters`，原型自动回退）
- ⑤ `generate_rest_world` → `set_world(era…world_summary + 基调)`
- `drive_ui(submit)` → 系统建书 → `get_build_status` 拿 book_id → `get_book_detail` 校验 → `generate_full_outline` → phase ready → `navigate(/books/<id>/continue)`。

**要点**：
- **不要在 next 后立即查 get_build_status**（浏览器异步消费会滞后 → 误判重试）；`get_build_status` **仅 submit 后用**（拿 book_id）。
- **双驱动防重**：task2 触发后 agent（dsh）是步 3 **唯一驱动者**；页面 `_agentDriving` 抑制自动一键补全，避免与 agent `set_world` 互相覆盖。
- **步 3 徽标条已删（用户 08-21）**：前端不再有 5 徽标进度区；`set_world`/`set_characters`/`set_picks`/`reset` 已去 `updateStageStatus` 调用，人物用新 `renderCharCards`（`#wz-char-cards`）。

### 2.4 get_build_status 建书状态工具
- `libraries/build_status.py`：`storage/build_status.json` 持久快照（set/get）。
- `POST /api/agent/build-status` 接收浏览器上报；`agent_tools.py` 注册 `get_build_status()` 只读 MCP 工具（无锁/无门控，工具数 41）。
- `WZ.reportStatus()`：`show()`/建书成功/每条 onnecommand 命令后上报 `{cur, bookId, creating, _picked, has_world, has_picks}`（浏览器驼峰 `bookId` → 后端 `book_id` 映射）。
- **当前只用于 submit 后确认建成**（skill 已删前置检查用法）。

## 四、待办 / 已知边界

1. **浏览器全流程 e2e（主要）**：填 idea/tags/笔名 → 点「🚀 让 Agent 构建」→ 确认：web 进步 2 显示「等待候选」→ `novel-build-candidates` 候选卡**呈现（不自动跳步；按钮路径应只 2 张工具卡）** → 用户点卡高亮（可换）→ 点「已挑选完毕」→ 进步 3「等待 Agent」+ 第二张建书任务卡 → `novel-build` 精简分阶段 → submit → 跳书详情 → `get_build_status` 拿 book_id → `generate_full_outline`。**唯一未现场完整闭环的环节**。注意：**改前端/后端后需重启平台（58080）生效**（skill 的 `.md` 每次任务重读，无需重启）。
2. **打断是 kill 整树**（`taskkill /F /T`）：打断长工具（generate_full_outline 阻塞数分钟）会丢未落盘中间结果（管线逐步落盘，可重跑续接）。
3. **dsh/LLM 偶发 `drive_ui` 漏传 `cmd`**（`cmd Field required`）：skill 已加「drive_ui 是两参工具」提示；重试即可，属 LLM 侧 flake。
4. **build_status.json 残留**：`reset` 清 bookId；建书成功 `created=true`。若误导，删 `storage/build_status.json`。
5. **旧 history 无 card 标记**：本次修复前存的 build 任务刷新后仍显用户气泡——侧栏「🗑 清空」可清。
6. **dsh 0.1.0-rc 会 breaking**：`vendor/dsh-ne/` 依赖已去 caret 锁精确快照（rc.8 子包）；升级前回归 mcp_smoke/test_all。
7. **已装 headless profile persona 旧**：`~/.dsh/profiles/headless/` 的 persona 仍是单 `novel-build` 旧分发——运行时靠 `dsh_bridge._REINFORCEMENT`（每任务注入）已覆盖拆分；如需 persona 级一致，用 `agent-sidecar/cordis.patch.yml` 模板重装。
8. **docs 数量口径**：工具数 41（set_candidates 是 drive_ui 子命令，不新增工具）；改工具后同步 `README`/`CLAUDE.md`/`架构总览`/`mcp_smoke`/本交接文档。
