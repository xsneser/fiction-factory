## 一、当前 agent 架构（一句话）

**侧栏聊天 / 建书向导按钮 → `libraries/dsh_bridge.py` 起 dsh-ne headless 子进程（事件流版）→ `vendor/dsh-ne/events-runner.mjs` 把每个工具调用逐事件写 NDJSON → 实时转 SSE → 前端工具卡 / 导航 / 向导命令。全服务单任务（新任务打断旧任务）。启动新书经 novel-build skill 全流程 agent 驱动（web 自动进步 2）。**

```
浏览器（侧栏 / 🚀 让 Agent 构建）
  → POST /api/agent/chat（或 agentSendTask → busy 打断+排队）
  → run_dsh_task：interrupt_current_task() 打断旧任务 → Popen node vendor/dsh-ne/lib/bin.js
  → events-runner.mjs 监听 session/event，tool/call·tool/result 逐行 NDJSON
  → _map_dsh_event 转 SSE（tool_call/tool_result/navigate/ui_command/reply/error/done）
  → 前端 handleEvent：callId 配对工具卡、实时导航、dispatchCommand 驱动向导
```

**护栏链**：系统工具已禁（headless profile `disabled: true` 约 30 个，只留 MCP+skills+联网）→ phase 门控 `tool_policy.py` → MCP 循环熔断 `loop_guard.py` → 建书保真度（前端自动 reset + 校验）→ 全服务单任务打断。

## 二、核心机制

### 2.1 事件流实时推送
- `vendor/dsh-ne/events-runner.mjs`：替换 `headless-runner`（原只打印最终文本），监听 `session/event` 把 `tool/call`/`tool/result` 逐事件写 NDJSON；收尾补 reply/done/error。挂载 = 运行期 overlay `--patch` 禁 headless-runner + insert events-runner（`file:///` 绝对 URL）。
- `dsh_bridge.py`：`Popen` + 双线程（stdout/stderr）逐行读 NDJSON → `_map_dsh_event` 转 SSE；`pending` 字典按 **callId** 配对 tool/result 补工具名。
- `agent_panel.js`：callId 配对工具卡（`toolCards`/`TOOL_CARD_LIMIT`）+ `busy` 期间暂停 nav-intent 轮询 + done 时 drain nav-intent 残留。
- 效果：浏览器实时看到工具进度/导航/向导命令（不靠 2.5s/3s 轮询）；外部 Claude Code 仍走 nav-intent 轮询兜底。

### 2.2 全服务单任务打断
- `dsh_bridge.py`：模块级 `_current_proc` + `interrupt_current_task()`（Windows `taskkill /F /T` 杀整树——node 会 spawn python mcp_server 子进程，`Popen.kill()` 只杀父进程会留孤儿）。
- `run_dsh_task`：启动前打断旧任务；`finally` 反注册+收尸（孤儿进程/客户端断连 GeneratorExit 兜底）；被打断/崩溃且无 done 事件 → `error`+`done` 收尾（前端 busy 复位）。
- `POST /api/agent/chat/cancel` 幂等端点；前端 `agentSendTask` busy 时先 cancel 再排队（`pendingTask`，done 接力）。
- 验证：`python tools/test_single_task_interrupt.py`（B 打断 A → A error+done / B 正常）。

### 2.3 启动新书 agent 驱动（🚀 让 Agent 构建 / 侧栏）
- 前端固定候选管线已移除（`loadCandidates` fetch 删）；步 1 主按钮「🚀 让 Agent 构建」。
- **`WZ.agentBuild()`**：点按钮 → **web 自动** reset + 填 idea/tags + **自动进步 2**（候选框「⏳ 等待 Agent 生成候选…」）→ `window.agentSendTask(task, {card:true})`（右侧显示「🚀 建书任务」卡片，history 带 `card:true` 标记刷新后仍显卡片）。
- **novel-build skill 两条路径**：
  - **按钮路径（任务说「已自动进步 2」）**：跳过 reset / set_field idea·tags / 步 1→2 next，直接从 `world_candidates` 开始。
  - **侧栏路径（「开一本新书」）**：走完整 `navigate → reset → set_field → set_tags → next（步 1→2）→ world_candidates`。
  - 步 2→3：`world_candidates`（LLM 约 2-5s，浏览器同时消化）→ `drive_ui(pick_candidate)`（**`idx` 可省略**，候选内容在 `candidate` 内嵌传入）→ 步 2 候选卡实时渲染 → `drive_ui(next)` → 步 3 分阶段（core_conflict→set_picks→factions→characters→rest_world）→ submit。
  - **不要在 next 后立即查 get_build_status**（浏览器异步消费会滞后 → 误判重试报错）；`get_build_status` 仅用于 **submit 后确认 book 建成**（拿 book_id）。

### 2.4 get_build_status 建书状态工具
- `libraries/build_status.py`：`storage/build_status.json` 持久快照（set/get）。
- `POST /api/agent/build-status` 接收浏览器上报；`agent_tools.py` 注册 `get_build_status()` 只读 MCP 工具（无锁/无门控，工具数 41）。
- `WZ.reportStatus()`：`show()`/建书成功/每条 onnecommand 命令后上报 `{cur, bookId, creating, _picked, has_world, has_picks}`（浏览器驼峰 `bookId` → 后端 `book_id` 映射）。

## 四、待办 / 已知边界

1. **浏览器全流程 e2e（主要）**：填 idea/tags/笔名 → 点「🚀 让 Agent 构建」→ 确认：web 进步 2 显示「等待候选」→ agent 候选卡实时出现 → next 进步 3 → 分阶段 → submit → 跳书详情 → `get_build_status` 拿 book_id 校验 → `generate_full_outline`。**这是唯一未现场完整验证的环节（前面多次逐步修复：步序/竞态/idx/卡片持久化）。**
2. **打断是 kill 整树**（`taskkill /F /T`）：打断长工具（generate_full_outline 阻塞数分钟）会丢未落盘中间结果（管线逐步落盘，可重跑续接）。
3. **build_status.json 残留**：`reset` 清 bookId；建书成功 `created=true`。若误导，删 `storage/build_status.json`。
4. **旧 history 无 card 标记**：本次修复前存的 build 任务刷新后仍显用户气泡——侧栏「🗑 清空」可清。
5. **dsh 0.1.0-rc 会 breaking**：`vendor/dsh-ne/` 依赖已去 caret 锁精确快照（rc.8 子包）；升级前回归 mcp_smoke/test_all。
6. **docs 数量口径**：工具数 41；改工具后同步 `README`/`CLAUDE.md`/`架构总览`/`mcp_smoke`。
