## 三、现状盘点（接手必看）

### 3.1 现有内置 agent（将被替换的主体）
- `plugins/agent_loop.py`:`run_agent_loop(messages, emit)` —— 原生 function calling(`LLMClient.call_tools`,默认 max_tokens=8192),`MAX_ITERS=12`,**无状态**(messages 浏览器持有),SSE 事件(tool_start/tool_result/reply/navigate/canvas/error/done)。`SYSTEM_PROMPT` 含「行动优先」+ 完整链路 + 护栏规则。
- 端点 `ui/web_blueprints/agent.py`:`POST /api/agent/chat`(SSE)+ `/api/agent/tool-log` + `/api/agent/nav-intents`。
- 前端 `ui/static/js/agent_panel.js` 右侧栏聊天面板 + 工具日志页签。

### 3.2 共享工具面（替换后 dsh 复用）
- `agent_tools.py` `TOOL_REGISTRY`:**43 工具**(Web 面 43 / MCP 面 40);`_WEB_ONLY_TOOLS = {canvas_command, create_book, delete_book}`(建书/删书护栏);`_LOCKED_TOOLS` 10 个写工具套书锁(`BookLock`/`BookBusyError`)。
- `mcp_server.py`:FastMCP stdio 适配层,注册 surface ∈ {mcp,both} 的 40 工具。

### 3.3 dsh 侧车现状（08-20 已搭好）
- 安装:`npm i -g @deepseek-ai/dsh`(0.1.0-rc.7);Node v24.19.0 已装。
- profile:`~/.dsh/profiles/headless/`(`cordis.patch.yml` 挂 `@deepseek-ai/dsh-mcp-client` → `python mcp_server.py`;`system-prompt.persona` 注入四阶段编排;默认模型 `deepseek-official / deepseek-v4-flash`);`~/.dsh/.env` 有 `DEEPSEEK_API_KEY`。
- 仓库侧:`agent-sidecar/`(4 个 dsh 版 SKILL.md + `cordis.patch.yml` 模板 + README,已提交);`.dsh/` 已入 gitignore。
- 结论文档:spike 结论已删,浓缩进 `docs/架构总览.md` §七(dsh 侧车现状/3 摩擦点)。

### 3.4 关键配置语法（踩过的坑,别再踩）
- dsh `cordis.patch.yml` 是 **patch 层**,只支持 id-targeted override;**新增条目必须用 `insert`(不带 id)** 追加到根列表;profile 的 `cordis.yml` 是硬编码空根,不生效,别编辑它。
- skill 挂载:`dsh-skill-filesystem` 默认扫 `<projectRoot>/.dsh/skills`(cwd 的项目根)与 `~/.agents/skills`;本项目把 `agent-sidecar/skills/` 复制到 `D:\NovelEngine\.dsh\skills\`。
- `dsh-agent-instructions` 从 cwd 读 `AGENTS.md` / **`CLAUDE.md`** —— NovelEngine 根目录的 CLAUDE.md 会自动成为 dsh 指令。

## 四、替换方案（方向 + 待定问题）

### 4.1 替换范围
- **停用/移除**内置 `plugins/agent_loop.py` 的 function-calling 循环,agent 大脑换成 dsh。
- **保留**共享工具注册表(43/40)与 Web 可视化(浏览器轮询意图队列),dsh 经 MCP 驱动。
- **侧栏入口对接方式（待定 #1,见下）**。

### 4.2 两种对接形态（待定）
| 形态 | 说明 | 优缺点 |
|---|---|---|
| **A. dsh 自带 web profile 作新界面** | 直接 `dsh --profile web`(端口 3080)当 agent 界面,NovelEngine Web 侧栏退役 | 白拿 dsh 全套 UI/会话/记忆;但脱离 NovelEngine 现有页面,Gantt/向导可视化要靠 navigate 意图桥绕 |
| **B. 侧栏保留,后端换 dsh** | `/api/agent/chat` 后端从 agent_loop 改为转发到 dsh(经其 OpenAI 兼容 HTTP 口或进程调用);dsh 经 MCP 调回平台工具 | 保留现有 UI;但有回环(平台调 dsh,dsh 又调平台),多一层,且 dsh 的会话/记忆要另开接口透出 |

> **待定 #1**:选 A 还是 B?(影响整个 Web 层改造范围)

### 4.3 替换后必补的护栏（spike 三个摩擦点的对应修复）
1. **长工具超时**:`generate_full_outline` / `write_next_bridge` 阻塞数分钟,`toolCallTimeoutMs` 必须 ≥600000(10 分钟),否则 MCP 掐断、大纲产出失败。
2. **循环失控**:agent 在 phase 未达 ready 时反复轮询 `get_book_detail` 死循环 → 需护栏层语义环熔断(同工具签名 ≥3 次/轮询 >N 次 → 报错终止),dsh 自带护栏在 headless one-shot 下不充分。
3. **建书保真度**:set_field/set_tags/pick_candidate 未忠实传达任务设定(要求都市赘婿建出玄幻重生,tags 一度空)→ 需向导状态保护 + 任务提示词强化 + 校验建书后基本盘。
4. **工具白名单收紧**:dsh 会擅自调用任务未要求的工具(如 `save_basic_info`)破坏状态 → 按 phase 门控工具(`ToolPolicy` 思路,**Phase 1 已实现**为 `libraries/tool_policy.py`)。

### 4.4 护栏语义(建书/删书)
- `create_book` / `delete_book` 仍为 web-only 不进 MCP 面(护栏不变)。
- dsh 经 MCP 驱动 → **建书只能走 drive_ui 向导**(浏览器在场)或**需要你决策是否放松护栏**(待定 #2)。

| 双脑并存混乱 | 替换期间内置 agent 与 dsh 并存 | 明确停用内置 agent 的入口(侧栏开关/路由) |

## 六、待确认清单（2026-08-20 已定）

1. **侧栏对接形态**(§4.2):A(dsh web profile 作界面)还是 B(侧栏保留,后端换 dsh)? → **MVP 用 B 变体**:侧栏保留现有 UI,`/api/agent/chat` 后端按 `config.json agent.driver` 转发 dsh headless 子进程;dsh 的 web UI 嵌入(待定项②)后置独立立项(web profile 实测从未安装)。
2. **建书护栏**:dsh 替换后建书仍走 drive_ui 向导(浏览器在场)?还是放松护栏让 dsh 直建? → **维持护栏**(create_book/delete_book 不进 MCP 面,建书走向导),不放松。
3. **内置 agent 去留**:完全删除 `plugins/agent_loop.py`,还是保留作兜底/对照? → **保留文件加开关**(`config.json agent.driver="builtin"|"dsh"`),Phase 2 默认翻 dsh,内置 agent 仅经配置显式开启。
4. **会话/记忆**:dsh 自带会话持久化与 compaction,是否直接用 dsh 的,放弃 v0.4 的 `session_store` 设计? → **MVP 用「浏览器 history 拼任务文本」维持多轮**(与内置 agent 同构);dsh 会话持久化后置。
5. **v0.4 设计处置**:用户方向转向 dsh,v0.4 设计文档已删除;ToolPolicy/LoopGuard/BudgetGuard 概念在 Phase 1 落地为 `libraries/tool_policy.py` / `loop_guard.py`(BudgetGuard 未单独实现,由 `cost_tracker.py` 预算门控承接)。

## 七、硬约束（勿违反）

1. **护栏**:create_book/delete_book 不得回到 MCP 面;建书走向导、删书手动(除非待定 #2 明确放松)。
2. **确定性管线不重写**:6 阶段大纲 / 桥段写作照旧,dsh 只做决策点(经工具调批处理),不自由化管线。
3. **保持 `deepseek-v4-flash`** 及写作纪律;只优化 prompt/参数/免费规则层。
4. **不引重依赖**:除已装的 dsh(Node)外,Python 侧不新增 jsonschema/fastapi 等。
5. **数量文档**:改工具后同步 README/mcp_server/CLAUDE/设计文档的 43/40。
