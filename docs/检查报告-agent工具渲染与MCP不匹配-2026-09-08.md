## 1. Agent 运行 tool 的渲染流程（事件链）

全链路（每跳都已核对到文件:行）：

```
dsh headless 调工具 (mcp__novelengine__<tool>)
  → vendor/dsh-ne/events-runner.mjs 只转 tool/call、tool/result、(llm/call 调试)
  → libraries/dsh_bridge._map_dsh_event
       · tool/call：_short_name 去前缀存 pending[callId]={name,args}
       · tool/result：按 callId 取回 name/args → 产 tool_result
       · navigate/drive_ui：除动作事件外仍建工具卡（防 result 找不到卡 fallback 污染）
       · WS6 新增：save_plot_draft/save_chapter_text/save_outlines 成功后追加 domain 事件
  → run_dsh_flow → /api/agent/chat SSE
  → ui/static/js/agent_panel.js handleEvent
       · tool_call→addToolCardFor 建卡（usage 计入 token）
       · tool_result→按 callId 配对 finishToolCard；配不到即忽略（绝不 fallback 别的卡）
       · navigate→切页；ui_command→dispatchCommand 驱动向导
       · domain→window dispatchEvent('ne:desk-refresh') → 写作台立即 run()
       · 3s 轮询 /api/desk/chapters 保留为 fallback（storyline_write_flow.html）
```

- **历史回放**：task_events.jsonl 只持久化 `tool_call / tool_result / llm_call`（dsh_bridge run 循环 `_append_task_event` 过滤），重建路径两处（handleEvent/回放 forEach）都用 `seen[callId]` 去重。domain / navigate 不入库 → 刷新回放不含领域事件（设计如此，仅 live 触发写作台刷新，3s 轮询兜底）。
- **卡片渲染**：`TOOL_ZH` 中文映射（agent_panel.js:46），未知工具回退**原英文名**（:101 `TOOL_ZH[tool] || tool`）→ 不会崩，但可读性差。summary = 工具返回 JSON 文本经 `zhKeys` 美化；source=mcp（Claude 直连）只写 tool_log，不流式到写作台。
- **结论**：渲染链路**自洽、无结构性缺陷**；domain 事件是新扩展、已接好 live 刷新 + 轮询 fallback。

## 2. MCP 不匹配问题（核心发现）

### 2.1 【高】profile 小工具面 与 注入 skill 引用的工具不一致（profiles 默认开后生效）

事实基线：`libraries/agent_tool_router.PROFILE_TOOLS`（:7-24）定义每个 profile 暴露的最小工具集；`dsh_bridge._task_tool_profile` 按任务文本选 profile，**默认开**（`AGENT_TOOL_PROFILES` 未设即开，b8c100f）。dsh 每任务 spawn 的 mcp_server 带 `--profile <p>` → 只暴露该集。但注入的 skill 文本引用了一批不在集里的工具：

| profile（暴露工具） | 对应注入 skill | skill 引用但 profile **没有**的工具 | 后果 |
|---|---|---|---|
| `write`（6）= get_writing_context / get_pen_style / pick_plot_sample / save_plot_draft / save_chapter_text / chapter_quality_gate | novel-story | **get_book_state、get_storyline、get_book_detail、validate_storyline** | 写正文第一轮（skill 前置 `get_book_state(book_id)`）即调不存在工具 → unknown tool，**写作 run 卡死/失败** |
| `build`（9）= get_build_status / drive_ui / query_arc_library / query_plots / query_profiles / query_gags / query_characters / validate_storyline / validate_world | novel-build | **navigate、list_books、get_book_detail** | 建书后收尾查相位（get_book_detail）与需 navigate 时不可用；步 3 主体工具齐全 |
| `build-candidates`（4） | novel-build-candidates | —（navigate/drive_ui/get_build_status 齐） | 基本吻合 |
| `replan`（7） | novel-replan | —（get_story_state/drive_ui/save_outlines/query_*/validate_* 齐） | 基本吻合 |
| `publish`（6） | novel-publish | —（get_book_detail/save_book_meta/publish_* 齐） | 基本吻合 |
| `scout`（11） | novel-scout | — | 基本吻合 |

- **触发条件**：profiles 默认开（本会话提交的 b8c100f 把默认值改为开）。`AGENT_TOOL_PROFILES=0` 回 legacy 全量 45 可逃生，但默认路径会被 2.1 咬住。
- **前端表现**：unknown 工具会以 raw 英文名/错误卡出现（TOOL_ZH 无映射），业务已断；渲染层无措。
- 佐证：novel-story SKILL 前置 `get_book_state(book_id)`；novel-build SKILL 收尾 `get_book_detail(book_id)`；write=6 / replan=7 与 `tools/test_mcp_profiles.py` 期望一致（不是测试错，是集本身小）。

### 2.2 【中】双份契约漂移：NOVEL_AGENT/docstring/CLAUDE 工具清单未随 profile 过滤同步
- NOVEL_AGENT §1.2 仍罗列全量落盘工具；本会话新增的可选参数（`save_plot_draft(outcome/expected_facts/run_id/based_on_storyline_revision)`、`save_chapter_text(planning_patch/expected_revision)`、`save_basic_info(expected_revision)`）**未补进 NOVEL_AGENT §1.2 / 相关 skill 契约** → 写作 agent 未必知道能传 structured outcome / planning_patch。

### 2.3 【低】服务名不一致但已被兼容（非 bug）
- dsh overlay：`serverName=novelengine` → 工具前缀 `mcp__novelengine__*`；Claude `.mcp.json`：`novel-engine` → `mcp__novel-engine__*`。`dsh_bridge._short_name` 兼容两种前缀；两侧各自进程、互不干扰。留意勿混淆即可。

### 2.4 【低】domain 事件不入 task_events
- 刷新后回放不含 `chapter_changed/plot_run_changed/plan_committed`，写作台不会因「历史回放」触发即时刷新；但 3s 轮询兜底仍工作，live 会话已即时。可接受。

### 2.5 无工具数不匹配
- `TOOL_REGISTRY` 实收 45 == `tools/mcp_smoke.py EXPECT_MCP_TOOLS` 45；mcp_smoke 58/58、test_mcp_profiles（write=6/replan=7）通过 → 工具面数量与注册一致，未新增未删（与 2.1 的「集偏小」是两回事）。

## 3. 建议（按优先级）

1. **给主链 profile 补「前置读/导航工具」或改 skill 只用 profile 内工具**：
   - 最优：`novel-story` 前置改用 `get_writing_context`（**已在 write=6**，且返回 book/storyline/phase/next_plot/planning，够做前置判断），写作路径尽量只用 write 内工具 → write 集可保持小；
   - `build`/`build-candidates`/`replan`/`publish`/`scout` 补共享 CORE：`navigate / list_books / get_book_detail / get_book_state / get_storyline`（必要时）——做成 `agent_tool_router` 里每个 profile `| CORE`，一处维护。
2. **加护栏测试（防回归）**：解析每个 `agent-sidecar/skills/*.md` 引用的工具名（含 mcp__ 前缀/裸名），断言其 ⊆ 对应 profile（`novel-story→write` 等）暴露集；缺则测试失败。这样 2.1 类回归在提交时即暴露。
3. **skill/NOVEL_AGENT 与 profile 同步**：NOVEL_AGENT §1.2 补本轮新增可选参数契约；skill 文本尽量只用本 profile 工具，少引全量工具。
4. **保留逃生与文档**：`AGENT_TOOL_PROFILES=0` legacy 全量；README 说明默认 profile-on + 逃生开关。

## 4. 结论

渲染链路（MCP→dsh_bridge→SSE→agent_panel 卡片/导航/domain 刷新 + 回放去重）**自洽**；数量与测试一致。**实质问题是 MCP 的 profile 最小工具面与注入 skill 引用的工具不匹配**，在「默认开 profile」后真实咬住 `write`（novel-story 前置 get_book_state）与 `build`（get_book_detail/navigate）两条主链——这是当前最值得先修的 MCP 不匹配。建议按 §3.1/§3.2 修复并加护栏测试；随后真机 dsh 实跑（起 58080 + 真实对话）做收尾验收。
