## 一、当前 agent 架构（一句话）

**侧栏聊天 / 建书向导按钮 → `libraries/dsh_bridge.py` 起 dsh-ne headless 子进程（事件流版）→ `vendor/dsh-ne/events-runner.mjs` 把每个工具调用逐事件写 NDJSON → `dsh_bridge` 逐行实时转 SSE → 前端工具卡/导航/向导命令。全服务单任务（新任务打断旧任务）。启动新书经 novel-build skill 全流程 agent 驱动（步 1→2→3）。**

```
浏览器（侧栏 / 建书向导按钮）
  → POST /api/agent/chat（或「🚀 让 Agent 构建」→ agentSendTask）
  → run_dsh_task：interrupt_current_task() 打断旧任务 → Popen node vendor/dsh-ne/lib/bin.js
  → events-runner.mjs 监听 session/event，tool/call·tool/result 逐行 NDJSON
  → _map_dsh_event 转 SSE（tool_call/tool_result/navigate/ui_command/reply/error/done）
  → 前端 handleEvent：callId 配对工具卡、实时导航、dispatchCommand 驱动向导
```

**护栏链**：系统工具已禁（`~/.dsh/profiles/headless/cordis.patch.yml` disabled ~30 个，只留 MCP+skills+联网）→ phase 门控 `tool_policy.py` → MCP 循环熔断 `loop_guard.py` → 建书 reset + 保真度校验 → 全服务单任务打断。

## 二、本次批次做了什么

### 2.1 事件流实时推送（原并行会话起，本批收尾落地）
- `vendor/dsh-ne/events-runner.mjs`（新）：替换 `headless-runner`（原 summarize 只打印最终文本），监听 `session/event` 把 `tool/call`/`tool/result` 逐事件写一行 NDJSON；收尾补 reply/done/error。挂载：运行期 overlay `--patch` 禁 headless-runner + insert events-runner（`file:///` 绝对 URL）。
- `libraries/dsh_bridge.py`：`Popen` + 双线程（stdout 读 / stderr 读）逐行读 NDJSON → `_map_dsh_event` 实时转 SSE；`pending` 字典按 callId 配对 tool/result 补工具名。
- `agent_panel.js`：`addToolCardFor`/`finishToolCard`/`toolCards`（callId 配对）+ `busy` 期间暂停 nav-intent 轮询（防双触发）+ done 时 drain nav-intent 残留（C1 修复）。
- 效果：浏览器不再靠 2.5s/3s 轮询补实时感，工具进度/导航/向导命令实时推送。外部 Claude Code 仍走 nav-intent 轮询兜底。

### 2.2 启动新书步 1-2 改 agent 驱动
- `start_book.html`：**移除前端固定候选管线**（`loadCandidates` fetch `/api/world-builder/candidates`）；步 1 主按钮「🎲 生成候选」→「🚀 让 Agent 构建」。
- 按钮收集 idea/tags/笔名 → `window.agentSendTask(task, {card:true})` → 右侧显示「🚀 建书任务」卡片（非用户气泡，任务文本仍进 history 供 SSE）。
- agent（dsh-ne + novel-build skill）走路线 B：`world_candidates` → `drive_ui(pick_candidate)`（注入渲染卡片）→ `drive_ui(next)` 驱动步 1→2→3。
- **步序 bug 修复**：skill 补「步 1→步 2 的 `drive_ui(next)`」（此前缺，导致浏览器停步 2 候选卡而 agent 误进步 3）；补 `skip_candidates` 路径；②④ 加「一次查够、选定即停」防重复查询；显式「dsh 是 Web 进程内子进程，无需平台启动」。

### 2.3 全服务单任务打断
- `dsh_bridge.py`：模块级 `_current_proc` + `interrupt_current_task()`（Windows `taskkill /F /T` 杀整树——node 会 spawn python mcp_server 子进程，`Popen.kill()` 只杀父进程会留孤儿）。
- `run_dsh_task`：启动前打断旧任务（单任务语义）；`finally` 反注册 + 收尸（解决孤儿进程 + 客户端断连 GeneratorExit 兜底）；被打断/崩溃且无 done 事件 → error+done 收尾（前端 busy 复位）。
- `agent.py`：`POST /api/agent/chat/cancel` 幂等端点。
- `agent_panel.js`：`window.agentSendTask` 在 busy 时先 cancel 再排队（`pendingTask`，done 后接力）。

### 2.4 get_build_status 建书状态工具
- `libraries/build_status.py`（新）：`storage/build_status.json` 持久快照（`set_build_status`/`get_build_status`）。
- `agent.py`：`POST /api/agent/build-status` 接收浏览器上报。
- `agent_tools.py`：`get_build_status()` 只读 MCP 工具（注册，无锁/无门控）→ **工具数 40→41**。
- `start_book.html`：`WZ.reportStatus()` 在 `show()`/建书成功/每条 onnecommand 命令后上报（cur/bookId/_picked/has_world/has_picks）。
- 作用：`drive_ui(submit)` 非阻塞，agent 用 `get_build_status` 拿 book_id → `get_book_detail` 校验（skill A4 已接入）。

### 2.5 附带（并行会话 + 本批收尾）

## 六、已知边界 / 坑

- **打断是 kill 整树**（`taskkill /F /T`）：打断长工具（generate_full_outline 阻塞数分钟）会丢掉已产出但未落盘的中间结果（管线逐步落盘，可重跑续接）。
- **busy 只在前端内存**：服务端无权威 busy 状态；单任务语义由 `run_dsh_task` 启动时 `interrupt_current_task()` 保证（新请求打断旧 proc）。
- **build_status.json 残留**：`reset` 会清 bookId；建书成功 `created=true`。若残留误导，删 `storage/build_status.json` 即可。
- **events-runner 与 headless-runner 互斥**：运行期 overlay 禁 headless-runner；手动 CLI 不加该 patch 仍是纯文本，两侧互不干扰。
- **文档数量口径**：工具数 41（MCP 面全量，无 web/mcp 分离）；改工具后同步 `README`/`CLAUDE.md`/`架构总览`/`mcp_smoke`。
