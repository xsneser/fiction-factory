## 一、系统一句话 + 分层与进程

**NovelEngine 是「可视化、外部 agent 可驱动的多阶段小说创作平台」。** 创作大脑（决策/生成）在平台**之外**——Claude Code 或侧栏 dsh headless——经 **MCP stdio** 调一套**薄工具面**驱动平台；平台只负责存数据 + 跑**免费规则**（去 AI 味/审查/门禁/台账/选择器），生成类 LLM 工作全在 agent 侧完成。

```
┌─ 驱动方（大脑，平台外）─────────────────────────────────────┐
│  Claude Code（交互式） · 侧栏 dsh headless（vendor/dsh-ne 子进程）│
└──────────────┬─────────────────────────────────────────────┘
               │ MCP stdio：mcp__novel-engine__*（45 个；可按任务 profile 裁剪）
        ┌──────▼────────┐          ┌──────────────────────────┐
        │ mcp_server.py │          │ Web 服务 Flask 58080      │
        │ FastMCP stdio │          │ ui/web_ui.py 壳 + 蓝图群   │
        └──────┬────────┘          └───────────┬──────────────┘
               │       agent_tools.py TOOL_REGISTRY（唯一工具源） │
               │   护栏：PHASE_GATES / BookLock / LoopGuard / nav-intent │
               ▼                             ▼
   ┌────────────────────────────────────────────────────────────┐
   │ libraries/ 引擎 + 四库模板 + 规则层   books/ 真实书数据       │
   │ libraries/data/{structures,plots,gags,characters}.jsonl     │
   │ storage/ 运行时缓存                                          │
   └────────────────────────────────────────────────────────────┘
```

**双进程并存**：Web 进程（Flask 58080）与 MCP 子进程各自独立 import ctx，靠 `books/` 文件 JSON + `storage/` 运行时缓存协调；写工具带书级锁（`BookLock`），冲突抛 `BookBusyError`。

| 层 | 实现 | 形态 |
|---|---|---|
| Web 服务 | Flask 3 + Jinja2，`ui/web_ui.py`（壳）+ `ui/web_blueprints/`（蓝图群，含 ctx 共享模块） | 58080（`launch.bat` 拉起，自动开浏览器） |
| MCP 适配 | `mcp_server.py`（FastMCP stdio），`_wrap_logged` 落工具日志 | stdio 子进程 |
| 工具注册表 | `agent_tools.py` `TOOL_REGISTRY = _build_registry()`；schema 从类型注解自动生成 | 唯一工具源，薄工具面 |
| 侧栏大脑 | `libraries/dsh_bridge.py` 转发 `vendor/dsh-ne/` headless 子进程（内置 agent `plugins/agent_loop.py` 已删除，无 builtin 可切回） | 一次性子进程，见 §七 |
| 规则引擎 | `libraries/engine.py` / `storyline.py` / `de_ai.py` / `reviewer.py` / `promise_ledger.py` / `style_samples.py` 等 | 免费规则/数据层 |

## 二、双通道驱动

`navigate` / `drive_ui` **无条件**写意图队列（`libraries/nav_intent.py` → `storage/nav_intent.json`，TTL 30s，取即清空）；浏览器据此切页 / 驱动建书向导。

| 通道 | 机制 | 消费方 | 延迟 |
|---|---|---|---|
| dsh 事件流（SSE，主通道） | `vendor/dsh-ne/events-runner.mjs` 把每个 tool_call/result 逐事件写 NDJSON → `dsh_bridge` 实时转 SSE（tool_call/tool_result/navigate/ui_command/reply/done） | 侧栏实时工具卡 + 零延迟导航 | 实时 |
| MCP 意图队列（轮询兜底） | 外部 MCP 客户端（Claude Code 等）无 SSE 通道 → 浏览器每 ~2.5s 轮询 `/api/agent/nav-intents` 消费 | `window.onnecommand` 单槽位 | ~2.5s |

- `ui_command`（drive_ui）白名单 `_WIZARD_CMDS`：set_field/set_tags/set_characters/set_candidates/add_candidate/pick_candidate/set_world/set_picks/set_outline/next/prev/load_candidates/skip_candidates/fill_world/reset/submit。
- 建书向导 `ui/templates/start_book.html` 的 `window.onnecommand` 接收 `ne:command`（canvas 事件已随内置 agent 删除）。切页与读数据是两回事：用户要「打开页面」须 `navigate`，即使已用 `get_book_state` 读过数据。

## 三、共享工具注册表与护栏

**唯一工具来源**：`agent_tools.py` 的 `TOOL_REGISTRY = _build_registry()`。注册方式：`_build_registry()` 硬编码函数列表，逐个包成 `{name, description, input_schema, func}`；schema 从类型注解 + `inspect.signature` 自动生成；`required` = 无默认值参数。

**工具数**：以 `_build_registry()` 实收为准（当前 45，`tools/mcp_smoke.py` `EXPECT_MCP_TOOLS` 同步维护）；每项同时携带 profile、读写、副作用、phase、锁及前置条件元数据。未指定 profile 时保持完整工具面，显式 profile 时由规则路由器裁剪。

**护栏（纵深，不可绕）**：

1. **直建/直删工具不在工具面**——建书必须 `navigate("/books/start")` + `drive_ui` 驱动「启动新书」向导，由系统 `POST /books/start` 建；删书走书库页手动。这是平台对「外部 agent 越权」的最终兜底，非靠 LLM 自觉。
2. **phase 翻 `ready` 无任何 agent 工具**——ready 恒由用户动作触发（正常=向导点提交；config 兜底=书详情「确认弧+情节段」）。
3. **书锁** `BookLock`（`libraries/book_lock.py`）：写工具被包书级锁，冲突抛 `BookBusyError`（30s 超时）；锁文件不删（防 TOCTOU）。
4. **阶段门控** `PHASE_GATES`（`libraries/tool_policy.py`）：按 `storyline.phase` 拒越权工具。
5. **MCP 循环熔断** `LoopGuard`（`libraries/loop_guard.py`）：近 5 步同 `(tool, args_digest)` ≥3 次且结果摘要不变 → 熔断；连续 ≥5 次失败 → 熔断；`NOVEL_DISABLE_LOOP_GUARD=1` 逃生阀。
6. **dsh 自带系统工具禁用**（headless profile `disabled: true` ~30 个，只留 MCP + skills + 联网，防绕过护栏直操文件）。

**工具功能簇**（现行薄工具，供导航；完整清单以注册表为准）：
- 只读/书与线：`list_books` / `get_book_detail` / `get_book_state` / `get_storyline` / `get_writing_context`（一次读写作全上下文，薄）/ `get_build_status`
- 规划/落盘：`save_basic_info` / `save_outlines` / `save_book_meta`
- 弧/段选材：`query_arc_library` / `arc_material_candidates` / `query_plots` / `query_gags` / `query_characters` / `query_profiles`
- 写作：`save_plot_draft`（逐情节段草稿）/ `save_chapter_text`（整章落盘 + 规则副作用）
- 校验/门禁：`validate_storyline`（覆盖/叶弧/内联）/ `validate_world`（势力/人物）/ `chapter_quality_gate`（五项聚合）
- 风格：`get_pen_style` / `pick_plot_sample`（Plot Run 单篇样文）/ `get_style_sample` / `add_style_rule` / `add_style_sample` / `delete_style_rule` / `delete_style_sample`
- 上架：`publish_check` / `publish_book` / `mark_finished` / `export_book`
- 侦察/提取：`discover_hot` / `list_rankings` / `fetch_novel` / `fetch_webnovel` / `fetch_book` / `list_crawled_novels` / `read_crawled_novel` / `extract_state` / `judge_extraction` / `ingest_library_assets`
- 导航/向导：`navigate` / `drive_ui`（both，写意图队列）

## 四、阶段与 skill 分发

**阶段状态机**：`storyline.phase ∈ config / outlines / plots / ready`（`gags` 已废弃残留于注释）；`book.status ∈ planning / writing / reviewing / finished / published / paused`。

| 阶段 | dsh skill | phase 前置 | 出口 | 主要薄工具 |
|---|---|---|---|---|
| 建书 | `novel-build-candidates` → `novel-build` | 无书 / config | 向导点提交即 `ready` | drive_ui(set_candidates/set_world/set_characters/set_outline) / validate_storyline(内联) / query_arc_library / query_plots |
| 弧+写作 | `novel-story` | `ready`（config/plots 为补弧兜底） | 章节/情节段写完 | save_outlines / save_plot_draft / save_chapter_text / chapter_quality_gate / pick_plot_sample |
| 上架 | `novel-publish` | 已有第 1 章 | published / finished | publish_check / publish_book / mark_finished / export_book |
| 侦察/提取 | `novel-scout` | — | 模板进四库 / 风格进笔名 | fetch_* / discover_hot / read_crawled_novel / extract_state / judge_extraction / ingest_library_assets |

- **skill 分布**：dsh 侧 5 个 skill 定义在 `agent-sidecar/skills/novel-*/SKILL.md`（2026-08-28 重写完成，`.dsh/skills/` 为其 gitignored 发现镜像，改后须手动 `cp` 同步）。Claude Code 侧 `.claude/skills/`（`novel-master` 统一调度 + 分 skill）独立演进，交互式 `novel-build` 与 dsh 侧不做镜像。
- **阶段 profile 由服务端定，任务文本只兜底**（2026-09-10）：写作用 `_writer_fsm`、建书用 `_build_fsm`（配 `libraries/build_flow.py`）。建书阶段由 `_build_fsm` 读向导快照（`build_status.cur` → BUILDING/STAGING）决定起 `build` 还是 `build-candidates`——**不靠中文关键词判阶段**。关键词只用于未分类任务的兜底；且完全命不中时**显式报错 + 列阶段入口**，不再静默回落到只读面（见 §十.13）。
- **向导快照 `storage/build_status.json` 的内容**（浏览器每次命令/切步后上报，`libraries/build_status.py`）：步骤与进度布尔（`cur`/`created`/`_picked`/`has_world`/`has_outline`/`submit_error`…）之外，**还带表单 `idea`/`tags`**——提交前服务端**只有这一份**表单快照（书要等用户点提交才创建），agent 生成候选时若任务文本没带全就靠它（见 §十.17）。
- **意图 → skill 分发**：拿不准阶段 → 先 `list_books` + `get_book_detail` 看目标书 `phase` 再定 skill；书多先问「对哪本书操作」。
- 写作类工具带书级文件锁，冲突抛 `BookBusyError`，稍后重试；`budget_paused` = 预算/额度触发，停下问用户。

## 五、建书与深化：步 3 深化式构建 → 提交即 phase=ready

**现行新书故事线流（2026-09-05 起）**——深化与步 3 生成是**一件事**，submit 后不再单独深化：

```
navigate("/books/start") → 步1-2 表单/候选（novel-build-candidates 呈现候选，停在步2 等用户挑选）
  → 步3「内容构建工作台」深化式构建（novel-build）：
      差异化命题：core_conflict(最核心一条) + world_building.differentiation(全量论述) 随 set_world 内联落库
      → 势力 → 弧+情节段（每弧 notes =「本弧目标 + 偏离库模板 X 的点」，drive_ui(set_outline) 落表）
      → 人物 → 其余维度
      → 内联 validate_storyline(outlines/plots) + validate_world(basic_info) 回打 ≥1 轮直到 passed=true
      → 汇报故事线蓝图
  → 用户在向导点「提交建书」（agent 不调 submit）
  → dashboard.start_new_book：fill_themes_and_hooks + annotate_plot_roles + 有 plots → phase=ready
  → novel-story 写作解锁（无书详情二次确认、无后置深化段/按钮）
```

- **config/补弧兜底**（弧没带上/遗留恢复）：submit 落 `config` → agent 自主生成 outlines/plots（含 notes）经 `save_outlines` 落盘 → phase=plots → 用户在书详情点「✅ 确认弧+情节段」（`/api/book/<id>/confirm-storyline`，保留为 legacy 恢复端点）→ ready。
- **已 ready 书续写/扩写追加弧**经 `save_outlines` **保持 ready**（不降级）。
- **ready 恒由用户动作触发**（正常=向导提交；兜底=书详情确认）；agent 无 fill_gags/confirm_outlines 等翻 ready 工具。

## 六、写作闭环与 Plot Run（现行：一次性 Plot Writer + 服务端 FSM）

情节段是正文写作的最小单元，章是后处理分组（写到目标字数即「章满」落盘；字数是权威轴、章号是兼容视图）。
**流程状态不由模型掌握**：Writer 只能 prepare 一次、save 一次、然后停；收章/门禁/续规划交接全在服务端。

```
侧栏任务 → POST /api/agent/chat → libraries/dsh_bridge.run_dsh_flow
  ├─ 意图=build / build-candidates → _build_fsm(session_id)   dsh_bridge.py:_build_fsm
  │     阶段读向导快照（build_flow.next_action：cur/created/submit_error）→ 起对应 profile 的
  │     子 run（cur≥3 → build；cur≤2 → build-candidates）→ 停下等用户挑选/自己点提交；
  │     一轮只派发一个子 run，连败超上限显式失败（不空转烧会话）
  │     **子 run 收「调用方原文 + history + 追加的阶段提示」——与 Writer 相反，不做薄任务**：
  │     idea/题材标签/「已选定候选「书名」」只在向导拼的任务文本里（服务端无副本），
  │     换掉文本=丢数据（曾因此让候选生成与用户标签完全无关）
  └─ 意图=write → _writer_fsm(book_id)                        dsh_bridge.py:_writer_fsm
       每轮先从磁盘判动作（write_flow.chapter_status → next_action），**先判后 spawn**：
         ├─ 章满（草稿字数 ≥ words_per_chapter）→ finalize_draft_chapter
         │     save_chapter_text（不可回退：落章 → 计量 → 标 written_chapter → revision+1 → 增强副作用）
         │     → chapter_quality_gate（**提交后诊断**，异常只标 skipped 不改「章已提交」）
         │     → flow DONE + 释放写作租约
         ├─ 已承诺情节段耗尽且到边界 → spawn 计划器(profile=replan) → replan_preview → auto 原子提交
         │     （REPLAN_POLICY=confirm 则停在 WAIT_CONFIRM 等用户在故事线面板确认）
         └─ 否则 → spawn 一次性 Writer 子 run(profile=write，仅 2 个工具)

Writer 子 run（每段一个子进程，环境注入 book/flow/child 身份）：
prepare_plot_run(book_id)                                     agent_tools.prepare_plot_run
   服务端组装输入快照 + 签发 commit_token：
     execution（本段 plot + 执行简报/弧目标/章内进度）、previous_change、
     cast（角色分级卡 + staged 事实投影）、memory（预算内近段 + 检索长期记忆）、
     horizon（下一段/边界/chapter_status）、thread（线程态）、
     style（style_card + **恰好 1 篇**随机样文 + style 快照）、
     run.context_version_vector（故事线版本/草稿/staged/角色态/planning/记忆/风格/样文指纹）
   ▼  agent 按快照写本段正文（去 AI 味在落盘侧做）
save_plot_draft(commit_token, text, plot_summary, outcome=?, character_events=?)
   校验令牌身份/版本向量/样文指纹（陈旧即拒，要求重新 prepare）→ 落 draft_chapter.json
   → reconcile（predicted expected_facts vs 实际上报 facts）→ stage_delta 进 staged 事实台账
   → accept 令牌（幂等：同令牌重放返回同一结果；崩在 stage/accept 之间可按草稿桥确定性补齐）
   → Writer 子 run 结束（模型不再继续决策）
```

- **Writer 契约恒为两个工具**（`prepare_plot_run` / `save_plot_draft`，见 `libraries/agent_tool_router.py` 的 `PROFILE_TOOLS["write"]`）：样文/风格/上下文全由服务端解析，模型不选材、不读文件、不跑门禁。
- **提交路径自持书锁**：`save_plot_draft` 签名里只有 `commit_token`，锁包装器取不到书号，故在函数内解析出归属书后显式 `BookLock`（归属书由服务端经 `NOVEL_WRITE_BOOK_ID` 注入，O(1) 定位令牌账本）。
- **令牌账本有界**：每段签发一条（含 7–11 KB 原始快照），已接受记录压缩为结果+身份并设保留窗口/上限，过期未用与吊销记录回收——不回收会随情节段数线性膨胀。
- **角色行为注入（2026-09-07）**：三层分工不混——`cast` 决定**谁在写**（behavior 定情境→一贯反应、speech_profile 定语言倾向、dyn 是前文演进结果）、`execution`/`horizon` 决定**写什么**、样文+style_card 决定**怎么写**。人物变化走事件驱动：agent 按情节段 `character_events` 上报 → `CharacterStateMachine` 纯规则落账（白名单映射 + 事件台账，mood/secret 等推断字段禁 agent 直写）。
- **结构认知**：Storyline 不是 事件弧/线程/角色弧 三个同级轴，而是分层——外部结构(Arc)/叙事记忆(Thread)/人物演化(Character Evolution，事件驱动、层级较低)；人物成长方向以 `basic_info.characters[].development_plan` 挂人物卡（观察门），暂不设 Storyline 角色弧集合/UI 泳道。
- **续规划（replan）**：边界由 `planning_state.detect_story_boundary` 纯函数判（剩余情节段 ≤ 阈值 或 承诺余量 ≤ 一批），阈值与计划器单批大小同源（`REPLAN_BATCH_MIN/MAX`）；预览经 `drive_ui(set_replan_preview)` 暂存，UI `commit-plan` 与 auto 编排共用 `replan_service.commit_replan_preview` 原子提交（storyline + planning_state 同边界、revision CAS）。
- **历史路径**：`get_writing_context` / `get_pen_style`(写作面) / `pick_plot_sample`(独立入口) / 旧位置参数版 `save_plot_draft` / `save_chapter_text`(agent 面) 均已不在写 profile 工具面；引擎内置流式写章路径（`storyline_writer.py` + `prompt_harness.render_bridge_prompt`）与 `desk.py` 三个 `storyline-engine` SSE 端点同为历史/参考，现行写作路径即上图。

## 七、dsh 侧车架构（侧栏大脑）

> 决策背景：2026-08-20 用户拍板用 dsh 核心完整替换内置 agent（`plugins/agent_loop.py` 已删，无 builtin 可切回）。先行的 dsh 侧车 spike 结论为「可用但有 3 摩擦点」，方向与用户拍板相反（spike 文档已删，3 摩擦点由 §四 护栏 + §十 坑 承接）。

**一句话**：浏览器侧栏 / 建书按钮 → `libraries/dsh_bridge.py` 起 dsh-ne headless 子进程 → `vendor/dsh-ne/events-runner.mjs` 把每个工具调用/结果逐事件写 NDJSON → 实时转 SSE → 前端工具卡/导航/向导命令。全服务单任务（新任务打断旧任务）。

- **引擎（vendor 进项目）**：`vendor/dsh-ne/` = dsh 0.1.0-rc.7 源码副本改名防冲突；`libraries/dsh_bridge.get_dsh_argv()` 用 `node vendor/dsh-ne/lib/bin.js` 直启（绕开 Windows `.CMD` shim 中文转码坑），不依赖全局安装；node_modules 不入 git（`npm install` 重建）。
- **headless profile（用户态，不入库）**：`~/.dsh/profiles/headless/`。`cordis.patch.yml` 挂 `@deepseek-ai/dsh-mcp-client` → `python mcp_server.py`；`toolCallTimeoutMs: 600000`（**务必 ≥600000**，长工具阻塞数分钟不被 MCP 掐断）。headless 是 one-shot（答一个任务即退出）。
- **事件流（主通道）**：headless 原 runner 用 `summarize` 丢弃中间事件；注入 `vendor/dsh-ne/events-runner.mjs`（运行期 overlay `--patch` 禁 `headless-runner` + insert 本插件，模板 `agent-sidecar/events-runner.yml`），`session/event` 里每个 `tool/call`/`tool/result` 写成一行 NDJSON → `dsh_bridge` 实时转 SSE。工具日志双源：外部 MCP `source="mcp"` 写 `storage/tool_log.jsonl`；dsh 内部调用 `source="dsh"` 不写 JSONL（工具日志页签 filter source=mcp）。
- **全服务单任务打断**：`dsh_bridge` 模块级 `_current_proc` + `interrupt_current_task()`（Windows `taskkill /F /T` 杀整树）；`run_dsh_task` 启动前打断旧任务、`finally` 收尸；`POST /api/agent/chat/cancel` 幂等；前端 `agentSendTask` busy 时先 cancel 再排队。
- **dsh 自动读根目录 `CLAUDE.md`**（dsh-agent-instructions）——根 CLAUDE.md 内容即 dsh 指令。系统工具（文件/shell/子代理/联网）默认暴露、无 sandbox，已在 headless profile 批量禁文件/shell/子代理等，只留 MCP + skills + 联网。

## 八、故事线数据模型（弧 / 情节段 / 线程）· 摘要

> 深度数据模型/术语表/硬规则细节见 **`docs/架构与故事线模型-情节弧情节段关系.md`**（2026-09-06，现行独立件）。本节只给要点，防架构文档膨胀。

**核心前提（三轴正交，勿混为一谈）**：库（模板）与书（实例）是两层；弧与情节段是**一根字数轴上的粗细两档**；线程是**横向贯穿的另一根轴**。

- **弧（情节弧）= 树状目标节点**：书内实例 `OutlineSlot` 用 `parent_arc_id` 连成弧树（顶层弧=不被其他弧包含；可多层嵌套，层数/数量由剧情结构决定，不设固定值）。弧 `start_word/end_word`（0 基，start 含 end 不含）为落盘权威轴；章号为兼容视图。
- **弧字数跨度 = 所含情节段 `words` 之和**，**不由章数 / words_per_chapter 决定**（反「印刷感」）：叶弧不要求=1 章（9000 字叶弧≈3 章正常）、同父下子弧跨度不必相等；第三层仅在块内 2+ 可独立排序子目标且块 ≥3×words_per_chapter 时拆。
- **情节段（Plot）= 弧内可执行剧情节拍**：实例 `PlotSlot` 挂 `outline_id`（**仅最底层/叶弧可拥有情节段**，硬规则）+ `thread_id`（线程）。字数按内容浓淡给 300~2500（过渡/日常 300-600、常规推进 800-1600、关键转折/高潮 1800-2500），**同弧/全书不要全部相等**；未给 `words` 回退 `cover_beats×200`。`written_chapter` 是断点续写依据。
- **库层 = 平级独立弧模板** `ArcNode`（无父子、每行一个可复用弧，2026-09 起平级化）与情节段模板 `PlotTemplate`；书层实例带 `template_id` 回指模板。实例化两条路径：agent 自主生成（现行）→ 落盘；规则引擎兜底（`StorylineBuilder`）→ 参考。
- **两条硬校验**（`validate_storyline`）：① 顶层弧完整覆盖故事线纵轴（无叙事空白）；② 情节段仅挂最底层弧（叶弧）。
- **线程/设局收局**：`threads[]`（主线/副线/伏笔线…）跨弧贯穿；埋伏笔情节段（`resolves_plot_id` 空）→ 收局（`resolves_plot_id` 指回）生命周期进 `promises[]` 台账（pending→advanced→fulfilled，逾期产生决策点）。

## 十、常见坑

1. **cordis.patch.yml 是 patch 层**：新增条目用 `insert`（不带 id）；profile 的 `cordis.yml` 是硬编码空根，别编辑它；id-targeted override 是整体替换 config（非深合并），给全 config（`dsh_bridge._write_runtime_overlay` 已处理）。
2. **dsh `.CMD` shim 中文乱码**：`subprocess.run(["dsh", 中文任务])` 经 cmd.exe ANSI 转坏；用 `get_dsh_argv()` 反推 `node <npm路径>\node_modules\@deepseek-ai\dsh\lib\bin.js` 直启（Node 经 CreateProcessW 收 UTF-16）。
3. **BookBusyError** = 另一进程在操作同书，稍后重试；锁文件不删。
4. **nav_intent TTL 30s**：意图过期即丢，驱动 UI 要在 30s 内消费；`navigateTo` 有同 path 去重。
5. **Windows 控制台 GBK**：脚本打印中文加 `sys.stdout.reconfigure(encoding="utf-8")`。
6. **flash max_tokens 余量**：流式生成 max_tokens 必须 ≥8192（推理余量），否则 content 为空解析必败；长工具阻塞数分钟，`toolCallTimeoutMs` 必须 ≥600000。
7. **重启杀净 58080**：`netstat -ano | findstr :58080` 全部 PID 杀净，否则旧进程「改动不生效」假象（`launch.bat` 可见独立终端，可随时关窗停服）。
8. **四库单例**：改 `libraries/data/*.jsonl` 必须重启服务才生效。
9. **测试/脚本会动数据**：`books/`、`profiles/` 是真实数据别删；删除类操作无回收站，先确认（直删工具不在工具面，删书走书库页手动）。
10. **dsh 自带工具默认会绕过 MCP 护栏**：已批量禁文件/shell/子代理等；禁依赖服务的插件（workflow-worker-thread/permission/command-goal）需一并禁，否则报 pending 未激活。
11. **`.dsh` 目录 gitignored**：改 `agent-sidecar/skills/*` 后需手动 `cp` 到 `.dsh/skills/` 同名文件（dsh 运行期从 `.dsh/skills/` 发现根读）。
12. **工具结果可能被 dsh 裁剪**（>8KB 只留头尾）：大载荷不能让模型代传，MCP 工具应服务端直推 nav_intent 或让前端轮询读；信息不足时用独立薄工具复读。
13. **空 profile = fail-open 到全量 45 工具**：MCP 侧 `filter_registry("")` 直接返回整个注册表（`agent_tool_router.py` 的 `if not profile: return registry`）。所以「未分类」绝不能让空值流到 `--profile`——`dsh_bridge._resolve_run_profile` 在 profiles 开启时**保证非空**（未知收敛到只读 `inspect`），面向用户的显式报错在 `run_dsh_flow` 那一层（拦在 spawn 之前）。改路由时别把这条绕过去。
14. **别按中文关键词判阶段**：建书两段的交接文本天然不可分（步 1 的任务同时含「候选」与「世界观」），曾因此把步 2→3 判成步 1-2 的 profile，而那个工具面没有 `set_outline`（`UI_COMMAND_POLICY` 拒收）→ 故事线在工具层就没有写入路径。阶段判定归服务端（`build_flow`），文本只作兜底；向导交接任务另带 `[build_session=…]` 机器标记，因为 `build_status.json` 是**全局单快照**，多开向导会张冠李戴。
15. **drive_ui 是异步的，不能阻塞等它落地**：命令只进 `nav_intent` 队列，浏览器每 ~2.5s 轮询后才应用到表单；而 58080 是**单线程** Flask——在 SSE 里 sleep 等快照刷新会把浏览器自己的 build-status 回报一起冻住，形成互等。所以服务端只报「已发起」，成效留到下一轮看（`_build_fsm` 的 attempts 记账）。
16. **skill 目录不受 MCP profile 约束**：目录由 dsh 自己的 skill 插件（`skill`/`skill-filesystem`/`tool-skill`）发现并注入。若不显式关掉，只读 profile 的 agent 也会看到 `novel-build` 等技能描述却没有对应工具（「被告知有这本事，却没有这工具」）。`_write_runtime_overlay` 对 writer 与「无 skill 注入的 profile」都会 disable 这三个插件。
17. **别用「薄任务」替换带数据的任务文本**：`_writer_fsm` 的薄任务是特例（Writer 的输入由服务端 `prepare_plot_run` 给）。建书/向导类任务的**表单数据只在任务文本里**——`build_status`（现含 `idea`/`tags`，见 §四）、`build_sessions`（planning 草稿）、`nav_intent`（30s TTL 且手填不走）都不是完整副本，`drive_ui` 的 18 个命令**也没有读回表单的**。替换文本会静默丢参数（踩过一次：候选与用户标签完全无关）。服务端只能**追加**阶段提示，且追加的文字里不出现工具名。
