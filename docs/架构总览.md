## 一、系统分层

| 层 | 实现 | 端口/形态 | 说明 |
|---|---|---|---|
| Web 服务 | Flask 3 + Jinja2，`ui/web_ui.py`（35 行壳） | 58080 | 10 个蓝图（`ui/web_blueprints/`），见 §四 |
| MCP 适配 | `mcp_server.py`，FastMCP stdio | stdio 子进程 | 注册 `surface ∈ {mcp,both}` 的工具，`_wrap_logged` 落工具日志 |
| 侧栏聊天后端 | `ui/web_blueprints/agent.py`（SSE `/api/agent/chat`） | Web 进程内 | 转发 dsh-ne headless 子进程，**唯一大脑**（内置 agent `plugins/agent_loop.py` 已删） |
| dsh-ne 引擎 | `vendor/dsh-ne/`（精简核心，改名防冲突） | 一次性子进程 | `libraries/dsh_bridge.py` 用 `node vendor/dsh-ne/lib/bin.js` 直启，经 MCP 客户端驱动平台工具，详见 §七 |

**双进程并存**：Web 进程与 MCP 进程各自独立 import ctx，靠 `books/` 文件 JSON + `storage/` 运行时缓存协调。**勿同时操作同一本书**（书锁保护写，见 §六）。

## 二、共享工具注册表与护栏

**唯一工具来源**：`agent_tools.py` 的 `TOOL_REGISTRY = _build_registry()`（L1171）。

- 注册方式：`_build_registry()` 硬编码 `fns` 列表，逐个包成 `{name, description, input_schema, func}`。schema 从类型注解 + `inspect.signature` 自动生成；`required` = 无默认值参数。
- **工具数：41 个**（无 web/mcp 面分离——surface 机制已随内置 agent 删除）。
- **护栏**：直建/直删工具不存在（无法经任何工具面调用）——建书走「启动新书」向导（`/books/start` POST），删书走书库页手动。

- **阶段门控**（Phase 1 新增）：`PHASE_GATES` 按 `storyline.phase` 门控工具，见 `libraries/tool_policy.py`。

**工具功能分组**（41 个）：
- 只读/建书：`list_books`/`get_book_detail`/`get_book_state`/`get_storyline`/`get_build_status`（建书向导进度）/`borrow_preview`/`query_*`（四库）/`outline_material_candidates`

## 三、导航/向导驱动（MCP 意图队列 + dsh 事件流双通道）

`navigate` / `drive_ui`（`agent_tools.py` L1030/L1072）**无条件**写意图队列 `libraries/nav_intent.py`（`storage/nav_intent.json`，TTL 30s，取即清空）。

- **dsh 会话内（实时，主通道）**：dsh 经 MCP 调 navigate/drive_ui 时，events-runner（`vendor/dsh-ne/events-runner.mjs`）把工具事件逐条推 stdout，`libraries/dsh_bridge.py` 实时转 SSE `navigate` / `ui_command` 事件 → 浏览器侧栏直接执行（`agent_panel.js` 在 busy 期间暂停 nav-intent 轮询消费，防双触发）。
- **外部 MCP 客户端（兜底）**：Claude Code 等无 SSE 通道，浏览器每 2.5s 轮询 `GET /api/agent/nav-intents` 消费 → `dispatchCommand`/`handleNavigate` → 页面 `window.onnecommand` 单槽位。

| 通道 | 消费方 | 延迟 |
|---|---|---|
| dsh 事件流（SSE） | 浏览器侧栏实时执行 | 实时 |
| MCP 意图队列（轮询兜底） | 浏览器每 2.5s 轮询 nav-intents | ~2.5s |

- `ui_command`（drive_ui）白名单 `_WIZARD_CMDS`（`agent_tools.py` L1058）：set_field/set_tags/set_characters/set_candidates/add_candidate/pick_candidate/set_world/set_picks/next/prev/load_candidates/skip_candidates/fill_world/reset/submit。
- 建书向导 `ui/templates/start_book.html` 的 `window.onnecommand`（L737）单槽位接收 `ne:command` 事件（canvas 事件已随内置 agent 删除）。
- **启动新书步 1-2 已 agent 驱动（2026-08-20，两 skill 拆分）**：前端固定候选管线（`loadCandidates` fetch `/api/world-builder/candidates`）已移除；步 1「🚀 让 Agent 构建」按钮收集 idea/tags/笔名 → `window.agentSendTask` 跑 **`novel-build-candidates`**（或侧栏「开一本新书」→ 先 `navigate('/books/start')` 翻到**步 1 表单**让用户填写，用户已给全则预填，点「🚀 让 Agent 构建」后走按钮路径），agent 经 `world_candidates`（**增量模式**：每次只生成 1 个候选并按 idea+tags 持久化去重、自动 `add_candidate` 填入步 2，连调 N 次积累 N 张卡）把候选**逐张呈现**成可点选卡、**停在步 2 等用户挑选**（不自动选/跳步；侧栏「再来几个」复用同 idea/tags 续接）；用户点「已挑选完毕」→ 页面自动发第二个任务 **`novel-build`**（置 `_agentDriving` 抑制 `show(3)` 一键补全）→ 步 3 分阶段建书 → submit → 完整大纲，右侧面板实时显示。
- **全服务单任务打断（2026-08-20）**：`libraries/dsh_bridge.py` 模块级 `_current_proc` + `interrupt_current_task()`（Windows `taskkill /F /T` 杀整树，因 node 会 spawn python mcp_server 子进程）；`run_dsh_task` 启动前打断旧任务、`finally` 收尸；`POST /api/agent/chat/cancel` 显式打断。前端 `window.agentSendTask` 在 busy 时先 cancel 再排队（done 接力）。被打断的任务以 `error`+`done` 收尾（前端 busy 复位）。

## 五、MCP 适配（mcp_server.py）

- `mcp = FastMCP("novel-engine")`（L30），注册循环：`for _entry in TOOL_REGISTRY: if surface ∈ {mcp,both}: mcp.tool()(_wrap_logged(entry["func"]))`（L110-113）。
- `_wrap_logged`（L66）：`functools.wraps` 保留 `__name__/__doc__/__wrapped__`，调用前后写 `log_tool_call(...)`（`libraries/tool_log.py` 环形缓冲 + `storage/tool_log.jsonl`，跨进程可见）。source 区分：外部 MCP 调用 `source="mcp"`（写 JSONL）；dsh 内部调用（runtime overlay 带 `--source dsh` 拉起 mcp_server）`source="dsh"`（**不写 JSONL**，工具日志页签 filter source=mcp 只展示外部调用）。
- 客户端看到的 `mcp__novel-engine__xxx` 前缀是客户端命名空间，非服务端行为。
- **LoopGuard 语义环熔断**（Phase 1 新增）：近 5 步同 `(tool, args_digest)` ≥3 次且结果摘要不变 → 熔断；连续 ≥5 次工具失败 → 熔断。`NOVEL_DISABLE_LOOP_GUARD=1` 逃生阀。见 `libraries/loop_guard.py`。
- 启动：`python mcp_server.py`（stdio）。Claude Code 侧经 `.mcp.json` 挂载（`claude mcp add --scope project novel-engine -- python mcp_server.py`）。

## 六、书锁与并发（libraries/book_lock.py）

- **两层锁**：每书一个 `threading.Lock`（防 Flask 多线程）+ `books/<id>/.lock` 文件首字节锁（Windows `msvcrt.locking` / POSIX `fcntl.flock`，跨进程）。
- `BookLock(book_id).acquire(timeout=30)` 成功后锁内写元信息 `{pid, ts, purpose}`；**锁文件不删除**（避免 TOCTOU 删除竞态）。
- 冲突抛 `BookBusyError(RuntimeError)`。读操作不加锁；写文件走 `write_json_atomic`（`core/json_store.py`）。

## 七、dsh 侧车现状（dsh 相关事实的唯一事实源）

> 决策背景：用户拍板用 dsh 核心完整替换内置 agent（见 `docs/交接文档-2026-08-22-内置agent整体.md`、`docs/架构文档-内置agent-dsh.md`）。先行的 dsh 侧车 spike 结论为「可用但有 3 摩擦点」，方向与用户拍板相反（spike 文档已删，3 摩擦点即本条 §七各要点 + §九 坑 11/12 的来源）。

- **引擎（vendor 进项目）**：`vendor/dsh-ne/`——dsh 0.1.0-rc.7 源码副本，**改名 dsh-ne**（防与全局 npm 的 dsh 冲突），顶层依赖从 61 剔到 51（去 C 级 web/client-ui/commands/tmux/schedule/dev-hmr，保留 A+B）。`libraries/dsh_bridge.get_dsh_argv()` 用 `node vendor/dsh-ne/lib/bin.js` 直启，**不依赖全局安装**；node_modules 不入 git（`npm install` 重建）。
- **profile（用户态，不入库）**：`~/.dsh/profiles/headless/`。`cordis.patch.yml` 挂 `@deepseek-ai/dsh-mcp-client` → `python mcp_server.py`，`toolCallTimeoutMs: 600000`（**务必 ≥600000**，否则 generate_full_outline 阻塞数分钟被 MCP 掐断），persona 注入四阶段编排 + 意图→MCP 直驱分发 + 护栏（模板在 `agent-sidecar/cordis.patch.yml`，两处须同步；dsh 侧 skill 已于 2026-08-24 删除）。**headless 是 one-shot**（答一个任务即退出）。
- **事件流（NovelEngine 定制，2026-08-20）**：headless 原 runner 用 `summarize` 丢弃中间事件、只打印最终文本；项目注入 `vendor/dsh-ne/events-runner.mjs`（经运行期 overlay `--patch` 禁掉 `headless-runner` 并挂本插件，模板 `agent-sidecar/events-runner.yml`），监听 `session/event` 把每个 `tool/call`/`tool/result` 写成一行 NDJSON 推 stdout。`libraries/dsh_bridge.py` 用 `Popen` 逐行读，实时转 SSE（tool_call/tool_result/navigate/ui_command/reply/done）给侧栏——**浏览器不再靠 2.5s/3s 轮询补实时感**（外部 MCP 路径仍走意图队列轮询兜底；「工具日志」页签仍 3s 轮询 tool-log 聚合，**只展示外部 agent 调用**——dsh 内部调用 source=dsh 不写 JSONL 不混入）。手动 CLI 不加该 patch 仍是纯文本最终回复，两侧互不干扰。
- **`~/.dsh/profiles/web/` 存在但从未安装**（`cordis.patch.yml` 空 `[]`、无 node_modules）→「dsh --profile web 作界面」是未验证设想。MVP 用「现有侧栏 + headless 转发 + events-runner 事件流」覆盖可视化（事件流 2026-08-20 已实现，见上一条）。
- **仓库侧模板**：`agent-sidecar/`（README + `cordis.patch.yml` 模板）。`skills/` 5 个 dsh 版 SKILL.md（novel-build-candidates/novel-build/outline/write/publish）**已于 2026-08-24 删除，仅保留 MCP 工具面**——`.dsh/skills/` 与 `agent-sidecar/skills/` 均已移除（skill 重写待后续会话）。
- **dsh 自动读根目录 `CLAUDE.md`**（`dsh-agent-instructions`）——根 CLAUDE.md 的内容即是 dsh 的指令。
- **系统工具已禁（2026-08-20 护栏收紧）**：dsh 默认会暴露自己的系统工具（文件读写 `tool-fs`、shell `tool-bash`/`tool-pwsh`、子代理 `subagent*`、联网 `tool-web` 等），cwd=D:/NovelEngine、无 sandbox，**可绕过 MCP 护栏直操项目文件**。headless profile 的 `cordis.patch.yml` 已用 `disabled: true` 批量禁掉文件/shell/子代理/工作流/任务/goal/todo/ralph 等 ~30 个，**只留** `mcp__novelengine__*`（40 个）+ 联网（`tool-web`/`web`/`web-search-deepseek`，用户要求保留；skills 已于 2026-08-24 删除）。模板与已装两处须同步。
- **cordis.patch.yml 语法坑**：dsh 的 profile 配置是 **patch 层**，只支持 id-targeted override；**新增条目必须用 `insert`（不带 id）** 追加到根列表；禁用既有插件用 `- id: X\n  disabled: true`（dsh-headless 自身以此禁 hmr）；profile 的 `cordis.yml` 是硬编码空根，不生效，别编辑它。

## 九、常见坑

1. **cordis.patch.yml 是 patch 层**：新增条目用 `insert`（不带 id），别编辑 cordis.yml（空根不生效）。
2. **book_lock**：`BookBusyError` = 另一进程在操作同书，稍后重试；锁文件不删。
3. **nav_intent TTL 30s**：意图过期即丢，驱动 UI 要在 30s 内消费；navigate 函数无条件写队列，内部 SSE 路径也可能产生重复意图（`navigateTo` 有同 path 去重）。
4. **Windows 控制台 GBK**：脚本打印中文加 `sys.stdout.reconfigure(encoding="utf-8")`。
5. **flash max_tokens 余量**：流式生成 max_tokens 必须 ≥8192（推理余量），否则 content 为空解析必败。
6. **mcp 2.0 勿升级**：FastMCP API 在 mcp 2.0 被移除，锁 `mcp>=1.2.0,<2.0`。
7. **重启杀净 58080**：`netstat -ano | findstr :58080` 全部 PID 杀净，否则旧进程「改动不生效」假象。
8. **四大库单例**：改 `libraries/data/*.json` 必须重启服务才生效。
9. **测试会动数据**：`books/`、`profiles/` 是真实数据别删；删除类操作无回收站，先确认。
10. **Python 侧零新增重依赖**：requirements.txt 仅 6 项（urllib3/requests/flask/jinja2/fonttools/mcp），硬约束不加 jsonschema/fastapi/pydantic。
11. **dsh 是 .CMD shim，中文参数会乱码**：Windows 上 npm 全局装的 `dsh` 是批处理，`subprocess.run(["dsh", 中文任务])` 经 cmd.exe 按 ANSI 编码转坏（exit 1）。修法：`shutil.which('dsh')` 得 .CMD 后反推 `node <npm路径>\node_modules\@deepseek-ai\dsh\lib\bin.js` 直启（Node 经 CreateProcessW 收 UTF-16，中文无损）。`libraries/dsh_bridge.get_dsh_argv()` 已封装。
12. **dsh patch 层 id-targeted override 是「整体替换 config」**（非深合并）：运行时 overlay 若只给 `toolCallTimeoutMs` 会把 mcp-novelengine 的 transport/serverName/command 冲掉报 ValidationError。必须给全 config（`libraries/dsh_bridge._write_runtime_overlay` 已处理，与 headless profile 保持同步）。
13. **dsh 有自己的工具面，默认不禁会绕过 MCP 护栏**：`--dump-config` 可见 dsh 自带 tool-fs/tool-bash/subagent 等系统工具，cwd=D:/NovelEngine 无沙箱可直操文件/执行命令。已在 headless profile 用 `- id: X\n  disabled: true` 批量禁掉（留 MCP + skills + 联网）。**注意禁用被依赖服务**：禁 subagents/shell/goals 后，依赖它们的插件（workflow-worker-thread / permission / command-goal）会报「pending 未激活」，需一并禁用。
