# 外部书目提取 · 顺序通读式提取（agent 协作）

> 本文定义 **agent 协作模式下外部书目提取功能**的完整方法论：agent（Claude Code / dsh 侧车）在 `/scout`·`/extract` 页对已抓取参考书执行**整本顺序通读式提取** → 自主提炼五类资产 → 入库（自主直入，或 `set_review` 呈现给用户勾选确认）。
> 回答六个核心问题：**什么是弧 / 如何区分弧 / 如何判断层级 / 如何划分桥段 / 怎么 get「内涵」/ 如何设计写作风格**，外加两个新问题：**怎么通读长书（记忆压缩续段）/ 怎么自主入库不去重过度**。
> 概念权威 = `NOVEL_AGENT.md` §1.1（全书唯一来源），故事线概念研究 = `docs/研究文档-故事线大纲桥段线程.md`；落地契约 = `novel-scout` skill 与 `NOVEL_AGENT.md` §1.2。

---

## 0. 提取的产出形态（先对齐，避免三套东西混淆）

外部提取写的是**可复用模板**，进桥段库 / 情节弧库 / 笑点库 / 角色库 / 风格规则库：

| 词 | 书中运行时（平台书内） | 可复用模板（提取产出） |
|---|---|---|
| **弧** | `OutlineSlot`：靠 `parent_arc_id` 树嵌套、`start_word/end_word` 字数轴定位，属某本平台书 | `StructureTemplate`：`stages`=子弧 `StageNode`、`children` 多层嵌套；**单弧一条模板** |
| **桥段** | `PlotSlot`：挂在某叶弧 `outline_id` 下 | `PlotTemplate`：单场景可复用事件模板 |
| **母题** | `plot.theme_hints/theme_moments`、`OutlineSlot.stages[].themes` | `StageNode.themes:[{name, position, how}]` |

**三条硬口径**（与书内规则不同，勿照搬）：
1. **顺序通读式提取（整本）**：以读者身份**从头到尾顺序读完全书**，把全书切成一连串自洽的弧模板（自由分段），弧随书长产出（1496 章的书切出几十个弧是正常的）。**提取目标 = 整本弧表 + 充足的可复用桥段/笑点/角色**，不是只挑两三个「代表弧」。
2. **`total_words` / `min_words` / `max_words` = 该弧 / 该 stage 在书里实际占用的字数跨度**，**绝不等于全书总字数**。旧 scout prompt 把 `total_words` 写成 `章数×3000`（全书）是 bug，勿抄。
3. **只表述字数、不含章数**；参考书**不改**。记忆压缩/断点信息不进模板（那是扫读运行态，落 extract_state）。

> 为什么不再是「代表性单弧采样」：采样只挑两三个代表弧，1400 章的书实测只读 9 章、出 2 弧——丢掉了全书 98% 的可复用结构。长书一次性通读又会顶爆单会话上下文（dsh 会话内无压缩）。于是改为**顺序通读 + 记忆压缩续段**（见 §9）：既覆盖全书，又把每次读入上下文的内容控制在预算内。

## 1. 什么是弧（提取语境定义）

**弧 = 有方向/目标的情节单元**（`NOVEL_AGENT.md` §1.1：弧是**树状目标节点**，一个弧承载一个方向/目标，可由多个子弧组成，层数/分支由剧情设计决定、不设固定值）。

在提取语境下要把「弧」读成**可复用目标单元**，而不是卷、不是副本名、不是章数段：

- **弧 ≠ 卷**：卷是几十上百章的出版分组；弧是「末日来临前囤物资」「进入第一个副本并通关」这一级。
- **弧 ≠ 章节块**：章节 = 纯字数切分（`words_per_chapter`），不是叙事单元，不能当弧边界。
- **弧 ≠ 桥段**：桥段 = 弧内一个可执行场景/事件（完成子目标的一步），弧可含多个桥段与多个场景。
- **弧 ≠ 线程**：线程 = 贯穿全书的横线索，由散布在不同弧里的桥段组成，**提取不建线程**。

一句话判据：**一段篇幅能否被一个「读者可感知的目标 + 一次起承转合的张力 + 一个阶段性收束」概括**。能 → 弧；只能概括为「做了一件事/一场戏」→ 桥段；跨好几个互不相干目标还串不起来 → 拆开。

## 2. 如何划弧（在一本长书里把一个弧「划」出来）

**识别弧的边界信号**（满足 ≥2 即可判边界；供顺序通读时在段末判定「这个弧收了吗」）：

1. **目标单元的开启与闭合**：出现可被读者感知的「这段要办成什么事」（接任务 / 立计划 / 出现要克服的威胁 / 要夺取的对象 / 要破解的事件）；当该目标**阶段性闭合**（达成 / 失败 / 转化为新威胁，常配打脸、夺宝到手、境界突破、危机解除、身份揭示）即为终点；随后节奏回落进入下一个目标 = 天然边界。
2. **一次完整的张力呼吸**：动机确立 → 阻碍升级 → 尝试/受挫 → 手段升级/翻底牌 → 阶段结果。读到一个「收束小高潮」+ 回落，即可判一个弧走完。
3. **章节块 / 标题信号（最省力）**：卷名、副本名、换地图、事件组标题是强边界，顺序通读遇到即重点复核。
4. **字数量级（参考，非硬框）**：多数弧约 1.5万–4万字；几千字的清晰小弧也收（标小跨度）；大于 ~5 万字多半内藏多层，先拆子弧再定稿。

**顺序通读与自由分段（v2 取代旧「采样原则」）**：
- **顺序推进**：从第 1 章读到末章，读完的不要重读（断点续读靠 `cursor`，见 §9）。同一条纵轴顺序收弧——上一弧收束处即下一弧起点，不必强行无缝隙，但**不跳大段、不回头补**。
- **随手开弧 / 及时收弧**：读到「目标出现」把弧**记入 open（未收束）**，在 digest 里跟踪；读到该目标**阶段性收束**即**定稿成模板**。别等整本读完才回头切——那等于又把长书塞回上下文。
- **弧的粒度随书走**：长短均可，不预设 1.5万–4万硬框。小弧（一个副本通关的几章、一次围城）单条模板；大弧（一次大事件跨几十章、多子目标递进）用 `children` 拆层（判据见 §3）。同书名下前后弧可以近似（升级-换图-再升级是网文常态），但**入库时注意同构模板去重**（见 §10），库不是照搬全书每一段。
- **仍要求可复用**：每段定稿前问「换本新书（换人名金手指数值），这段目标/张力还成立吗」。成立才值得做模板；纯过渡、纯换皮流水账段可以不收（如实注明在 digest 里划走，不强行凑数）。

提炼前/入库前先 `query_arc_library` / `query_plots` / `query_gags` 查库内已有模板，避免重复度高（见 §10）。

## 3. 如何判断层级（一个弧该不该拆、拆几层）

**核心判据**：一个节点往下拆成子弧 ⇔ 它承载的目标能分解为 **≥2 个「递进、且各自能独立开合一次小张力呼吸」的子目标**，且每个子目标在书里实际占**一段连续篇幅（经验线 ≥ ~5000 字，不设死值）**。

- **够格拆 children**：子目标之间有**推进关系**（前一个为后一个铺路），且每个单独读起来像一段「小起承转合」。
- **不够格、收作 `key_events`**：并列小额操作（卖房 vs 抵押贷款）、一个动作拆几步、撑不起独立张力的——写进本节点 `key_events`（= 关键事件清单，**不是**子弧名）。
- **一个都不够格 = 叶节点**：书里若给它挂桥段，模板里它就是叶 stage。

参考反例（`NOVEL_AGENT.md` 思考例）：「囤物资」→ 变卖资产→采购→住所加固 是三个递进、可独立闭合的子目标 → 拆成 3 个子弧；「变卖资产」下的 卖房/抵押 是并列小额操作 → 收作 key_events，不再拆。

**实操顺序**：
1. 写出该弧承载的目标。
2. 列出推进该目标所需的**子目标序列**。
3. 逐个按「独立张力 / 连续篇幅 ≥ ~5 千字 / 能否独立闭合」打标。
4. 够格的递归进 `children`；不够的留作本节点 `key_events`。
5. 为整弧与每个有意义的节点补 `foreshadow_opportunities`（能埋的坑，将来在哪收）与 `themes`（见 §6）。

**硬约束**：深度/分支**按书里真实结构定、不要求均匀**——同一份提取里 3 层弧、1 层弧、纯叶弧并存是合法的。别为了好看强拆到等深。

## 4. 如何划分桥段（弧内怎么切、怎么进桥段库）

弧往下切桥段，是「把完成子目标的一步步动作/冲突切成**单场景事件**」，每桥段承载推进一步。

**切分尺度与内容判据**：约 **0.3–2 章 / 800–2500 字**（模板 `word_range` 默认 [800, 2500]）。一个合格桥段应含：场景、人物行动、冲突或小转折、能直接扩写成文。

**模板化三件事**（决定它能否被别书复用）：
1. `template_structure` = 箭头流程骨架：`[当众羞辱]→[主角隐忍]→[关键时刻亮实力]→[全场震惊]→[对方后悔]`。骨架只留**戏剧动作**，不留人名数值。
2. `slots` = 变量槽 `[{name, options}]`：把桥段里会随书/角色变化的点提成槽（如 `空间类型: [封闭密室, 空旷大厅, …]`）。**能提槽的才值得入库**。
3. **剥离绑定**：主角名 / 专有金手指 / 具体数值 → 不写进桥段。绑定角色的私货归角色模板（`catchphrases`），绑定金手指的设定归弧模板，桥段只留「换个人也能演的戏剧动作」。

**从书里筛**（不是叶弧内每拍都收）：收①情绪 / 爽感 / 反转结构清晰、可迁移；②库里同类少的；③能一句话讲清动作骨架的。纯流程向、非网文爽点节奏的事件不收。整本扫读下候选会远多于旧采样——正合适，只要入库时按 §10 去重，别把同骨架换皮的重复版本灌进去。

> 例（v2 补充）：读到「九个人，宣布『只剩十人时，你们之中要杀一个』」——这是把**规则抛给读者/角色的桥段**，可提成 slots（人数 / 惩罚 / 场景），入库。

## 5. 笑点(gag)：抓到「为什么好笑」的机制

目标 = 把段子抽象成**与人物解耦的可复用机制**：

- 落 `pattern_description`（机制描述，含「结构：…」句式骨架，如 `生死关头对方猜身份 → 主角一本正经报离谱职业 → 全场错愕`）+ `fit_scenes`（适配场景）+ `examples`（书里原例 1–2 条）。代码会把 `pattern_description` 自动回填 `template`。
- 提炼法：读到段子 → 问「笑点来自哪种结构」（预期违背 / 冷面吐槽 / 误会错位 / 反差 / 内心吐槽 / 节奏破坏…）→ 写成与人物解耦的机制。
- **绑定具体角色的口头禅式笑点 → 归角色 `catchphrases`，不进 gag 库**。
- 一个 gag 至少能被答出「在什么场景、对什么预期、做哪种打破」才成立，否则不单收。

> 注：平台语义里 **「内涵」≠ 笑点机制**。gag 只承载机制（`pattern_description`）；「内涵」指**母题/theme**，见下节。

## 6. 怎么 get「内涵」（母题 / theme 挂载）

平台术语里 **内涵 = 母题/theme**：全文反复出现、可被读者反复「尝到」的主题意义，与笑点无关。既有词汇表：**公平（Justice）/ 成长的代价（Cost of Growth）/ 身份与伪装（Identity & Disguise）/ 牺牲（Sacrifice）/ 归属感（Belonging）/ 传承与突破（Legacy & Breakthrough）**，可扩。

**提取产出落点**：弧模板的**整弧与每个 stage** 写 `themes:[{name, position, how}]`——
- `name`：母题名（上面词汇或自拟）。
- `position`：母题在**这段**最浓的位置（开头 / 中段 / 结尾）。
- `how`：靠**哪类事件**让读者尝到它（如「主角为救人押上全部家当」落地 牺牲）。

**提炼问法**：读一段 → 问「这段最想让读者心里留下哪种味道/主题意义、在哪个位置最浓、靠哪类事件落地」。写不出 `how` 就不硬写。

**传导链与已知边界（如实保留，决策点暂不改代码）**：平台书内 plot 级自动化挂母题靠 `THEME_PLOT_COMPAT`（`libraries/storyline.py` 内）且**只覆盖内置 `plot_dating_*` 桥段模板**；`scout_*` 提取桥段的 template_id 不在此表，故 scout 桥段无法经该规则自动带母题。因此 **scout 弧模板的 `stage.themes` 是「新书用它时选母题 / theme_moments 传导」的主要载体**——这正是要求 stage 写 `themes` 的原因。若想让 scout 桥段也自动挂母题（把提取桥段的 category 或模板接入一张映射表），属**未来可做项**，本文档不做代码改动。

## 7. 角色原型提取（简述）

人物 → 原型，落 `personality / description / archetypes / examples（含出处角色）/ catchphrases / tags / fit_tags`。**剥掉与书名绑定的专属剧情**；可复用的是「人设类型 + 口头禅 + 适配题材」。参照样例：`冷静破局智囊 ← 《十日终焉》齐夏（职业骗子型主角 / 规则破局者 / 高智商冷静型）`。

**整本扫读下的注意**：角色刻画是**渐进**的（「一个清冷女人开口」只是起点）。读到一个人物有 2–3 处可复用的「人设类型/说话方式/反应模式」证据后，才把它收进角色模板候选；纯龙套、纯绑定本副本剧情的配角不必逐个入（可在 digest 记一句话，避免反复重描）。已有主角原型后，同一人后文的新刻画并入同一候选，不重复建模板。

## 8. 如何设计写作风格（外部作者文风 → 目标笔名规则）

**落点只能是 `prefer` / `ban` 两条机制**（平台风格规则库，归属用户所选笔名 `profile_id`；未指定归默认笔名「枫落」），且**规则语义站在平台读者 / 去 AI 味视角——不是克隆作者**。

> 红线（平台设计硬约束，`docs/设计文档-总览-claude.md`）：**刻意不做**「拆书仿写 / loom 式写作指纹」级分析，风格只能落规则层。

**提炼法**：整本扫读全程留意句式/用词习惯，读到有代表性的开局/中段高潮/对话密集章即可定稿（不必等全书读完）——
- **句式层 → `prefer`（正向指令）**：句长整体倾向（短句为主 / 长短交错 / 长句铺陈）、段落疏密、对话占比、视角与心理描写习惯、「有效且想借用」的句式结构。写成指令文本，如 `句长偏短，动作推进用三连短句`。
- **用词 / 套话层 → `ban`（禁止内容）**：作者的套话、口头禅、冗余腔调——若属「AI 味 / 水词要防」，落 `ban` 且 `replacements` 给替代表达（作者的常用替代表达正好可填进 `replacements` 触发自动去 AI 味替换）；`replacements` 空 = 硬禁句式检测。**作者低效 / 雷同 / AI 味的表达照禁**，不是照抄。
- **数量分寸**：一档建议 3–8 条 `prefer` + 5–15 条 `ban`，只收「高频、可判、有迁移价值」的，不把整本书词典灌进规则库。

## 9. 阅读循环与记忆压缩（v2 核心：长书怎么读完）

**物理约束**：dsh / 单会话上下文无法装下整本长书（《十日终焉》306 万字 ≫ 任何单会话预算），且会话内无上下文压缩。因此整本通读**分多段**：每段是一个新会话，段尾把**压缩记忆**落盘（`extract_state`），下一段只带压缩记忆从断点续读。观感上是同一读者连续读完，实现上每段上下文有界。

**一段内的阅读循环**：
1. 段首：若续段，`extract_state(action=load, folder, mode=summary)` 取 `{cursor, memory, committed}`；新扫读则 `read_crawled_novel(folder, chapter=0)` 拿一次目录（`chapter_count`）。
2. 顺序读窗：`read_crawled_novel(folder, start_chapter=A, end_chapter=B)`（窗口自定，常 ≤~25 章/次防裁剪），零星用 `chapter=N` 单章。读到即按 §2–§7 随手提炼 / 记 open。
3. 段尾（**记忆压缩**）：判断该压缩续段——经验阈值：已顺序读 **~60–150 章**、或单窗工具结果明显变大、或自感上下文重。执行：
   - 把本段新增内容**并入压缩记忆**（不是追加原文）：`digest` 只留——关键人物与当前状态、进行中目标与 open 弧、已收束弧的**一句话索引**、未决悬念/线索、前段已入库的近似提示。`digest` 目标 ≤ ~6–8k 字（新会话任务文案 / load(summary) 要装得下）。
   - `extract_state(action=save, folder, state={book, cursor=已读到第N章, memory:{digest, open_segments, people, unresolved}, committed, segments_log})`。
   - **停下**，汇报「已读到第 N 章，记忆已压缩落盘；回复『继续』我从第 N+1 章续读」。**不要**在段内硬顶到超限继续读。
4. 收尾：读到 `chapter_count` 末章，或连续几个窗口都无可提炼 → save 置 `status=done`，汇总「共 N 弧 / M 桥段 / K 笑点 / 角色 / 风格规则，已入库 X 条」，结束。

**digest 精简纪律**：digest 是**记忆不是书摘**——只留「后面还要用」的。已定稿入库的弧只需一句索引 + 入库名（去重查用），不要复制其 stage 细节；只有 open 的弧才需保留较细的目标/张力/位置。

## 10. 入库决策与去重（v2：agent 自主、防过度重复）

**何时入**：候选成熟即可入，不必等全书读完。自然节奏：每收束几段后把已定稿候选入库一批；也可段尾一起入。入库用 `ingest_library_assets`（纯规则落四库，按 `scout_{source}_{name}` 净名去重）。入库即把名称记入 `extract_state.committed`，防止本段或续段重复。

**入库前查重（防过度重复）**：逐条先比对库里已有模板——
- 用候选的 **标签 / 关键词 / 结构骨架（箭头流程）/ gag 机制** 调 `query_arc_library` / `query_plots` / `query_gags` / `query_characters` 查库；
- 命中**高度近似**（同骨架同机制、只换人名数值）→ **不重名硬灌**：要么跳过（库里已覆盖，标注 note 跳过原因即可），要么**差异化**——改名 + notes 写明与既有模板的差异点（如「同《》X 模板，本版差异在『惩罚不是杀人而是逐出』」）再入；
- 桥段/gag 的**机制级**近似比「名字近似」更重要：同一个「规则揭晓→人人自危」骨架，哪怕出处不同也判近似，只保留变体最清晰的一版（或差异化合并）。
- 一个机制/骨架在同一本书最多收 1–2 个变体；弧级模板若全书同构段很多（升级-换图-再升级），收每个**子目标实质不同**的变体，纯换皮段不做模板。

**给用户过目（可选）**：仅当用户明确要审查而非自主入库时，把候选经 `drive_ui(set_review)` 呈现成可勾选卡，停页面等用户勾选；用户确认后由页面 POST `/api/scout/ingest` 落库（不经 agent）。候选量大时**分批**呈现，别一次塞几百条（会被裁剪/卡 UI）。

**自主直入 vs 呈现**：v2 默认 agent 自主入库（用户明确要求；入库前查重 + committed 记录做护栏）。若语境是「整理给我看看再定」或用户要求过目，走 set_review 呈现。二者择一，不要既直入又 set_review 造成重复入库。

## 11. 呈现与入库纪律（护栏汇总）

1. 默认：提炼完一批成熟候选 → 入库前 `query_*` 查重 → `ingest_library_assets` 分批直入 → 名称记 `committed` → 汇报。**参考书仅供借鉴 / 入库复用，不改书**。
2. 用户要过目：`drive_ui(set_review)` 呈现可勾选卡（`title` 必填、五类至少一类非空；`style_rules` 每项 `{kind(prefer|ban), pattern, desc?, severity?, replacements?}`），**停下等用户勾选**，确认后由页面 POST `/api/scout/ingest` 落库（不经 agent）。
3. 兜底：用户要求「直接入库」且无需自主决策时，才调 `ingest_library_assets`（四库，不含风格；风格另用 `add_style_rule` 逐条）。
4. 长书必须分段：**别指望一次会话读完**。段尾 `extract_state(save)` 压缩落盘 → 汇报续读指令；断/超时从 `extract_state(load)` 的 cursor 续。置 `status=done` 前不要反复重读已扫过的章节。

## 附：工具契约要点与已知决策点

**读章工具（read_crawled_novel，v2 形态）**：
- `chapter=0`（默认）→ 元数据 + 章节目录（一次，拿 `chapter_count`）；
- `chapter>0` → **只回该章正文**（不再回带整份章节目录——单章走 O(1) 懒加载）；
- `start_chapter>0`（+`end_chapter`/`max_chapters`）→ 成批顺序读窗口正文（无目录回声），供分窗通读。
- 断点记忆：`extract_state`（load/save/clear，见 skill）。

**已知决策点（本次未实现，供后续）**：
- `THEME_PLOT_COMPAT` 只覆盖内置 `plot_dating_*`，scout 桥段不经规则自动带母题（靠 stage.themes 传导）——见 §6。
- `query_arc_library` 工具 docstring 仍残留旧 `total_chapters` 字样（模板跨度实为 `total_words`）——勿被误导。

- dsh 会话内无上下文压缩（vendor 的 compaction 未挂载），故记忆压缩 = 落盘 digest + 新会话续读；若未来挂载会话内压缩，「段尾续段」可改为单会话长跑，方法论 §9 相应简化。
