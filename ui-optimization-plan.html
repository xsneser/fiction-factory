🎨 NovelEngine UI 视觉检测与优化方案

基于真实浏览器逐页渲染的视觉走查报告 · 含根因分析与可执行优化清单
检测方式：浏览器实拍截图 + DOM/OCR 走查 检测环境：Flask :58080 · 视口 960×980 覆盖页面：16 个主页面 检测日期：2026-09-03

一、检测结论摘要

一句话结论：NovelEngine 的整体 UI 功能完整、信息密度高，但在常见桌面窗口宽度下，主内容区被左导航（180px）+ 右 Agent 面板（360px）挤压到约 420px，导致大量表格、表单、卡片内容竖排变形、文字截断，多个页面接近不可用。核心矛盾是「固定三栏布局 × 无响应式兜底」。

检测共覆盖 16 个主页面，所有页面在 960px 视口下均出现不同程度的内容挤压。其中设置页（3/10）、书库（4/10）、写作台（4/10）、上架管理（4/10）、外部书库（4/10）问题最严重。根因集中在 base.css 的固定宽度布局：nav{width:180px} + aside#status-bar{width:360px} 为硬编码，全站仅 1 个 @media 断点（且仅作用于 .world-edit .toolbar 单一组件），没有针对内容区收缩的响应式规则。

二、页面健康度评分（视觉走查人工评分，1–10 分）

评分依据：内容可读性 / 布局完整性 / 表单可用性 / 信息层级，10 分为理想状态。分数越低表示挤压越严重。

三、核心问题清单（按优先级）

🔴 P0 — 阻断可用性（影响全部页面，须最先处理）

问题现象（检测证据）根因优化方向
P0-1 主内容区被固定三栏挤压 960px 视口下 main 仅剩 ~420px（含 padding），内容区 ~360px；书库书名竖排 5 行、设置表单逐字竖排、统计卡"情节段模板"截断为"情节段模"。 nav 180px + aside 360px 硬编码，main{padding:30px} 再吃 60px，无自适应收缩。 侧栏改可收缩 + 内容区最小宽度保护 + 断点降级。
P0-2 Agent 面板默认抢占 38% 宽度 360px/960px ≈ 38%；该面板在纯管理页（如设置/书库）也常驻，进一步挤压主内容。 aside#status-bar{width:360px} 默认展开且不按页面类型区分。 窄窗口下默认折叠；管理类页面可完全隐藏；折叠状态持久化。
P0-3 全站缺少响应式断点 全站仅 1 个 @media (max-width:900px) 且只作用于单一组件；任何窗口宽度下三栏结构不变。 base.css 等样式表基本无媒体查询；表格/表单/卡片无窄容器降级规则。 建立 1440 / 1100 / 800 / 560 四级断点体系，窄屏逐级降级。

🟠 P1 — 高影响（表单与数据密集页）

问题现象根因优化方向
P1-1 表格无法容纳 7 列 书库表（书名/笔名/题材/故事线/进度/状态/操作）在窄容器内书名竖排、列宽失衡。 table{width:100%} 无 min-width 保护，列无自适应策略。 表格设 min-width + 横向滚动；或改卡片式列表；长文本列省略号。
P1-2 表单逐字竖排 设置页 LLM 配置、新书向导、笔名档案的表单字段在窄容器内文字逐字换行，几乎不可填写。 .form-row{grid-template-columns:1fr 1fr} 在窄容器下仍强行两列。 表单加最小宽度 / 窄容器改单列；label 与控件同行布局。
P1-3 主按钮色与状态色语义冲突 主操作按钮用 #238636（绿=成功色），与"成功/已完成"状态同色；导航 logo 与链接又用蓝色。 全局 button{background:#238636}，设计令牌未区分「品牌强调色」与「语义色」。 引入品牌主色（建议保留蓝 #58a6ff）做主按钮，绿仅用于成功状态。

🟡 P2 — 中影响（体验与层级）

问题现象根因优化方向
P2-1 统计/数字卡层级弱 仪表盘 4 张统计卡被压窄，数字 32px 与标签 11px 落差大、间距过近；卡片文字截断。 .cards{minmax(260px,1fr)} 在窄区退化为单列但无最小宽度保护。 统计卡改横向指标条或 2×2 网格；数字/标签留白加大。
P2-2 筛选标签密集换行 情节段库 14 个分类、角色库 30+ 标签在窄区挤压成密集换行，不可扫读。 标签区无横向滚动 / 无收起机制。 筛选区支持横向滚动（overflow-x:auto）或折叠"更多"。
P2-3 页面标题与区块层级不清 h1 24px 与区块标题、卡片标题视觉差不足；部分页无面包屑层级。 全局 h1/h2/h3 样式简单，缺少辅助线/次级信息。 统一页头组件：标题 + 说明 + 主操作按钮同排。

🟢 P3 — 低影响（视觉精修）

问题现象根因优化方向
P3-1 空状态与加载态缺失 空库、无书、无数据时仅简单文本，无引导 CTA。 .empty 仅有图标+文字。 空状态加「去创建」引导按钮。
P3-2 交互反馈平淡 按钮 hover 仅变色；无焦点态；Toast 已有但位置固定右上。 样式表对 :focus-visible、动效覆盖不足。 补焦点环、按钮按压态、卡片悬浮阴影。
P3-3 写作台左右分栏不可读 写作台 .editor-left{width:50%;min-width:320px} 在窄 main 里两栏挤压，正文几乎不可读。 min-width:320px 与容器冲突导致溢出/挤压。 写作台改为可折叠左栏或全屏切换模式。

四、分阶段实施路线

1

阶段一 · 布局框架重构（1–2 天，解决 P0）

  • 侧栏宽度改为可变量，main 设 min-width:0 与内容最小宽度保护（min(960px, 100%)）。
  • Agent 面板折叠态由 JS 持久化到 localStorage，窄窗口（<1200px）默认折叠。
  • 新增断点：@media (max-width:1200px) 折叠面板；@media (max-width:1000px) 导航收窄为图标列；@media (max-width:720px) 侧栏变抽屉。
  • 所有 table/form 容器加 min-width + 外层横向滚动，杜绝内容竖排。
2

阶段二 · 数据密集页专项（2–3 天，解决 P1）

  • 书库/上架/设置：表格改「自适应列 + 省略号 + 横向滚动」，或提供列表/卡片视图切换。
  • 表单统一为「窄容器单列、宽容器两列」的 .form-row 栅格升级。
  • 建立品牌色令牌 --brand（蓝），主按钮改品牌色；语义色（成功/警告/危险）严格分离。
  • 写作台 .editor-split 增加折叠左栏按钮，正文区可切换全宽。
3

阶段三 · 体验与视觉精修（1–2 天，解决 P2/P3）

  • 统一页头组件（标题+说明+操作按钮）；统计卡改指标条布局。
  • 筛选标签横向滚动；空状态加 CTA；补 :focus-visible 焦点环与按压态。
  • 全站字体层级、卡片间距、圆角统一量化（间距 4/8/12/16/24 体系已具备，可复用）。

五、关键 CSS 优化示例

以下为可直接落地的方向性示例（需按各模板实际类名微调）。

5.1 内容区最小宽度保护（P0-1）

/* base.css */
.main-wrapper { flex:1; min-width:0; }
main { flex:1; min-width:0; padding:24px clamp(16px, 3vw, 32px); }
/* 数据容器不塌缩：窄时外层横向滚动而非内容竖排 */
.table-scroll, .form-scroll { overflow-x:auto; }
.table-scroll table, .form-scroll form { min-width:640px; }

5.2 侧栏自适应与面板折叠（P0-1 / P0-2）

/* 窄窗口默认折叠 Agent 面板 */
@media (max-width:1200px){ aside#status-bar{ width:0; padding:0; border-left:none; } }
/* 更窄时导航收窄为图标列 */
@media (max-width:1000px){
  nav{ width:56px; }
  nav a{ padding:12px 0; text-align:center; font-size:0; }
  nav a::first-letter{ font-size:16px; } /* 保留 emoji 图标 */
  nav .section, nav .logo{ font-size:0; }
}
/* JS：折叠状态持久化 */
localStorage.setItem('statusBarCollapsed', '1');

5.3 表格列自适应（P1-1）

.table-scroll table{ width:100%; min-width:760px; }
th,td{ white-space:nowrap; overflow:hidden; text-overflow:ellipsis; }
td.book-title{ max-width:220px; }  /* 长书名省略号，不再竖排 */

5.4 表单窄容器单列（P1-2）

.form-row{ display:grid; grid-template-columns:repeat(auto-fit,minmax(240px,1fr)); gap:14px; }
@media (max-width:760px){ .form-row{ grid-template-columns:1fr; } }

5.5 品牌色与语义色分离（P1-3）

:root{
  --brand:#1f6feb; /* 主按钮 / 链接 / 激活态 */
  --success:#238636; --success-fg:#3fb950; /* 仅成功状态 */
  --danger:#da3633; --warn:#d29922;
}
button, .btn-primary{ background:var(--brand); }
.pill.ok, .badge-done{ background:var(--success); }

七、检测方法与可信度说明

  • 方法：启动 Flask 服务（:58080）后，用浏览器逐页导航，截图 + DOM 文本 + OCR 三重走查；结合 base.css / workspace.css / story_line.css / reader.css 源码定位根因。
  • 评分性质：页面健康度评分为基于视觉走查的人工评估（示意口径），用于横向对比优先级，非精确度量。
  • 覆盖范围：16 个主管理页面；书籍详情/写作台等依赖真实数据，检测基于现有示例书 book_001。
  • 已知限制：截图视口固定为 960×980（浏览器窗口默认尺寸），未覆盖 1440+ 宽屏表现；Agent 面板交互态、弹出抽屉等未逐一展开检测。
