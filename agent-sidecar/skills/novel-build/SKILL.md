# 建书 步3：内容构建（novel-build）

护栏：本阶段只能填表——`save_build_draft` 落草稿，**提交只能由用户在页面点击**（agent 无
直建/翻 ready 工具）。不要给用户派活、不要自己改流程。

**分阶段落盘**：每完成一个阶段就落一次，让用户在表单里看得见、改得着，不要憋到最后一次性提交。
系统会回报**待填清单**（还差什么）与**失效阶段**（哪些下游要重做）——先看它们再动手。

## 构思流程（与「续写大纲」共用同一内核）

<!-- plan-core:begin -->
这一节是**两个入口共用**的构思流程：建书内容构建、续写大纲，都按它来想。
它只说"怎么想"，不说"调用什么"——每步用什么能力，由本文件后面的入口小节给出。

### 七步

**1. 读权威状态**
先读回本轮的权威输入：已有的设定、已有的规划、系统给出的**待填清单**、以及**失效阶段**。
只依据读回来的东西推进；记录里没有的就是没有，不要凭前文猜、也不要复述历史对话。
**先看失效**：若有阶段被标为失效，从最靠前的那个失效阶段起重做——它的下游都是拿旧结论推的，
不能假装仍然有效。

**2. 立规划命题**
先想清楚"本轮到底要解决什么"，再动笔写任何内容。
- 建书入口：这本书的**核心矛盾**是什么？它和同类比，差异点在哪？
- 续写入口：故事**现在卡在哪里**？下一段最值得推进的矛盾是什么？读者此刻最需要、或最该被延迟的答案是什么？

命题没立稳就不要往下走。后面的骨架与规划，都是它的推论。

**3. 查库对镜**
把素材库当**镜子**，不是模板：挑同类结构对照，明确写出「可迁移的机制」与「本书要避开的点」。
查几次由入口策略决定（有的入口必查，有的默认不查）。对镜的结论要落进内容里
（例如每一条弧的设计意图），不能停在"我读过了"。

**4. 近期规划（可执行）**
只承诺**马上能写**的那一小段，按剧情目标组织，不按章节均分。
这一段里的**伏笔**要在这一步就埋好：哪一段埋、埋的是什么、打算在哪一段收。
写"埋什么、在哪收"，不要写正文。

**5. 远期规划（预测）**
把还没到展开时机的方向写成**远期意图**：主线升级、角色成长、尚未兑现的线索。
远期的**伏笔**同样登记：拟埋在哪、拟收在哪。
远期只是预测——不得伪装成正式情节，也不得挤进近期承诺。

**6. 伏笔对账**
逐条过一遍：近期埋的、远期拟埋的，未来能不能找到收口？
找不到收口的，要么补上收口、要么不必埋；已经被新规划放弃的，标成取消，不要留着当谜。
只有**真正写进正文之后**，伏笔才算欠下读者的债；此前它只是计划。

**7. 自查回打**
拿校验结果对着改，改到通过为止，至少一轮。
软提示（结构重复感、字数均匀感）要**重排内容**去消解，不是忽略、也不是改小数值糊过去。
这一步只改内容，不改校验口径。

### 通用纪律

- 设定、人物、故事线是一个整体；改一处先回头检查其余两处是否还自洽。
- 先想清楚再落，不要边想边写，也不要反复推翻重来。
- **分阶段落盘**：每完成一个阶段就落一次，让用户看得见、改得着；不要憋到最后一次性提交。
- 用户改过的地方优先于你的版本；写入被保护挡住时如实说明，不要绕开。
- 一个情节段只承载一个主要戏剧变化；出现时间跳跃、地点转换、冲突对象变化、
  旧问题解决后又起新问题、两个独立高潮，就拆开。
- 只保存结构化的决策结果，不输出、不持久化私有思维链。

## 阶段与两个停点

一次 run 内按内核顺序推进；**两个关键点必须停下**（主动结束本轮，向用户汇报本阶段产出 +
待填清单，等用户改完表单点「➡ 继续下一阶段」）：

- **停点 A**：骨架（世界观 + 势力 + 人物）落盘后停下。让用户先确认"这本书的世界与人是这个
  方向"，再往下排弧——否则弧白排。
- **停点 B**：自查通过后停下。用户 review 全份蓝图，自己点「创建并进入写作台」。

其余阶段连跑，**不要每段都停**。

**从断点续跑**：新一轮进来先 `get_build_context`，看 `plan_meta.phase` 与 `plan_meta.stale_phases`：

- 有失效阶段 → 从**最靠前**的那个失效阶段起重做（它的下游都是拿旧结论推出来的）；
- 否则从当前 `phase` 继续——不要从第一步重来，也不要重复已经落过盘的内容。

## 创作原则（硬约束由 `validate_build` 强制，不必背）

- **只承诺开篇**：正式弧 + 情节段覆盖开篇约 1.5万~3万字；远期方向写进 `planning.future_intents`，
  不要一次排完整本书。
- **弧按剧情，不按章**：弧是树状目标节点，字数跨度由内容决定；**不要**把顶层弧按章均分成等长
  叶弧、也不要让情节段字数全相同。同一父弧下的子弧不必等长；需要分层时用 `parent_arc_id`。
- **一个情节段 = 一个主要戏剧变化**（`primary_turn` 必填，缺了会被拒收）：一章通常 **4~6 段**，
  字数 过渡 250~450 / 推进 450~700 / 冲突 600~850 / 关键 800~1050 / 高潮 850~1100，
  **硬上限 1200**。出现时间跳跃 / 地点转换 / 冲突对象变化 / 旧问题解决后又起一个可独立成立的
  新问题 / 两个独立高潮，默认就要拆段。
- **情节段只挂最底层弧**；每段带 `chapter_break_after` ∈ `preferred|allowed|avoid`。
- **每条弧给结构化设计意图** `design_intent{goal, conflict_function, deviation}`：本弧目标、
  在全局冲突里承担什么、以及偏离库模板的地方。`notes` 可写自由备注，**不做格式要求**。
- **伏笔在规划期就登记**：设局段写 `foreshadow{kind:"setup", ...}`；收局段用
  `foreshadow{kind:"payoff", promise_id:...}` 或 `resolves_promise_ids` 精确指回。
  同一段可以埋多条，**兑现时要说清兑现的是哪一条**。远期伏笔写进 `future_intents` 的 `foreshadow`。
- **人物语音给「生成规律」不给台词**：具名人物给 `speech_profile`
  `{rhythm,logic,emotion,social_register,habits[],forbidden[]}`（至少两项有实质内容）+ `behavior`。
  `habits` 只写句式/思维倾向，不写「先说某句」的字面台词；`signature_phrases` 可选（多数角色不需要）。
- **人物服务于势力与剧情**：每个势力至少 1 人；人物行为要一贯（不同刺激下反应一致）。
- **借骨不借皮**：弧库/段库模板是单弧参考，书内弧树由你按剧情结构自主设计。

## 失败处置

- `validate_build` 一直不过 → 按 `issues` 逐条改内容；不要靠改参数或换写法绕过校验。
- `save_build_draft` 报 `revision_conflict` → 服务端草稿已被改动（可能用户在表单里改了）：
  重新 `get_build_context` 拿最新版与失效阶段，再落盘，不要强推。
- 落盘返回里带 `protected_field_conflicts` → 那些字段沿用了用户的版本。如实说明，不要绕开去改。
- 拿不到会话 id / `get_build_context` 报 `no_build_session` → 停下让用户在向导里重走一遍，
  不要凭猜测照写。
