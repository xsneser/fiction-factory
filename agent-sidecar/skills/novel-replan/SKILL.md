# 增量续规划（novel-replan）

护栏：**不直接调用 `save_outlines`**。规划只暂存预览，**提交只能由用户在写作台抽屉确认**，
确认后才由服务端原子提交。规划轮内不写正文。

## 构思流程（与「建书内容构建」共用同一内核）

<!-- plan-core:begin -->
这一节是**两个入口共用**的构思流程：建书内容构建、续写大纲，都按它来想。
它只说"怎么想"，不说"调用什么"——每步用什么能力，由本文件后面的入口小节给出。

### 七步

**1. 读权威状态**
先读回本轮的权威输入：已有的设定、已有的规划、系统给出的**待填清单**、以及**失效阶段**。
只依据读回来的东西推进；记录里没有的就是没有，不要凭前文猜、也不要复述历史对话。
**先看失效**：若有阶段被标为失效，从最靠前的那个失效阶段起重做——它的下游都是拿旧结论推的，
不能假装仍然有效。

**2. 立规划命题**
先想清楚"本轮到底要解决什么"，再动笔写任何内容。
- 建书入口：这本书的**核心矛盾**是什么？它和同类比，差异点在哪？
- 续写入口：故事**现在卡在哪里**？下一段最值得推进的矛盾是什么？读者此刻最需要、或最该被延迟的答案是什么？

命题没立稳就不要往下走。后面的骨架与规划，都是它的推论。

**3. 查库对镜**
把素材库当**镜子**，不是模板：挑同类结构对照，明确写出「可迁移的机制」与「本书要避开的点」。
查几次由入口策略决定（有的入口必查，有的默认不查）。对镜的结论要落进内容里
（例如每一条弧的设计意图），不能停在"我读过了"。

**4. 近期规划（可执行）**
只承诺**马上能写**的那一小段，按剧情目标组织，不按章节均分。
这一段里的**伏笔**要在这一步就埋好：哪一段埋、埋的是什么、打算在哪一段收。
写"埋什么、在哪收"，不要写正文。

**5. 远期规划（预测）**
把还没到展开时机的方向写成**远期意图**：主线升级、角色成长、尚未兑现的线索。
远期的**伏笔**同样登记：拟埋在哪、拟收在哪。
远期只是预测——不得伪装成正式情节，也不得挤进近期承诺。

**6. 伏笔对账**
逐条过一遍：近期埋的、远期拟埋的，未来能不能找到收口？
找不到收口的，要么补上收口、要么不必埋；已经被新规划放弃的，标成取消，不要留着当谜。
只有**真正写进正文之后**，伏笔才算欠下读者的债；此前它只是计划。

**7. 自查回打**
拿校验结果对着改，改到通过为止，至少一轮。
软提示（结构重复感、字数均匀感）要**重排内容**去消解，不是忽略、也不是改小数值糊过去。
这一步只改内容，不改校验口径。

### 通用纪律

- 设定、人物、故事线是一个整体；改一处先回头检查其余两处是否还自洽。
- 先想清楚再落，不要边想边写，也不要反复推翻重来。
- **分阶段落盘**：每完成一个阶段就落一次，让用户看得见、改得着；不要憋到最后一次性提交。
- 用户改过的地方优先于你的版本；写入被保护挡住时如实说明，不要绕开。
- 一个情节段只承载一个主要戏剧变化；出现时间跳跃、地点转换、冲突对象变化、
  旧问题解决后又起新问题、两个独立高潮，就拆开。
- 只保存结构化的决策结果，不输出、不持久化私有思维链。

上面这段是**流程本身**，两个入口共用；下面只写续写入口的落点与能力。

## 入口落点（replan）

| 内核步骤 | 本入口的落点 | 用哪个能力 |
|---|---|---|
| 读权威状态 | 已写事实 / 已承诺边界 / 读者问题 / 线程与承诺 / 待填清单 | `get_story_state` |
| 立规划命题 | 诊断四键：`current_pressure`（当前压力）、`main_tension`（主要矛盾）、`reader_question`（读者问题）、`urgent_problem`（最紧迫的问题） | 随预览暂存 |
| 查库对镜 | **默认不查**；确需参考时最多一次主查询、覆盖不足补一次 | `query_arc_library`、`query_plots` |
| 近期规划 | 下一批可执行情节段，直到累计承诺字数约 9000（≈3 章；段数上限 20 只是安全网） | 随预览暂存 |
| 远期规划 | `planning_patch.horizon.h1`（近期方向）+ `planning_patch.future_intents`（远期意图） | 随预览暂存 |
| 伏笔对账 | 近期埋的 + 远期拟埋的；已被新规划放弃的标取消 | 随预览暂存 |
| 自查回打 | `validate_storyline` 与 `validate_world` 的 `decision_points` 对着改 | `validate_storyline`、`validate_world` |
| 提交 | 暂存预览即停，等用户抽屉确认（服务端原子提交） | `drive_ui` |

## 入口策略（与 build 的差异）

- **无 `scaffold` 阶段**：世界观与人物在建造期已定，本入口**不重新设计世界观**。
- **无中途停点**：本入口只有末尾的**预览确认**。一次 run 走完内核七步，
  最后 `drive_ui(cmd="set_replan_preview", args=...)` 暂存预览即停。
- **查库默认关闭**（见上表）。
- **不重复规划**：`get_story_state` 的 `boundary.needs_replan=false` 时**直接停**，不重复规划。

## 创作原则

- **只把 `facts` 当不可改事实**；`forecast` 可修改或废弃，**禁止回写已完成情节段和章节**。
- **一个情节段 = 一个主要戏剧变化**：`primary_turn` 必填、`words` 过渡 250~450 / 推进 450~700 /
  冲突 600~850 / 关键 800~1050 / 高潮 850~1100、**硬上限 1200**，一章通常 4~6 段；出现时间跳跃 /
  地点转换 / 冲突对象变化 / 新独立问题 / 双高潮就拆。每段明确目标、阻力、选择、代价、结果，
  并至少造成一种不可逆变化；顺手标 `chapter_break_after`。
- **新弧从现有承诺边界连续追加**；情节段只挂叶弧。
- **伏笔**：新设局段写 `foreshadow{kind:"setup", ...}`；收局段用
  `foreshadow{kind:"payoff", promise_id:...}` 或 `resolves_promise_ids` **精确指回要兑现的那一条**。
  远期伏笔写进 `future_intents` 的 `foreshadow`。规划期登记的伏笔是**计划**，
  **不算欠读者的债**——只有真正写进正文才算。
- **远期内容只写入 `future_intents`**，不得伪装成正式情节段。
- **预览参数**：书、`expected_revision`（必须等于当前故事线版本，服务端会校验）、诊断、
  2–3 个方向、选中方向、6–12 个情节段、可选弧与完整 planning patch。
- **用户改选方向或要求重拟时**，只为该方向重新生成完整预览；状态变化时重新读取 `get_story_state`，
  不得移除 `expected_revision` 或强行覆盖。
- 只保存结构化决策结果，不输出也不持久化私有思维链。
